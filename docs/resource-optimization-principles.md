# 资源与首屏优化原则

创建及更新日期：2026-10-16。本文为项目长期开发规范，通过根目录 [AGENTS.md](../AGENTS.md) 纳入后续迭代要求。新增或修改场景功能、几何、材质、灯光/后期、素材、Babylon 导入与注册、着色器、加载流程、依赖、构建和发布配置时，实施前阅读本文及相关技术方案。

依据本项目已完成的 [资源大小优化](technical-plans/2026-10-14-study-resource-size-optimization.md) 和 [Tree-Shaking 专项](technical-plans/2026-10-15-study-tree-shaking.md)，验收代码基线为 `42ed45b`。下面的实测值是该提交的历史基线，预算是持续执行的约束；后续结果应建立新记录，不覆盖旧实验。

## 1. 先确定指标和瓶颈，再选择手段

- 分别统计运行素材、生产构建、完整发布目录、实际首屏请求、HTTP 传输、运行内存和显存。文件按原始字节求和，1 MiB = 1,048,576 字节；磁盘分配空间另列。
- 首屏 JS 必须包含页面进入可用状态前实际请求的全部 JS，包括必要的异步加载器和着色器。主文件变小、代码分包和延迟请求，都不能单独证明首屏变小。
- 完整发布目录须计入所有动态调试/编辑器分包、来源和许可说明、分析报告、清单自身，以及实际交付的解码器和预压缩副本。排除其他示例的收益不得重复计入以当前场景资源为基线的缩减比例。
- 先拆解 GLB 的几何、图片、元数据和外部依赖，再决定优化对象。本次两个大模型约 98.8% 的体积来自内嵌图片，重写几何的收益很小；JS 则依据实际模块图和请求记录裁剪。
- 优化前记录提交、依赖版本、命令、文件清单和 SHA256，前后使用可比较的条件。文件变小不等于加载更快、FPS 更高或 Git 历史更小；声称耗时收益时必须另测网络、缓存、解码、GPU 上传等相关成本。

## 2. 把画质和现有功能作为约束

- 体积优化默认保持当前画面与功能。减少细节、改变灯光/后期、删除 Inspector 或提供低画质版本，应在对应需求方案中明确范围和验收差异，不能算作无损的工程优化。
- 按屏幕覆盖和第一人称可接近距离选择贴图尺寸，分别评估颜色、法线和材质数据。本次全 1K 近景木纹偏软，最终保留 2K 颜色；不要求所有图片统一尺寸或统一编码质量。
- 保留颜色的 sRGB、数据贴图的线性解释、法线方向和通道语义。旧模型的金属度/粗糙度图不能未经确认就当作项目其他材质的 ARM 图处理；法线缩放需要处理向量归一化。
- 声明“仅优化图片”时，应保护全部非图片数据、UV、节点变换、材质引用和采样设置；若确需改几何或层级，按新的行为改动建立方案及布局/碰撞验收。
- 检查全景、局部近景和第一人称距离下的木纹、接缝、高光、法线、物品贴合、家具落地、投影与碰撞。几何测试和图片误差指标不能替代实际画面检查。

## 3. 素材处理必须可复现、可回滚、可追溯

- 每次有损转换从固定提交、已校验摘要的原件开始，避免对上一轮压缩结果再次有损编码。记录工具版本、缩放/编码参数、图片尺寸、原始与交付摘要及结构校验结果。
- 候选、原件备份和处理临时文件放在发布白名单之外；源文件可由 Git 历史恢复，不在运行目录长期保留重复的大文件。相同输入和工具应能重现交付结果，工具变化导致的差异要记录。
- 新增素材同步维护来源、作者、许可、处理记录和最终交付路径。许可不明确时如实标注，已有柜体、书架和装饰画的 `unverified` 状态不能继承其他素材的 CC0 声明。
- KTX2、WebP、Draco、Meshopt 等新格式先做受控试验，核对画质、支持范围、颜色/通道解释、解码与上传成本，并将必要解码器及其他依赖纳入发布。不要假定更换格式一定更小或更快。

## 4. 让新功能只引入它实际需要的代码

- 书房运行路径沿用 Babylon pure 导入或经验证的精确路径，类型用 `import type`，建模使用实际需要的独立 builder。其他示例留在独立入口，不因保留示例而进入书房依赖图。
- 2026-10-23起项目TypeScript输出使用ES2020，与现有未转译Babylon 9.30.0的可选链/空值合并语法一致，减少重复降级包装。修改编译目标仍须复验生产运行、异步加载和Inspector；不将语法压缩解释成FPS收益。取舍与字节见[景观第一阶段](technical-plans/2026-10-23-island-background-landscape.md#8-渐进实施计划2026-10-23)。
- 新功能所需的运行注册集中维护在 [RoomRuntime.ts](../src/examples/RoomRuntime.ts)，启动着色器维护在 [RoomShaders.ts](../src/examples/RoomShaders.ts)。检查纹理、HDR、材质克隆/解析、阴影、SSAO/后期、射线、碰撞和相机输入，避免类型检查通过但运行能力缺失。
- 不覆盖第三方包的副作用声明，也不把整个 Babylon 包设置为 `sideEffects: false`。必要注册应显式保留，不能通过关闭渲染效果取得裁剪收益。
- Inspector 保持按需入口；首次打开及后续编辑器请求单独统计，全部产物仍进入完整发布目录。已经存在的懒加载不能重复算作新收益。
- 精简加载器须有资产证据：当前四个 GLB 不使用扩展，因此只注册 glTF 2.0 核心。未来增加扩展、外部 URI、动画或解码需求时，同步核对加载器、发布清单及测试，不能照搬当前支持边界。
- 既检查字节，也检查请求数量和重复模块。本次纯模块候选曾出现 49 个首屏请求，显式启动着色器后收口为 23 个；不能默认分包越多越好。GLSL/WGSL 共享 include 的策略调整也须复验。
- 初始模块例外只允许有实际依赖依据的具体工具；当前 glTF 的 `FlowGraphInteger` 值类型和 SSAO/深度使用的点云类型判定函数，不能成为放行整套流程图或点云渲染器的理由。

## 5. 以预算和回归检查防止倒退

| 指标 | 当前预算 | `42ed45b` 实测 | 执行位置 |
| --- | ---: | ---: | --- |
| 古董柜与书架两个目标 GLB 合计 | ≤ 4.25 MiB | 4.13 MiB | 资源配置、模型测试及生产发布校验 |
| 当前场景全部运行素材 | ≤ 16 MiB | 15.14 MiB | 发布白名单、生产构建及发布校验 |
| 静态初始 JS | ≤ 3 MiB | 2.32 MiB | 初始 chunkGraph 分析及发布校验 |
| 实际首屏 JS，含必需异步 JS | ≤ 3 MiB | 2.47 MiB | 独立托管后的浏览器请求测量 |
| 完整发布目录 | ≤ 41 MiB | 40.08 MiB | 生产构建及发布校验，包含清单自身 |

- 阈值与实现见 [资源配置](../tools/study-release.config.cjs)、[初始依赖分析](../tools/study-bundle-analysis.cjs)、[生产打包](../tools/StudyReleasePlugin.cjs) 和 [发布校验](../tools/verify-study-release.cjs)。它们是现有构建检查；浏览器请求、画质和交互仍需按改动影响单独验收，并非已由这些脚本自动覆盖。
- 18 个素材和 462 个发布文件是本次实测数量，不是禁止新增资源的固定目标。新增资源应同步维护白名单、来源、相关测试和预算记录；新增无关大系统不能绕开初始依赖检查。
- 确需调整预算、依赖例外或功能范围时，先在对应技术方案中记录原因、替代方案、前后字节与画面/功能证据，并同步本文、代码阈值/白名单和测试。不得只提高阈值、跳过失败检查或悄悄放行大模块。
- 同时报告各项收益与代价。本次 tree-shaking 的实际首屏 JS 减少 69.87%，完整目录却增加 0.67 MiB；这是两个不同指标，不能写成完整发布体积也下降。

### 海岛植被几何预算（2026-10-23）

按[大面积覆盖方案](technical-plans/2026-10-23-island-forest-coverage.md)，原海岸及全部景观（排除单独预算的灯塔内构件/细节/设备）上限由166,000调整为250,000顶点，全部景观由15,000调整为55,000三角形。旧上限分别仅余171顶点和4,584三角形，无法覆盖本轮约3/4岛屿的新需求；原几何仍单独受166,000约束。新林地最多5,400株、110个空间块，阈值见`CoastalForest.FOREST_BUDGET`与相关回归测试。

实际海岸/景观228,476顶点、景观48,968三角形，**包含所有LOD备份**；不得仅用引擎当前活动几何计数替代全部存储几何。新增4,731株采用13顶点/8三角形，相比现有远树60顶点/46三角形降低单株几何；额外94个块、透明覆盖和LOD备份仍有成本。原四项字节预算、初始依赖规则、完整交付要求不变。覆盖由实际冠顶alpha并集与生产截图验证，FPS/加载耗时采样保持暂停，不能将此结构优化写成已测帧率收益。

## 6. 发布必须能独立运行

- 使用显式运行白名单，不复制整个 `public`，也不靠删除其他示例减小发布目录。保持资源相对路径，并覆盖动态拼接 URL、GLB 依赖、必要本地解码文件及全部构建分包。
- 正式交付使用 `npm run build:production`，保留完整 `dist` 目录结构；默认 `npm run build` 是开发构建。生产命令已自动执行发布校验，已生成目录可单独用 `npm run verify:release` 复核。
- 只托管最终目录验收，不能借开发服务器从 `public` 补齐缺失文件。检查页面、素材、未触发的动态分包、调试入口和来源说明的可访问性与摘要；不要用测量服务器特例掩盖页面遗漏，本次曾因此暴露 favicon 404。
- 网络压缩和缓存是独立部署能力：离线 Brotli/gzip 试压不能写成线上已启用；验证响应头和实际传输后再报告。缓存命中、冷启动与完整交付分别记录。

## 7. 按改动影响完成验收和交付

1. **实施前**：阅读本文与相关方案，确定目标指标、基线、范围和预算；较大改动先建立或更新技术方案。
2. **实施中**：维护资源/依赖记录，用必要测试保护真实失败路径，例如缺失资源、同长度篡改、外部依赖、超预算和缺失注册；不为低风险文档调整增加实现镜像测试。
3. **工程检查**：运行代码、资源或构建改动按相关方案执行 `npm test`、`npm run typecheck`、开发及生产构建；先做开发构建再做生产构建，或将开发输出放到临时目录，避免覆盖已验收的 `dist`。生产构建的发布校验至少通过一次。
4. **浏览器检查**：引擎导入、注册、素材、加载或发布行为改变时，在独立托管页面检查受影响视角、近景、移动碰撞、拖动缩放、设置和 Inspector。对首屏/加载优化，用相同浏览器、视口、DPR、缓存和网络条件保存实际请求；构建时的静态入口统计不能代替它。
5. **避免误判**：注册回归使用没有 core 总入口预热的独立进程；否则既有测试可能提前注册功能，掩盖 pure 模式下的缺失。浏览器记录运行/着色器错误、404 和已有告警，不能把“无新增错误”写成“零告警”。
6. **测量边界**：静态截图不自动扩大为 FPS 或加载速度实验。性能测试遵循用户当前授权及暂停指令；未经测量不推断耗时收益，不用关屏/后台样本宣称亮屏性能达标。
7. **完成后**：保存前后字节、模块/资源清单、配置、截图/请求证据、实际结果与遗留事项，更新方案、索引和变更日志，再按项目约定提交推送。只有文档/规范变化时，核对链接、预算与脚本一致性及 Git 差异即可，无需重跑渲染和构建。
