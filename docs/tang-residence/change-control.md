# 决策、变更与质量检查

更新时间：2026-10-18。当前档案版本 `0.1`，详见[入口](README.md)。本流程用于落实已授权的工作，不新增逐项审批；用户直接要求的调整应在现有授权范围内执行，并留下依据和影响记录。

## 1. 每次变更的处理顺序

1. **登记目标**：建立 CR，写清用户指令或新证据、旧值、新值、范围和当前基线。先读 SET 与未关闭 Q，定位涉及的 SP、EL、OT、PL、H、AS；不从模型或截图反推背景。
2. **展开影响**：从下表逐领域检查，并检索相关 ID 的全部引用与共享资产使用者。既处理直接依赖，也检查生活逻辑和间接影响；“检索无引用”不能证明没有影响。
3. **更新主数据**：先修改对应设定/空间/原型，再同步布置、素材、图面、代码、地图、交互/文字/音效及方案。新值需要证据时先补证或记录简化推演，不能静默猜测。
4. **逐项验证**：每个影响项标“已复查无需改及原因 / 已修改待验 / 已验证及证据 / 待处理及 Q”。未实现内容只做设计复核，不标成场景验收通过。
5. **收口记录**：确认旧值无活跃冲突，补充结果、残留事项、影响项状态、图面/验收、版本、CHANGELOG 和提交。相关对象未完成时，不能通过关闭上游 CR 将其自动结项。

ID 检索优先使用 `rg 'SET-001|OT-019|AS-003' docs/tang-residence docs/technical-plans src tests public` 等具体范围；命中用于定位，是否历史快照、代码还是当前主数据需人工判断。新增对象和实际代码映射不齐全时，检索不能替代完整清单检查。
