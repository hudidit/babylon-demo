## 1. 背景与目标

现有灰盒步道约192.94米，默认步行速度的控制器标尺推算单程约166秒。用户认为这一旅行时间对小游戏偏长，希望保留灯塔的远方感，同时减少赶路等待。

推荐增加一辆停在家门外的单座小电驴。玩家出门上车，沿步道骑到灯塔，随时停车看海，再骑回家。保持当前地标位置、道路长度和室内步行速度，以载具提供更快的旅行方式。

| 方式 | 单程节奏 | 用途 |
| --- | --- | --- |
| 步行 | 约2分46秒，现有控制器推算值 | 近距离探索和停留 |
| 小电驴 | 目标约40～50秒，不含停留 | 房屋与灯塔之间的日常往返 |

载具初始巡航上限5米/秒，约18公里/小时；按全路线匀速计算约38.6秒，40～50秒是计入起步、缓弯与停车后的设计目标，须在可通行灰盒中实际往返校准。若频繁急弯使目标无法达到，优先调整局部圆角和限速过渡，再调整巡航参数。

## 2. 载具外观与范围

小电驴采用低饱和苔绿车身、米白前面板、深色坐垫和两个小轮子，风格与房屋相配。车长约1.65米、把手宽约0.65米，适应现有1.8米步道；道路、护栏和车辆完整外廓仍需一起检查。

首版只提供一辆车。使用原创简单几何表现车身、踏板、坐垫、车把与车轮；轮子随位移转动、前轮随转向变化即可。驾驶使用第一人称，画面下方看到车把与少量前面板，不制作人物、手部或上下车动作。上下车平滑切换视点，保留既有视野设置，不增加速度晃动。

采用稳定直立的街机操控，不加入真实两轮平衡、侧翻、摔车、损坏、电量、充电、装备升级或车辆跳跃。首版不新增音频素材、车灯光源、第三人称跟随镜头或物理引擎。

## 3. 操作与旅行流程

### 3.1 基本操作

| 输入 | 行为 |
| --- | --- |
| 靠近并看向车辆，左键或E | 停车状态下上车；沿用中心交互提示，默认距离约1.5米 |
| W / ↑ | 前进，平滑加速到当前路段上限 |
| S / ↓ | 行进时刹车，停稳后继续按住则低速倒车 |
| A、D / ←、→ | 左右转向；低速允许很小半径调头，停车时可原地调整朝向 |
| 松开行驶键 | 自动减速停车，不要求一直捏刹车 |
| 空格 | 快速刹停；骑乘时不触发人物跳跃 |
| E | 下车；行进中先刹停，再寻找安全落脚点 |
| 鼠标、M、ESC | 环顾、地图及退出沿用现有习惯；打开界面或退出时先停车 |

鼠标只负责看风景，车辆方向由A/D控制；看向海面不会把车带向悬崖。按键提示只在初次上车及状态变化时简短显示。既有“移动速度”设置继续只影响步行，载具速度按米/秒单独控制。

### 3.2 停车与寻车

家门外放置一个小停车位，避开门扇扫掠和主通路；灯塔前场与途中观景点各留一处停车空间。无需精确对准车位，停在有足够支撑的室外路面或路肩即可下车；停车位只是提示和可靠的调头空间。

下车优先选择车辆侧面的有效位置，再尝试另一侧和后方，同时检查地形、人物半径和障碍物。没有安全位置时保持停车并提示稍微挪车，不把人物放进墙体、护栏或悬崖外。车辆留在原地，海岸地图显示它的位置；本次页面会话内保留停车状态，刷新后恢复家门初始车位。

与灯塔阶段B的“回到家门”统一处理：主动回家时，人物和车辆一起回到各自的家门有效位置，清空速度，避免车辆遗留在灯塔。正常往返仍可全程骑行；不增加另一套传送按钮。

### 3.3 容错与限速

巡航初值5米/秒，家门附近、急弯和停车区自动降到约2米/秒，倒车上限约1米/秒。加速、松键减速和快速刹停分别调参，先让方向和停车容易掌握，再微调旅行时间。

车辆可以在连续、允许骑行的路面与近路草地内移动。接近崖缘、缺失地面或明显陡坡时减速并阻止越界；碰到墙、石块、灯塔或护栏时停止，不弹飞、不摔下去。门口阻止车辆驶入房屋，玩家下车后正常进门。车辆停靠时也不应成为堵住人物或入户门的障碍。

## 4. 实现方式与依赖

灯塔阶段B的出屋通行与真实地面支撑是前置工作。当前阶段A仍有室内范围限制，不能仅提高相机速度、把车绑定相机就视为载具完成。建议顺序为：**灯塔B → 载具灰盒与操控 → 灯塔C及载具外观 → 合并工程验收**。

载具采用独立的米制速度、朝向和骑乘状态，按时间推进位置。角色步行与骑乘输入互斥；骑乘时停用人物的水平键盘位移和跳跃，保留鼠标环顾。下车恢复原有步行速度及控制器，不叠加相机惯性。

地面查询复用阶段B同源支撑，覆盖实际地形三角形、路面与平台顶面。前后轮及车身宽度范围的支撑共同决定允许位置和坡度；车身只做小幅贴坡，不能仅查询车中心后让轮子悬空。碰撞使用简化车身外廓与连续移动检查，长帧分步，避免高速跨过细护栏或狭窄转角。

骑乘状态统一处理“步行、驾驶、界面暂停”。地图/设置、指针锁定丢失、窗口失焦、页面隐藏、切换预设均立即清空行驶输入和速度；恢复时等新的按键才起步。切换预设前落定停车位置，重新进入第一人称恢复原位置与骑乘状态。主动回家和异常恢复清理旧状态，场景销毁注销监听与共享资源。

交互优先级区分车体与室内物件，驾驶中不远程触发门、抽屉或信件。车辆网格使用场景级所有者，不挂在某个房间下，避免房间重建重复生成或提前销毁。

## 5. 资源与预算

沿用pure精确导入、显式注册和室外材质/日光体系；优先复用既有材质。新增程序几何、控制器和状态仍需计入JS、顶点和运行资源，不能按“没有GLB”当作零成本。

| 指标 | 阶段A实测基线 | 硬预算 | 本载具设计分配 |
| --- | ---: | ---: | --- |
| 两目标GLB | 4,332,840字节 | 4.25MiB | 保持不变 |
| 运行素材 | 15,867,631字节 | 16MiB | 不新增下载素材 |
| 实际首屏JS，含必需异步 | 2,816,507字节 | 3MiB | 净增目标≤64KiB |
| 完整发布目录 | 42,216,937字节 | 41MiB | 净增目标≤128KiB，包含全部分包及说明 |

载具几何目标≤5,000顶点、≤10个网格、新增材质≤2，不新增纹理、光源、相机或阴影渲染目标。阴影是否需要更新复用已有外景策略，并记录动态车体造成的绘制/更新成本。

这份分配占用灯塔方案原有剩余空间，不叠加提高原预算。灯塔B/C和载具合并实施时须重新汇总；阶段A尚余实际首屏329,221字节、完整发布774,679字节。旅行时间目标不代表FPS或加载速度收益，原暂停的性能实验继续暂停。

验证以真实输入完成全程往返，记录上车到塔前停车的时间、限速区与转弯次数，不把匀速公式当实测。覆盖急转、倒车、坡面、道路边缘、护栏、门口和无安全下车位置；低帧率长步及连续按键时不能越界。

检查骑乘空格只刹车、下车后人物跳跃正常；调整步行倍率不改变车速。地图/设置、ESC、指针锁定、后台恢复及切换预设不得无人驾驶；主动回家后人物与车的位置均有效。保留门扇扫掠、家具跳跃、双卫镜面、门灯抽屉与信件交互。

实施时完成必要测试、类型检查、临时目录开发构建及生产发布校验。独立托管最终dist，核验根路径和子路径的完整文件/动态分包与实际首屏JS；Chrome/WebKit检查横竖屏及DPR1/2，其他平台按实际条件记录。保存同姿态画面、资源计数和实际字节后同步本方案、索引和变更日志。
