## 1. 背景与目标

最初阶段A灰盒步道约192.94米，默认步行速度推算单程约166秒。实施基线已完成灯塔A～D，当前连续路线194.07米，真实步行去程163.53秒、返回163.04秒。用户希望保留灯塔的远方感，同时减少赶路等待。

推荐增加一辆停在家门外的单座小电驴。玩家出门上车，沿步道骑到灯塔，随时停车看海，再骑回家。保持当前地标位置、道路长度和室内步行速度，以载具提供更快的旅行方式。

| 方式 | 单程节奏 | 用途 |
| --- | --- | --- |
| 步行 | 约2分43秒，灯塔D实际输入记录 | 近距离探索和停留 |
| 小电驴 | 目标约40～50秒，不含停留 | 房屋与灯塔之间的日常往返 |

载具初始巡航上限5米/秒，约18公里/小时；按当前全路线匀速计算约38.8秒，40～50秒是计入起步、缓弯与停车后的设计目标，须在可通行灰盒中实际往返校准。若频繁急弯使目标无法达到，优先调整局部圆角和限速过渡，再调整巡航参数。2026-10-18用户反馈18 km/h过慢、转向偏灵敏，实际交付改为40 km/h巡航并将转向偏航响应减半；上述5米/秒和40～50秒保留为调整前的历史设计基线，见第9节。

## 2. 载具外观与范围

小电驴采用低饱和苔绿车身、米白前面板、深色坐垫和两个小轮子，风格与房屋相配。车长约1.65米、把手宽约0.65米，适应现有1.8米步道；道路、护栏和车辆完整外廓仍需一起检查。

首版只提供一辆车。使用原创简单几何表现车身、踏板、坐垫、车把与车轮；轮子随位移转动、前轮随转向变化即可。驾驶使用第一人称，画面下方看到车把与少量前面板，不制作人物、手部或上下车动作。上下车平滑切换视点，保留既有视野设置，不增加速度晃动。

采用稳定直立的街机操控，不加入真实两轮平衡、侧翻、摔车、损坏、电量、充电、装备升级或车辆跳跃。首版不新增音频素材、车灯光源、第三人称跟随镜头或物理引擎。

## 3. 操作与旅行流程

### 3.1 基本操作

| 输入 | 行为 |
| --- | --- |
| 靠近并看向车辆，左键或E | 停车状态下上车；沿用中心交互提示，默认距离约1.5米 |
| W / ↑ | 前进，平滑加速到统一40 km/h上限 |
| S / ↓ | 行进时刹车，停稳后继续按住则低速倒车 |
| A、D / ←、→ | 左右转向；低速允许很小半径调头，停车时可原地调整朝向 |
| 松开行驶键 | 自动减速停车，不要求一直捏刹车 |
| 空格 | 快速刹停；骑乘时不触发人物跳跃 |
| E | 下车；行进中先刹停，再寻找安全落脚点 |
| 鼠标、M、ESC | 环顾、地图及退出沿用现有习惯；打开界面或退出时先停车 |

鼠标只负责看风景，车辆方向由A/D控制；看向海面不会把车带向悬崖。按键提示只在初次上车及状态变化时简短显示。既有“移动速度”设置继续只影响步行，载具速度按米/秒单独控制。

### 3.2 停车与寻车

家门外放置一个小停车位，避开门扇扫掠和主通路；灯塔前场与途中观景点各留一处停车空间。无需精确对准车位，停在有足够支撑的室外路面或路肩即可下车；停车位只是提示和可靠的调头空间。

下车优先选择车辆侧面的有效位置，再尝试另一侧和后方，同时检查地形、人物半径和障碍物。没有安全位置时保持停车并提示稍微挪车，不把人物放进墙体、护栏或悬崖外。车辆留在原地，海岸地图显示它的位置；本次页面会话内保留停车状态，刷新后恢复家门初始车位。

与灯塔阶段B的“回到家门”统一处理：主动回家时，人物和车辆一起回到各自的家门有效位置，清空速度，避免车辆遗留在灯塔。正常往返仍可全程骑行；不增加另一套传送按钮。

### 3.3 容错与速度

当前前进统一以40 km/h为上限，倒车上限约1米/秒，A/D转向响应为初版的0.5。2026-10-19按用户要求取消家门、急弯、停车区和边缘的自动减速；加速、松键减速、S/空格手动刹车参数保持。历史18 km/h巡航、2米/秒限速区及后续调参结果见第8/9节。

车辆可以在连续、允许骑行的路面与近路草地内移动。完整外廓地面检查阻止驶过崖缘、缺失地面或明显陡坡；减速由玩家通过S/空格控制；碰到墙、石块、灯塔或护栏时停止，不弹飞、不摔下去。门口阻止车辆驶入房屋，玩家下车后正常进门。车辆停靠时也不应成为堵住人物或入户门的障碍。

## 4. 实现方式与依赖

灯塔阶段B的出屋通行与真实地面支撑是前置工作。该前置工作现已完成。车辆仍需独立速度/朝向、完整外廓与状态控制。原定顺序为：**灯塔B → 载具灰盒与操控 → 灯塔C及载具外观 → 合并工程验收**。

载具采用独立的米制速度、朝向和骑乘状态，按时间推进位置。角色步行与骑乘输入互斥；骑乘时停用人物的水平键盘位移和跳跃，保留鼠标环顾。下车恢复原有步行速度及控制器，不叠加相机惯性。

地面查询复用阶段B同源支撑，覆盖实际地形三角形、路面与平台顶面。前后轮及车身宽度范围的支撑共同决定允许位置和坡度；车身只做小幅贴坡，不能仅查询车中心后让轮子悬空。碰撞使用简化车身外廓与连续移动检查，长帧分步，避免高速跨过细护栏或狭窄转角。

骑乘状态统一处理“步行、驾驶、界面暂停”。地图/设置、指针锁定丢失、窗口失焦、页面隐藏、切换预设均立即清空行驶输入和速度；恢复时等新的按键才起步。切换预设前落定停车位置，重新进入第一人称恢复原位置与骑乘状态。主动回家和异常恢复清理旧状态，场景销毁注销监听与共享资源。

交互优先级区分车体与室内物件，驾驶中不远程触发门、抽屉或信件。车辆网格使用场景级所有者，不挂在某个房间下，避免房间重建重复生成或提前销毁。

## 9. 用户反馈调参（2026-10-18）

### 9.1 背景与目标

V1～V3交付后，用户实际驾驶反馈两点：HUD最高只到18 km/h，明显慢于现实常见40 km/h；A/D方向过于灵敏，希望降低50%。本轮目标只调整驾驶手感，不改路线、车体外观、停车位、相机、碰撞、资源或既有交互。

### 9.2 方案与实施

`SCOOTER`新增两个明确参数：

- `cruise: 40 / 3.6`：控制器继续使用米/秒，HUD沿用`速度 × 3.6`显示，最高稳定显示40 km/h；不另做公里/小时控制分支。
- `steerSensitivity: .5`：现有“低速小半径、高速略增”的转向曲线保持不变，只把整条偏航响应乘以0.5。这样原地、低速和高速都严格降低50%，不引入新的速度分段或隐藏参数。

`advanceScooter`的偏航角增量应用`steerSensitivity`；其他加速度、滑行减速、急刹、倒车和限速区参数保持不变。未新增网格、材质、纹理、灯、相机或下载资源，未修改HUD布局与提示文字。

### 9.3 验证与实际结果
