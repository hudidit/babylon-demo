# 剧情步骤一：任务、章节与消息状态机

状态：已完成（纯逻辑、完整故事检查点及原页面独立发布回归）。创建及更新：2026-10-22。输入基线：`9b80607`。上位设计：[三天代班剧情](2026-10-21-lighthouse-three-day-story.md)；工程约束：[资源与首屏优化原则](../resource-optimization-principles.md)。

## 背景与现状

已有设备、天气、线索及版本2完整值守存档，正常与演练分槽。三天剧情只有设计，尚无任务推进、章节、正式联络、运输或结尾状态。当前正常槽继续作为探索值守保留，不能将它当作故事槽。

## 目标与范围

- 新增无 Babylon、DOM、网络或墙上时钟依赖的 `LighthouseStory.ts`，实现 ST01—ST11、三章与留站尾声、可回读消息、运输和主动结束。
- 原始设备事实经独立输入边界传入，保存设备对象、原事件、修订、问题实例、方法和最小事实。提前证据可用，失效证据保留历史；已完成任务不受原设备七日日志裁剪影响。
- 故事使用独立身份、连续接受小时和满72小时接送计划。消息按原发送时间留档，正式来源和旧呼号标签分开；报告、发出核对、收到回复及已读分别保存。
- `LighthouseStorySave.ts` 将剧情与已有完整天气/设备检查点放入独立故事槽，严格校验后恢复并先暂停；不自动读取、升级或覆盖探索/演练槽。
- 本步通过事件夹具跑完全篇和异常路径。场景入口、实际设备事件适配、故事天气/专用问题安排、等待结算、玩家界面和完整实际游玩分别留步骤二至五，不宣称已可玩。

## 方案及取舍

剧情控制器只接收已提交事实，不写设备、Wh、天气或维护期限。输入设备事件在各来源内按原编号递增转发；保留来源游标防止重订阅/读档后旧事件再次生效。晚到事实保留自身发生时刻，不能伪造当前观察。消息、报告和玩家命令按语义稳定编号幂等处理，拒绝的命令可以在条件满足后重试。

当前事实保留有界缓存；每个任务及报告另存完成时的事实和上下文。任务历史只证明当时完成，提交新报告、当前交接和延班导航仍检查当前修订/日序/来源。清洁是动作记录，不能代替独立复查；普通未见和疑点不能冒充确定结果。

报告提交、岸站回复、玩家阅读使用独立状态，允许在任意两步间保存。正式取消于故事接受时间72小时发生，独立于当前雨量和任务进度；迟做正文承认尚未收到报告。旧呼号消息在延班导航完成且无动作进行时发出，核对结论只说明岸站没有发送记录，不确认未知发送者。

故事检查点采用单独版本封套和新键，里面的设备/天气仍复用原版本2编解码。故事时钟必须与设备日序、钟面和天气接受小时一致，拒绝探索手动选时混入故事。旧探索槽的迁移继续由既有实现负责，本步不复制旧槽或改动玩家模式菜单。

### 实施中调整：共享回执跨日守恒

扩展完整故事存档至85.1接受小时后，在第325个0.037小时回执发现：故事为第2日00:01，设备却为第3日。既有`advanceWeatherDuty`在五分钟天气分段的午夜边界把末端写为略小于24；运行模型已经跨日，下一段却又收到这个旧钟面，于是再次计数。严格故事封套正确拒绝此矛盾，不能放宽日序校验或缩短测试绕过。

本任务因此追加最小前置修复：中间天气分段在1e-9小时误差内归一为午夜0点，最后一段仍精确沿用原回执钟面；跨日字段只分配原回执尚未分配的次数，最后一段接收余量。新增原天气桥回归，按不同步长/手动选时后的有效回执验证日序；夹具沿用共享时钟在整数小时的1e-10舍入，避免把未舍入的伪回执当作原时钟。重跑工程与生产浏览器检查。运行桥进入入口，因此不再预设最终生产包与输入逐字节相同，按实际差异记录预算与功能。

- 全任务按依赖完成；只读文本不能补造工作，缺失/陈旧/错误来源证据、未解决差额、未说明的关键异常和主备均不可用时不可跳过。
- 重复命令、重复设备事件、重复发信/回复/阅读/结尾不产生额外状态；可选材料全部跳过仍可完成。
- 提前清洁及独立复查、直接细查、两次普通未见、跨日重新确认、超72小时才读消息、极晚完成使用真实时间和原消息。
- 保存于提交/等待回复/回复未读、取消通知未读、留站后、核对请求/回复以及结束前后，恢复结果一致，不重抽天气、不重放设备动作、不补算离线。
- 严格拒绝未知字段/版本、越界或矛盾时间、跳过依赖、伪造来源、错误事实引用及跨模式封套；失败保持当前会话与旧槽，探索/演练原始数据逐字节保持。
- 沿用 GLB 4.25 MiB、运行素材16 MiB、实际首屏JS 3 MiB和完整发布41 MiB。纯逻辑未接入运行包时须以构建及清单证据说明；不据此声称加载/FPS改善或剧情现场验收完成。
