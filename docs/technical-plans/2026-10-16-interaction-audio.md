## 1. 推荐决策

采用 **“实物录音素材为主、简单提示音离线合成为辅，Babylon Audio V2 统一管理，短音效预加载并复用解码结果”** 的方案。

1. 木抽屉、门轴/门扣、灯开关、纸张使用第三方录音，优先逐项核实为 CC0 的素材。它们需要材质细节，现成录音的投入产出通常更适合本项目。找不到合适录音时，优先自行录制。
2. 简单界面轻点声可用脚本在本地离线合成；本地 AI 生成作为以后特殊音色的候选途径。首期无需安装生成模型，也无需接入在线生成服务。
3. 所有交付音频放进项目，由应用自己的静态站点提供。第三方平台只用于制作阶段获取素材，运行时不访问素材平台。
4. 首期复用已安装的 Babylon Audio V2，以一个 `RoomAudio` 管理类处理解锁、缓存、音量、并发和清理。先验证精确导入、动态分包与浏览器行为，再全面接入。
5. 声音响应已发生的动作和真实运动状态；声音加载失败、被浏览器限制或用户静音时，交互照常执行。

预加载、短音频缓冲复用、用户手势解锁和音量控制有浏览器官方指南依据；素材配比、音量、并发数和分期方式是针对本项目的设计判断，需实施时试听验证。不存在适用于所有项目的唯一音频库或音量参数。[MDN Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)

## 2. 背景与现状

已阅读[资源与首屏优化原则](../resource-optimization-principles.md)、[房间交互方案](2026-10-16-room-interactions.md)、[物品详情方案](2026-10-16-item-inspection.md)、[连通门方案](2026-10-16-connecting-door.md)和[墙面替换验收](assets/painted-walls-2026-10-16/README.md)。

- [RoomInteractions.ts](../../src/examples/RoomInteractions.ts) 集中注册八个抽屉、三盏灯、一扇连通门和信件。拾取已有遮挡、距离及拖动误触保护，适合在动作被接受后发出音频事件。
- 抽屉全程标称 0.45 秒，门全程标称 0.7 秒，均可中途反向；门还会因为玩家挡住扫掠范围暂停。它们不是不可取消的固定时长动画，不能点击时便预约一个“关到底”的声音。
- [Room.ts](../../src/examples/Room.ts) 在信件详情打开时停止更新房间交互动画；页面隐藏时停止渲染。音频必须同步处理这些暂停，否则音画会脱节。
- 环绕相机经常离物件很远；第一人称相机的可交互距离为 7.5 个场景单位。两种视角需要不同的空间音频策略。
- [BasicExamples.ts](../../src/components/BasicExamples.ts) 已有设置及本地保存流程，[页面](../../public/index.html) 可增加音效开关/音量；详情模式当前会隐藏工具栏，需保留可达的静音入口。
- 当前运行代码没有音频管理。`RoomRuntime.ts` 没有注册旧版音频组件，后续不能为了音效改回 Babylon 总入口。

## 3. 目标、声音风格与范围

声音保持安静、干燥、近距离的木质/纸张/机械质感，匹配胡桃木、黄铜与复古房间。先使关键操作有反馈，不为所有点击、悬停和相机移动增加声音。

| 交互 | 首期声音 | 触发时机与边界 |
| --- | --- | --- |
| 抽屉 | 短木质滑动；到位轻碰声 | 实际开始移动时播放滑动，到达真实端点时播放轻碰；中途反向停止旧滑动声，再对应新方向 |
| 灯具 | 一次轻微机械开关声 | 开关状态成功改变后播放，三盏灯复用音频数据，各自有声源位置 |
| 连通门 | 短门轴摩擦；关闭门扣声 | 实际移动才响；被挡住时淡出运动声，恢复移动时可重新触发；仅完全关闭时响门扣 |
| 查看/返回信件 | 轻纸张摩擦 | 详情成功打开或关闭后播放一次，以二维声音呈现 |
| 普通界面 | 可选的轻点声 | 基础交互稳定后再评估；音量滑块不逐格响，静音操作本身不发声 |

首期约 10～14 个短片段：按材质共享，常用动作提供两个变化版本，避免八个抽屉各下载一套。滑动/摩擦片段与到位/门扣片段分开，防止反向或受阻时仍听见素材自带的关门撞击。

脚步、持续环境声、音乐、对话、混响、穿墙遮挡和复杂声学模拟不在首期范围。它们分别涉及移动节奏、流式加载或声学设计，后续有需求时另行扩展。

## 4. 音频素材从哪里来

### 4.1 获取途径与选择

| 途径 | 推荐用途 | 优点 | 成本与取舍 | 本项目选择 |
| --- | --- | --- | --- | --- |
| 第三方录音素材 | 木抽屉、门、开关、纸张 | 实物质感成熟，无需录音设备 | 要筛选、试听、统一响度并核实每条许可 | 实物音效的主要来源 |
| 本地程序合成 | 简单 click、提示音、原型占位 | 可重复生成，参数可追踪，体积很小 | 很难以简单波形表现真实木材与纸张 | 少量界面提示，离线导出文件 |
| 自己录音 | 对特定家具/门声有要求时 | 容易贴合交互，录制几种力度方便 | 需要安静环境、剪辑和降噪；手机可起步 | 找不到合适素材时的首选补充 |
| 本地 AI 生成 | 不常见的特殊声音探索 | 可以按描述探索音色 | 模型运行资源、输出控制、版本重现及许可需评估 | 首期不依赖；以后离线试验 |
| 商业素材库/云生成 | 对独特音色或一致性要求更高时 | 候选多，可购买专门音效包 | 费用和条款各异，需覆盖 Web 交付与仓库分发方式 | 免费候选不足时再评估 |

这里的“本地生成”首先指离线程序合成，而不是让用户浏览器现场运行模型。推荐交付普通音频文件，和录音素材走同一加载、音量及验收流程。AI 输出也要固定保存，不能依赖每次重新生成获得相同结果。

### 4.2 推荐平台和筛选方法

- **Freesound**：作为实物录音的主要搜索入口。使用 `wood drawer slide`、`wooden door hinge`、`door latch`、`lamp switch`、`paper handling` 等关键词，并筛选 CC0、短时长、低底噪、少混响。下载需要账号；每条素材的作者和许可独立核实，不能把平台上的声音一律视为免署名。[Freesound 官方 FAQ](https://freesound.org/help/faq/)
- **Kenney Interface Sounds**：适合界面轻点和原型候选，该包页面明确标记 CC0。其声音是否适合写实灯开关仍需试听，不能仅凭分类确定。[官方素材包](https://kenney.nl/assets/interface-sounds)
- 第一轮优先比较同一作者/同一录音系列的候选，以减少音色与录音环境差异；每类保留少量候选，最终结合实际动作节奏试听。

这两处是已核对的平台/素材包入口，**还没有选定、下载或验听任何具体交付音频**。实施时要记录逐文件选择结果。

### 4.3 许可和来源管理

首期优先 CC0；优质 CC BY 素材可作为补充，但必须交付作者、标题、来源、许可和修改说明，并提供页面中的“素材来源”入口。首期排除 CC BY-NC、禁止改编及许可不清的候选，以保持以后商业用途与裁切处理的选择空间。CC0 允许复制、修改及商业使用；仍保存来源，且不意味着平台替上传者验证了全部权利。[CC0 说明](https://creativecommons.org/publicdomain/zero/1.0/)、[Creative Commons 署名指南](https://creativecommons.org/reusing-cc-licensed-content/)

商业包的“royalty-free”不能直接等同于可把原始音频放进公开 Git 仓库；选用时按该包实际条款确认应用内交付、修改和仓库分发权限。本地 AI 也不能因为“在本机生成”就自动认定许可明确，应记录模型、权重条款、工具版本、提示词及输出来源。

每个最终片段至少记录：素材 ID、原始标题、作者、原始页面 URL、下载日期、许可标识/链接及随包许可证据、原件 SHA256、裁切/声道/采样率/增益/编码参数、工具版本、交付路径及 SHA256。多来源混音要保留全部来源。

拟新增 `public/audio/study/source.json` 保存记录，并更新 [STUDY_ASSET_SOURCES.md](../../public/STUDY_ASSET_SOURCES.md)。少量获准再分发的原件保存在发布目录之外的 `assets/audio-source/study/`；处理脚本放 `tools/`。大包不整体进入仓库，临时候选和中间文件不提交。不可公开分发的原件应保存到受控归档，并记录恢复方式，不把不可恢复的临时路径作为唯一来源。

## 5. 素材制作与格式

### 5.1 推荐处理流程

`获取原件与许可 → 试听选段 → 裁切 → 轻量清理/声道处理 → 同类音量校准 → 导出候选 → 浏览器解码试听 → 固定交付摘要`

- 原件保留无损 WAV/FLAC，按照原件真实规格记录；低规格录音上采样不会增加细节。后续重新制作从原件开始，避免对有损交付反复压缩。
- 短开关/碰撞通常约 0.05～0.25 秒，纸张约 0.2～0.6 秒，运动片段控制在约 0.2～0.7 秒。动作长短与试听优先，不机械地把所有文件剪成一样长。
- 去除明显前导空白和不需要的尾声，保留瞬态；仅在需要处做约 2～10 ms 的淡入淡出，避免截断爆音，不把机械开关的起音磨平。
- 点状实物声优先单声道，便于定位并减少文件与解码内存。立体声原件转单声道前检查相位抵消；首期不保留录音房间的大量混响。
- 先统一同类片段的主观响度，再在场景混音。几十毫秒短声不统一套用音乐的 `-14 LUFS` 目标；检查交付文件解码后的峰值，建议至少留约 3 dB 峰值余量，同时验收多声叠加不削波。
- Audacity 可用于选段、试听与编辑，FFmpeg 可用于批量转换；将确定的处理步骤、时间区间和参数保存为可复现脚本/记录。本地合成固定参数与随机种子，不在运行时生成随机音色。

### 5.2 交付格式

**默认 MP3，44.1 或 48 kHz、单声道，先以 96 kbps 制作试听候选；特别短且依赖清晰瞬态的开关/碰撞可直接用 PCM 16-bit WAV。** 96 kbps 是本项目的起始试验值，不是所有音效的质量标准；听出失真就提高码率或改用 WAV。

MP3 的主流浏览器支持广，适合先保持交付简单；Opus/Ogg 等暂不作为必需格式。不先为每个音效同时交付两份格式，若目标浏览器实测需要备选，再计入全部副本和验收成本。[MDN 音频编码指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs)

压缩文件小不代表解码后内存小。短音效完整下载并解码，后续播放复用数据；长音乐/长环境声以后使用流式方案。`decodeAudioData()` 需要完整文件数据，不能把音频 HTTP 分段当成可直接播放的解码块。[MDN decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)

首期使用独立小文件，控制数量。不预先建设音频 sprite：它虽然可合并请求，但也把加载、修改和失败绑定到一个文件，需要额外维护片段边界；只有请求数实测成为瓶颈后再比较收益。

## 6. 播放技术与代码边界

### 6.1 引擎选择

| 选择 | 适用情况 | 本项目取舍 |
| --- | --- | --- |
| Babylon Audio V2 | 已有 Babylon 场景，需要缓冲声音、总线与空间定位 | 首选，复用现有版本，业务层保持小而集中 |
| 原生 Web Audio | 少量二维短声、希望完全掌控依赖 | 可作验证失败后的备选；需要自己维护音频图、空间坐标与节点生命周期 |
| Howler.js | 独立 Web 产品需要统一播放封装及 HTML Audio 回退 | 能力合适，但本项目已有引擎，不再并行维护另一套音频生命周期 |
| 每次点击创建 `<audio>` | 简单演示或长媒体播放 | 不用于本项目高频短声，避免每次动作重新准备播放 |

Howler 官方提供缓存、空间声和 Web Audio/HTML Audio 回退，作为备选有成熟依据；本方案没有把其官网压缩体积当成本项目的实际新增体积。[Howler 官方介绍](https://howlerjs.com/)

本地已核对 `@babylonjs/core@9.30.0`：`AudioV2/webAudio/webAudioEngine` 导出 `CreateAudioEngineAsync`，引擎提供 `createSoundBufferAsync`、`createSoundAsync`、`createBusAsync`、`unlockAsync`、`pauseAsync`、`resumeAsync` 和空间 listener。`StaticSoundBuffer` 可以由多个声音共享，缓冲声音的实际播放实例仍需限额。以安装版本的公开类型为准，不复制其他版本或 Babylon Lite 的 API 名称。

**已有依赖不等于没有新增 JS。** Audio V2 的声音与总线创建还会动态导入实现，实施阶段先做最小验证，检查 pure/精确导入是否带入额外系统。由 `RoomRuntime.ts` 集中维护确实需要的 Babylon 注册，不引入旧版 `Sound`/AudioSceneComponent，不添加 core 总入口或放宽现有模块检查。

### 6.2 拟议结构

| 文件/位置 | 职责 |
| --- | --- |
| 新增 `src/examples/RoomAudioCatalog.ts` | 强类型音效 ID、文件路径、变体、分组、基础增益、优先级、冷却时间与预加载级别；不包含播放逻辑 |
| 新增 `src/examples/RoomAudio.ts` | 一个音频引擎、加载去重、共享缓冲、有限播放实例、解锁/音量/暂停/销毁，以及可选空间声源 |
| 修改 `RoomInteractions.ts` | 在真实运动开始、反向、受阻、恢复、到位、灯状态改变时发出带实体 ID 的事件 |
| 修改 `Room.ts` | 组织音频生命周期，处理详情、相机、隐藏/恢复及销毁，转交事件 |
| 修改 `BasicExamples.ts` / `public/index.html` | 音量、静音、试听及本地偏好保存；保留详情模式的静音可达性 |
| `public/audio/study/` | 最终交付音频和来源说明；白名单按文件列出 |
| 新增对应音频测试/处理工具 | 保护失败、并发、状态与资源校验；实现阶段按真实风险编写 |

数据流为 `已接受的交互/动画状态变化 → 音频事件 → RoomAudio → 共享缓冲 + 独立播放实例 → effects/ui 总线 → 主音量 → 输出`。业务只认识音效 ID 和实体，不拼接 URL，不操作解码对象，也不等待音频 Promise 才开抽屉或切灯。

管理类提供类似 `preload(group)`、`unlockFromGesture()`、`play(id, entity)`、`stopEntity(entity)`、`setVolume()`、`setMuted()`、`pause()`、`dispose()` 的小接口。`play` 同步返回可停止的句柄或空结果；没有资源时立即降级。首期不建设跨音频库的通用框架。

## 7. 加载、缓存、解锁与失败处理

### 7.1 分阶段准备

| 阶段 | 工作 | 是否阻塞场景 |
| --- | --- | --- |
| 页面启动 | 读取容错后的音效偏好，准备轻量目录和手势监听 | 不等待音频网络或解码 |
| 必需场景资源完成、画面可交互后 | 初始化音频引擎并准备 P0：每类至少一个常用版本；限制为同时 2 个音频加载/解码任务 | 不加入模型 ready 的等待条件 |
| 后续空闲时 | 准备 P1：第二变体和可选界面声音；无空闲 API 时使用普通任务调度 | 可取消，不抢必需模型/贴图加载 |
| 有效用户手势 | 在同一输入回调内发起恢复/解锁；已经准备好的声音可响应当前动作 | 不延迟业务动作 |
| 用户已保存静音 | 暂缓音频预加载；启用时再准备，并显示短暂“音效准备中”状态 | 场景始终可用 |

这样优先准备会常用的短声，而不是第一次点击某个抽屉时才开始下载。预加载期间若用户提前操作，视觉动作仍立即生效，该次声音允许缺失，界面不假称全部音效已就绪。首屏画面可用与音频准备完成分开记录，不能靠延后请求虚报总下载量减少。

### 7.2 解锁与状态模型

浏览器可能禁止没有用户手势的声音，尤其要检查 Safari/iOS。下载完成、音频引擎初始化完成和允许发声是三件事，分别维护 `idle/loading/ready/failed`、引擎 `suspended/running/interrupted/closed` 及用户 `muted/volume`。[MDN 自动播放指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

- 引擎初始化可发生在播放解锁前；建议禁用默认浮层与后台自动恢复：`disableDefaultUI: true`、`resumeOnInteraction: false`、`resumeOnPause: false`。由项目自己的入口恢复，避免与设置/后台策略冲突。
- 保留一个由 `RoomAudio` 拥有的 `AudioContext`，设置 `latencyHint: "interactive"`，将其传给引擎；这是延迟偏好，不是实际输出延迟承诺。若初始化尚未完成，手势内可直接恢复已创建的 context，不能先等待网络或动态 import 再依赖原手势解锁。
- 在真实 canvas 操作、进入第一人称、启用音效/试听按钮的回调中同步发起解锁，随后继续原逻辑；不能 `await` 音频后才请求 Pointer Lock。键盘入口需来自真实操作，排除输入框、按键重复和合成事件，不阻止既有 ESC 行为。
- 调用底层 `play` 前同时检查缓冲、播放实例和 `running` 状态。不要让底层把 locked/suspended 时的旧声音自动积压，恢复后突然连响。
- 仅当缓冲和实例已就绪、当前手势的恢复正在完成时，允许暂存这一动作的候选，最长 100 ms；恢复后还要核对动作代次、实体状态、页面可见性和静音。其他加载未完成的事件直接丢弃，晚到资源不补播。
- 页面上提供“启用音效/试听”的明确入口供受限浏览器重试。失败不反复弹窗，不绕过用户静音；首期设置 `disableIOSRingerSwitchWorkaround: true`，尊重系统静音，iOS 实机验收记录实际结果。

### 7.3 缓存和网络

以最终 URL/内容版本作为缓存键保存一个加载 Promise，避免并发触发重复 fetch/decode。每个文件只解码一次，抽屉/灯具共享 `StaticSoundBuffer`；每个实体需要独立的可定位播放实例，不能改变一个共用声源的位置去同时代表两个物件。

预热还要完成总线、所需实现分包和可复用 `StaticSound` 对象的准备，不能只下载 MP3，等点击时再调用异步 `createSoundAsync`。物件注册后按需准备其声音对象；异步导入的古董柜也走同一流程，未准备好时该次声音降级。底层一次性播放节点由引擎按播放创建，复用的是缓冲和声音对象，不尝试重复启动一次性节点。

用项目控制的 fetch 读取完整文件，设置约 8 秒超时和取消，检查 HTTP 状态后交给引擎创建缓冲；失败标记到单项，不让整组 Promise 拒绝阻断其他声音。同会话每项最多做一次延后重试；切到后台时不自动重试，用户“重试音效”可重新发起。解码失败不无限换格式/重试。

初期保留全部短声缓冲，不引入 LRU、IndexedDB 或 Service Worker。下载后释放不再需要的编码字节引用；解码不能依赖 fetch 取消来停止，需用任务代次/销毁标记忽略晚到结果并清理对象。记录失败次数、准备耗时、活动实例及解码字节用于调试，正常页面不展示底层实现细节。

资源使用相对站点路径，核对带子路径部署；采用带内容版本的文件名或部署版本策略。版本化文件可配置长期缓存，HTML/索引按实际部署更新；这只是部署建议，只有验过响应头才能称已启用。运行时不热链第三方平台，不将音频 Base64 内嵌进 JS；同源静态托管避免额外 CORS 依赖。

## 8. 声音与交互状态同步

`RoomInteractions` 维护实体 ID 和运动代次，音频层消费状态事件，不读取渲染每帧的“正在开”布尔值反复播放：

1. **抽屉**：从静止进入移动时触发一次短滑动。目标改变时停止旧句柄并增加代次；只有更新真正跨入端点才发到位事件。碰撞/到位声音不使用固定 `setTimeout(450)`。
2. **门**：在扫掠通过且 `progress` 实际变化时才开始运动声。进入 blocked 状态时淡出，blocked 的每一帧都不重播；恢复移动时发一次恢复事件。反向取消旧句柄，只有实际到达关闭端点才发门扣声。
3. **灯**：改变灯光状态成功后发一次 `lamp.changed`，避免通用按钮声与机械开关声重复。
4. **信件**：`inspection.open()` / `close()` 成功后发二维纸张声。重复打开、无效关闭和销毁清理不发声；进入详情先停止运动声音，返回后仅为确实继续运动的物件重新准备，不补播暂停前事件。
5. **输入**：保留现有遮挡、距离、拖动和锁定检查；悬停、拾取失败、拖动结束、右键和 Pointer Lock 被拒绝不触发成功音效。

首期采用可取消的短运动片段加真实端点声音，不做持续滑动循环。没有循环拼接需求，也不会因动画被挡住无限响。连续运动的声音若自然结束，无需逐帧续播。

同类两个变体尽量避免连续选同一个；可加约 ±2% 播放速率和很小的音量变化，但不随机改变到位时机。冷却只抑制声音，不禁止用户快速反向操作；建议机械启动声按实体约 80 ms 冷却，停止旧声和真实到位事件仍正常处理。

## 9. 混音、空间感和用户控制

### 9.1 音量与并发

使用主音量及 `effects`、`ui` 两组总线，不把每个物件的音量暴露成用户设置。默认启用交互音效、音量滑块 50%，首次操作前保持无声；已有静音偏好优先。滑块采用固定的感知曲线映射增益，0 即无声，具体基础增益在扬声器/耳机试听后确定。

- 全局最多同时 6 个播放实例；每个实体最多 1 个运动声，运动结束后再发端点声。显式设置底层实例上限，不能保留默认无限并发。
- 开关/门扣/到位声优先于运动声，运动声优先于可选界面声。满额时淡出低优先级旧声或丢弃低优先级新声，不无限扩容。
- 停止、静音和音量变化约用 10～30 ms 平滑过渡，避免爆音；快速连续调整时合并为最新目标并串行应用短增益变化，避免引擎“已有 ramp”错误，不依赖私有节点接口。
- 总音量与并发上限不能单独保证不削波；验收六声叠加的实际输出峰值，必要时下调单声基础增益。首期不靠过强压缩器掩盖过响的素材。

### 9.2 二维/三维策略

基础阶段先把所有音效作为适度的二维反馈验收；空间阶段使用同一管理类增加以下规则：

- **环绕/预设视角**：保持二维，不按远处的环绕相机距离衰减，否则全屋视角点开抽屉几乎无声。
- **第一人称**：门、抽屉和灯使用单声道空间声源，绑定真实物件世界位置，listener 跟随第一人称相机的位置与朝向。声音在用户左右、接近/远离时应有正确变化。
- **信件详情/UI**：始终二维。详情的独立相机位于展示坐标，不能用它移动房间 listener 到世界原点；进出详情停止房间旧声，并正确恢复模式。

可先以约 4 个场景单位为衰减起点，使用 inverse 模型、约 0.8～1 的 rolloff，再在 7.5 单位交互范围内试听校准。这些单位不直接称为米；第一人称高度与房间模型比例需要一起考虑。空间模型可根据位置和方向衰减，不能把 `maxDistance` 一律解释成超距完全无声。[MDN PannerNode](https://developer.mozilla.org/en-US/docs/Web/API/PannerNode)

声源只在有活动实例时更新；复用世界位置，避免全场景每帧遍历或做音频射线。验证 Babylon 左手坐标和 Web Audio 空间转换的实际左右方向。首期不做穿墙遮挡、卷积混响或 HRTF 效果承诺。

### 9.3 用户控制与生命周期

- 工具栏提供有文字/可访问名称的音效开关，设置提供音量和一次短试听；详情模式也保留静音入口。音效不是操作成功的唯一提示，现有画面和文字继续有效。
- 按版本化键保存 `enabled` / `volume`，读取时校验类型、有限数值及范围；localStorage 不可用时使用会话默认值，不让设置异常阻断应用。恢复默认明确包含音效和移动速度。
- 静音时淡出并停止活动声音，期间的新事件不排队；取消静音仅影响之后的操作。
- 页面隐藏/失焦时停止短声、暂停音频引擎并清除候选事件。页面回来不补播，下一次有效手势恢复；不要建立后台轮询强行恢复声音。
- 场景销毁时取消加载、移除监听和 observer、停止/释放实例与总线、清空缓存，并由唯一所有者释放引擎/context。检查显式传入 context 的所有权，避免重复关闭或遗留第二个 context。

## 10. 资源与首屏预算

| 音频专项指标 | 首期目标 | 统计/执行方式 |
| --- | ---: | --- |
| 全部音效交付文件，含确需的备选格式 | ≤ 0.50 MiB | 新增音频专项检查，同时计入原 16 MiB 素材总额 |
| P0 常用版本 | ≤ 128 KiB，约 6～8 文件 | 场景 ready 后预热；实际数量以试听选择为准 |
| 解码缓冲 | ≤ 8 MiB | 按实际采样帧 × 声道 × 4 字节统计，不以 MP3 文件大小替代 |
| 同时播放实例 | ≤ 6 | 运行时硬限制及压力检查 |
| 音频新增实际 JS | 目标 ≤ 0.10 MiB | 模块图和浏览器测量；总首屏 JS 仍须 ≤ 3 MiB |

8 MiB 是缓冲 PCM 数据预算，不代表包含节点和引擎开销的进程内存上限。例如 20 秒、48 kHz、单声道 float32 约 3.66 MiB；浏览器重采样后用实际缓冲规格统计。

按历史字节作静态估算，增加 0.50 MiB 音频后运行素材约 15.20 MiB，完整目录再加 0.10 MiB 音频 JS 后约 40.27 MiB，尚有空间留给来源说明与发布清单。**这是规划估算，不能代替生产构建结果。** 若 Audio V2 的增量超过专项目标，先比较精确导入、所需能力和原生 Web Audio 备选；不能为了保留候选而提高全局预算。

新增交付文件必须进入 [study-release.config.cjs](../../tools/study-release.config.cjs) 的逐项 runtime 白名单；来源 JSON 和必要许可说明进入 documentation，并同步来源总表。构建校验要核对目录引用、文件摘要、音频规格/时长、来源状态和专项预算。来源未确认的新音效不发布。

静态初始 JS 继续由[现有分析器](../../tools/study-bundle-analysis.cjs)检查。音频引擎及其内部动态声音/总线分包，只要在首屏可用前被请求，全部进入实际首屏 JS；首屏后预热的音频 JS/文件单列准备阶段成本，完整交付仍计入全部动态分包、来源、许可与清单，不漏交“尚未触发”的文件。

## 12. 验收方法

### 12.1 工程与自动化

1. 保护真实失败路径：同文件并发只加载/解码一次、404/超时/坏文件只影响单项、迟到结果不补播、销毁后不新增对象；设置损坏/存储不可用仍可操作。
2. 用可控音频后端/时钟验证状态：未解锁/静音/后台不调用底层播放；恢复不放旧声；全局限额、优先级、同实体反向及终点事件正确；门受阻和详情暂停停止旧声。模拟测试不能代替浏览器的真实手势和声音。
3. 检查音频清单与代码 ID/路径一致、来源/摘要、音频解码规格、专项及全局预算；发布测试覆盖遗漏音频、缺分包和篡改文件等实际风险。
4. 按原则执行 `npm test`、`npm run typecheck`、开发构建（独立临时输出）、`npm run build:production` 和发布校验；保留 pure 独立进程回归，避免总入口提前注册掩盖问题。

### 12.2 浏览器与人工试听

| 场景 | 验收要求 |
| --- | --- |
| 新会话与首次手势 | 无手势无声；已预热时正常解锁；准备不足/被拒绝时动作仍即时执行，有明确重试入口 |
| 普通交互 | 八抽屉独立开合/反向、三灯独立切换、门双面开合/受阻/恢复/到位、信件打开/按钮返回/ESC 均正确；无效点击不响 |
| 快速操作 | 连续反向、多个物件交错操作；无无限叠加、错误门扣或到位声，试听高并发无削波/刺耳突变 |
| 模态与生命周期 | 设置、Inspector、第一人称锁定/拒绝、信件横竖屏、切换视角、隐藏/失焦/恢复、重复初始化/销毁均无声音残留或旧声补播 |
| 静音与偏好 | 0 音量/静音、取消静音、刷新保存、无 localStorage、损坏数据、键盘操作与详情静音入口可用 |
| 空间阶段 | 第一人称左右、前后/转头、接近/远离；环绕预设仍可听；信件展示不移动房间 listener |
| 弱网/缺失文件 | 冷缓存/弱网/音频404/解码失败；页面可用不依赖音频 ready，重试有上限，无未处理 Promise 错误 |
| 独立部署 | 只托管最终 dist，验证子路径、MIME、所有音频/来源/许可/动态分包的 HTTP 可达性与摘要，无运行请求依赖开发 public |

桌面至少验 Chrome、Firefox、Safari；移动如作为交付支持范围，至少验 iOS Safari 与 Android Chrome 的真实设备。记录浏览器/系统版本、声音设备、系统静音、缓存和网络条件；未具备的设备明确列为未验证，不写成已兼容。

对已解锁、已预热的音效记录“动作接受/运动开始 → 调度播放”时间，目标在一次应用更新内，约 ≤ 50 ms；门原本受阻到开始移动的等待单列。另测冷准备与解锁时间。该指标不含操作系统、蓝牙和扬声器的输出延迟，若声明用户实际听到的延迟，需回录/实测。保存音频播放记录和人工试听结论；截图、网络成功及 `play` 调用成功都不能证明听感合格。

回归现有画面、移动碰撞、拖动缩放、设置、Inspector 和所有交互，保存实际请求、模块图、字节与警告。遵守既有性能测量边界：本方案不承诺 FPS 或加载速度收益，也不恢复已暂停的 FPS 专项测试。

## 13. 风险与后续扩展

| 风险 | 控制方式 |
| --- | --- |
| 多平台录音音色/响度不统一 | 同系列优先、离线剪辑与场景试听；不只比较峰值 |
| Audio V2 引入额外模块或动态分包遗漏 | A 阶段先做生产验证，保持精确导入与完整发布 |
| 首次操作过早、系统静音或浏览器限制 | 区分准备与解锁、明确可重试、无声降级；记录实际支持边界 |
| 动画反向/受阻/详情暂停造成音画不同步 | 真实状态事件、实体句柄及动作代次，取消过期声音 |

### 15.1 实际选择与调整

- 从 laleksic 的 [Various Sound Effects](https://opengameart.org/content/various-sound-effects) 选择八个 CC0 自录原件，制作十二个短音效，覆盖木抽屉运动/到位、门轴/门扣、开关、纸张。选择同包录音以减少音色差异，并避免账号下载依赖；未使用 AI、合成声或未核实许可素材。原件、来源和 SHA256 保存在 `assets/audio-source/study/`。
- 所有交付片段采用 48 kHz、单声道、PCM 16-bit WAV，合计 **287,568 字节 / 0.274 MiB**，P0 为 **126,984 字节**，文件 PCM 解码数据合计 **574,080 字节 / 0.547 MiB**。短声无损文件已经满足目标，因此替代初始 MP3 候选，不额外引入编码器、格式备份或解码库。处理脚本和来源记录均可重现。
- `RoomAudio` 管理加载/失败/手势/静音和实体句柄，独立懒加载 `RoomAudioBackend` 使用 Babylon Audio V2 精确入口。每片段两个已准备的声音对象共享一个缓冲，二十四个对象共用十二个缓冲；全局最多六个活动实例。音频准备不加入场景 ready 的等待条件。
- 抽屉与门按真实运动状态发事件，反向、受阻、详情暂停、隐藏/失焦会取消旧声；门扣只在真正关闭到位时响。二维环绕/详情反馈和第一人称空间声均已接入；声源和 listener 一起转换坐标，避免左右倒置。
- 工具栏和详情对话框均可静音；设置包含音量、试听、恢复默认和来源页，偏好容错保存。自动重试每项最多一次；用户手动重试开启新一轮有限尝试，只重试失败项。真实前台手势也能恢复失焦状态，避免依赖遗漏的 focus 通知。
- 新增音频专项校验，并纳入原有白名单、来源说明与生产发布校验。既有十八个运行素材摘要全部保持不变，未改全局预算或放宽依赖检查。
