## 1. 背景与现状

用户要求一天每隔 3 小时设置一个时间节点，明确太阳角度、早晚低角度日光、正午南向高光和夜间柔和月光，并在页面左下角增加可展开收起的时间切换菜单。本轮只设计方案。

当前光照并非由一个太阳统一驱动：

- [CoastalSky](../../src/examples/CoastalSky.ts)固定太阳向量为 `(0.55, 0.78, 0.30)`；依现有坐标约为东南偏东、仰角 51.2°。天空颜色在 [RoomExterior](../../src/examples/RoomExterior.ts)构造时写入球体顶点色，之后不会随时间改变。
- 室外方向光强度为 `3.8`，只影响室外 PBR 网格及显式加入的小电驴；使用一张 `1024²` 局部阴影图，随近宅、途中和塔区锚点重定位。重定位仍引用固定太阳向量。
- [CoastalOcean](../../src/examples/CoastalOcean.ts)有独立的太阳方向、颜色、天空反射、水体底色、泡沫和海雾；太阳颜色未与方向光强度关联，直接调暗灯光不会让海面正确入夜。
- [CoastalMaterials](../../src/examples/CoastalMaterials.ts)使用含固定太阳亮斑的室外 HDR，材质环境强度为 `3.8`；室内另用 `study-interior.hdr`，场景 IBL 强度为 `0.35`。[RoomLighting](../../src/examples/RoomLighting.ts)还有固定窗边聚光灯、半球补光及可独立开关的人工灯。
- 页面左下已有视角按钮和帮助提示，右下已有小地图；[页面](../../public/index.html)与[控制绑定](../../src/components/BasicExamples.ts)需要共同处理布局和输入。设置、地图、物品查看、指针锁定及驾驶均有暂停/恢复行为。

因此，时间变化应统一控制主光、环境、天空、水面和窗光，同时保留人工灯的用户状态。

## 2. 目标与范围

1. 设置 `00:00、03:00、06:00、09:00、12:00、15:00、18:00、21:00` 八个节点，24:00 回到次日 00:00，不增加重复节点。
2. 首次进入默认 `12:00 正午`，手动切换后保持选定时间；同一场景切换视角、步行、骑行、地图和回家均不重置时间。首版不持久化时间，刷新后恢复默认，避免上次夜景导致初次画面过暗。
3. 手动切换是主要入口；菜单另提供默认关闭的“自动流转”。开启后一个昼夜为现实 24 分钟，每 3 小时约 3 分钟，节点之间连续变化。
4. 保持天气为晴到轻霭的同一种状态。采用适合观看的北半球示意日轨和明亮月夜，不绑定经纬度、日期、时区、真实月相或天文历算；场景时间独立于电脑时间。
5. 保留房间灯、门窗、镜面、碰撞、地图、物品查看和小电驴功能。时间本身不自动开关房间灯，也不顺带新增路灯、车灯、灯塔旋转光束、星空贴图或天气系统；灯塔设备照明仍由原方案独立维护。

以下角度是设计值；颜色、相对亮度与过渡时间是实施起点，需在实际画面中校准，尚无运行验收结论。

## 3. 方位定义与八个节点

### 3.1 统一坐标

沿用 [HouseLayout](../../src/examples/HouseLayout.ts)：世界 `+X` 为东、`+Y` 为上、`+Z` 为南；平面图的南为 `+y`，北为 `-y`。方位角从正北顺时针计：北 0°、东 90°、南 180°、西 270°。高度角从地平线向上计，负值代表天体在地平线下。

表中“来自”指观察者指向光源的方向，不能直接作为 Babylon 灯光传播方向。若方位角为 A、高度角为 h，则指向天体的单位向量 L 为 `(cos(h)·sin(A), sin(h), -cos(h)·cos(A))`，运算前转弧度；方向光的 `direction = -L`。正午 L 约为 `(0, 0.9063, 0.4226)`，光线朝下、朝北传播，水平地面投影向北。方向光与位置的关系参考 [Babylon 灯光文档](https://doc.babylonjs.com/features/featuresDeepDive/lights/lights_introduction/)。

## 4. 时间推进与切换规则

- **手动选点**：选择后用约 1.2 秒缓入缓出到目标，不依次播放中间所有时间。昼间到昼间可以插值方向、强度与天空；日月光切换时先降低原主光，在强度接近零时换方向，再渐入目标主光，避免月亮横扫天空。天空、环境与海面同时过渡。
- **连续点选**：从当下已显示的状态重新过渡到最新目标，取消旧过渡；不排队、不回跳到上一个节点。切换时菜单保持展开，方便比较，当前目标有选中标记和短暂“切换中”状态。
- **自动流转**：内部以 `[0,24)` 连续小时推进，相邻节点之间插值。方位角先展开为连续角，跨 360°/0°不倒转；高度、线性颜色、环境强度连续插值，21:00→次日 00:00 与其他段相同。八个按钮代表关键帧，自动模式显示实时 `HH:mm`，当前三小时段采用起点高亮。
- **日月交接**：太阳与月亮各自按表插值，高度不大于 0°时其直接光和光盘为零，0°～5°平滑渐入。根据上述轨迹，日落后、月升前与月落后、日出前有短暂暮光/晨光，仅保留天空与环境照明；此时两种直接光都为零，不硬造双主光。主方向光在两者均暗时切换身份。
- **操作优先**：自动模式下手动选点即暂停自动流转并转到所选节点；重新开启从当前显示时刻继续。关闭自动时停在当前连续时刻，无需强制吸附节点。
- **暂停恢复**：打开时间菜单、设置、地图、物品详情或 Inspector，失焦、页面隐藏时暂停自动时钟；关闭后按此前自动开关恢复。手动切换的短过渡允许在时间菜单内完成。恢复首帧不补算后台经过时间，长帧 delta 限制为 0.1 秒，场景销毁清理观察者。
- **减少动态效果**：遵守 `prefers-reduced-motion` 时手动改为短淡化，不播放方向扫动，自动模式仍由用户主动开启；切换不触发相机移动。

## 5. 光照联动与技术取舍

### 5.1 一个时间状态统一分发

拟新增集中时间控制模块，维护节点、当前小时、目标、自动状态和已求值的视觉参数，场景负责向各系统分发。节点只存一份，菜单文字和自动插值共用；各模块不再保留独立的固定太阳常量。这里的模块职责均为待实施设计：

| 接入位置 | 计划职责 |
| --- | --- |
| 新的时间配置 / 控制模块 | 八节点、角度换算、日月有效性、插值、前后台时钟与通知 |
| `Room.ts` | 生命周期、共享暂停原因、当前时段接口、异步模型就绪后补应用当前状态 |
| `RoomExterior.ts` / `CoastalSky.ts` | 当前主光方向/颜色/强度、主光阴影位置、动态天空与日/月光盘 |
| `CoastalMaterials.ts` | 室外 IBL 亮度和环境色调；所有后建材质同步，包括灯塔与车体 |
| `RoomLighting.ts` | 分开管理自然窗光和人工灯，按窗口朝向及当前主光重算自然光 |

| `RoomRuntime.ts` / `RoomShaders.ts` | 仅在确有新增运行能力时补精确注册与启动着色器 |

### 5.2 主光、室内窗光与人工灯

1. 室外复用现有方向光、影响白名单及局部阴影图。白天是太阳，夜间是月亮；不全局增加第二盏方向光，不改变室外材质当前只接收一个直接光源的约束。
2. 室内继续用现有窗口聚光代理，保留房间隔离、窗框/帘和家具投影。以窗口外法线 N 与指向有效天体的 L 的 `max(0, N·L)` 决定直接光权重，检查窗口真实开口；背光窗只保留间接天空照明。代理光从开口照入，方向与天体一致，不能把灯转向后仍从实墙内发光。窄门、其他房间和无窗卫浴不凭空获得直射月光。
3. 月光下窗代理使用月光色和弱强度；晨昏不能所有房间维持固定白色窗光。半球光、场景 ambientColor 与室内材质 IBL 同步缩减，保存每个材质的白昼基准并计算目标，避免累乘和覆盖既有差异强度。室内外材质必须明确归属；共享材质只应用一次。
4. 保留台灯、落地灯、厨卫灯等原来的开关、暖色及亮度；白天手动关灯，切到夜晚仍关闭。若关灯后局部较暗，以合理的窗外/环境弱光保证通行，不通过全局曝光把夜间抬成白天。
5. ACES 和曝光先保持现有 `1.12`；优先校准光照比例。镜面继续反射实际场景，不对镜面反射目标乘一遍环境色，避免真实灯光与夜色重复处理。不改发光灯罩、灯具 emissive 和交互提示颜色来模拟昼夜。

### 5.3 天空、环境贴图与海面

- **动态天空**：保留现有天空球几何，改为统一参数驱动的解析天空材质；通过 uniform 更新渐变、朝向暖色与柔和光盘，不每帧重建球体、网格或大段顶点色。天空与海面各自产生线性颜色，仅由现有后期执行一次色调映射；保留裁切和镜面相机支持。
- **室外 IBL**：现有 HDR 内含固定太阳亮斑，单纯降低强度会留下错误方位的高光。计划由既有确定性生成流程产出一张无太阳亮斑、低频中性天空 HDR，替换当前室外环境用途，沿用 `128` 面预过滤。用各材质原环境强度乘时段系数，并在原 `reflectionColor` 上乘时段环境色，连续改变漫反射环境与反射色；主光承担实体方向性，天空/海面承担可见光盘和光带。无需八套 HDR、实时环境探针或新增全局照明管线。
- **近似边界**：单一中性环境图不能复现晨昏天空在各方向的完整彩色反射；首版接受这一低频近似，但不得保留固定太阳高光。用日夜全景、窗边木材/金属、灯塔和车体近景核验是否可接受；若不足，在实施记录中另比较方案和预算，不把近似写成物理准确。Babylon IBL 的预过滤与漫反射数据说明见[官方 HDR 文档](https://doc.babylonjs.com/features/featuresDeepDive/materials/using/HDREnvironment/)；本地 9.30.0 的 `pbrBlockReflection` 也已核对 `reflectionColor` 对环境辐射与辐照度的共同缩放。
- **室内 IBL**：沿用现有室内 HDR 作为室内低频反射近似，通过各室内材质的环境强度与自然补光时段系数减弱夜间贡献；保留导入家具的材质基准，不改全局 IBL。排除真实镜面反射目标、物品查看预览和自发光/不受光材质。HDR 中若有夜间仍醒目的固定亮斑，列为实施画质问题处理，不能以灯关了就算完成夜景。
- **海面**：把现有 `sunDirection/sunColor` 的语义推广为当前有效天体及其辐射强度，夜间为低强度月光；太阳下山后日光高光必须归零。天空反射读取同一时段参数；水体底色与泡沫按天空照明同步变暗，海雾向当前地平线色融合。不能只改高光而保留白昼青蓝水底和亮白泡沫，海天接缝仍需隐藏。
- **资源归档**：中性 HDR 仍由原创解析生成，记录参数、生成工具、原/新文件摘要、处理步骤和替代关系；同步来源文件、资源白名单与相关测试，不引用新外部素材，不覆盖历史稳定基线。

### 5.4 阴影更新与低角度风险

- 时间改变时同步更新方向光位置与方向：位置由当前局部锚点加 `L × 距离` 得到。锚点切换必须使用当前 L，不能又恢复固定下午方向；现有 6 米滞回及房屋/途中/塔区划分保留。
- 灯光投影矩阵和对应阴影图应在同一更新批次变化，禁止方向每帧变而沿用旧方向阴影。手动 1.2 秒过渡期间仅刷新相关自然光阴影，人工灯静态缓存保留；目标稳定后恢复按需缓存。
- 自动模式初定主光方向/自然光阴影以不高于 10 Hz 的同批参数更新，天空/海面颜色可逐帧插值；停止后补一次最终精确状态。实际若出现影子步进，再按连续帧证据调整频率，不能直接承诺性能收益。
- 晨昏 5° 会产生长影，20 米灯塔在平地上理论投影约 229 米，超出现有局部图范围。首版验收近玩家局部阴影与接触关系，远处长影允许因局部覆盖缺失；不能直接把整条步道纳入一张低精度阴影图。围绕当前可见接收区沿光向扩展投射物检查，按角度校准深度范围和偏移，重点排查塔身截影、墙面条带、漂浮与穿墙光。
- 夜间保持 PCF 基础和较低主光反差，优先用现有过滤控制柔和感；室内窗光可沿用已存在的接触硬化设置。是否增加室外 PCSS 或改变分辨率需另有画质/成本证据，遵守[官方阴影文档](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows/)的投影与精度约束。

## 6. 左下角时间菜单

### 6.1 内容与视觉

收起时显示一枚常驻按钮，例如“☀ 12:00 正午 ▴”或“☾ 00:00 午夜 ▴”。图标为内联矢量/字符并附文字，不增加图片或图标包；实际实现应避免不同平台 emoji 色彩影响识别。按钮与现有米白/木褐界面统一，夜间仍有固定可读对比度。

展开面板包含标题“场景时间”、右上角收起按钮、以下两列四行节点及底部“自动流转”开关；开启时显示“一天约 24 分钟”和当前时间。不向普通用户显示角度、引擎参数或资源状态。

| 左列 | 右列 |
| --- | --- |
| 00:00 午夜 | 03:00 后夜 |
| 06:00 清晨 | 09:00 上午 |
| 12:00 正午 | 15:00 午后 |
| 18:00 黄昏 | 21:00 入夜 |

节点按钮至少 44 像素高，选中态使用底色、描边和标记共同表示。保留面板便于连续比较；点击外部或 Esc 收起，收起不会取消选定时间。

### 6.2 布局和已有界面

- 桌面左边距沿用 `32px`。将已有视角栏与时间菜单放在同一左下布局容器：视角栏在下，时间按钮在上，间距 `12px`，面板从时间按钮向上展开。按钮距底部由视角栏实际高度确定，不能硬编码后与换行视角栏重叠；帮助文字移到该容器上方并随高度避让。
- 窄屏边距 `12px` 加安全区，收起按钮保持左下、底部视角栏上方，与右侧小地图留出间隔。展开面板宽不超过 `288px` 且不超视口；当可用宽高不足时改为窄屏底部面板，临时隐藏视角栏、小地图和帮助提示，保留关闭按钮，关闭后恢复。内部列表可滚动，面板最大高度不超过可用视口的 60%，不覆盖页面关闭入口。
- 时间菜单与设置互斥展开；地图、物品查看及 Inspector 打开时收起并隐藏时间入口，关闭后恢复入口。UI 显隐不改变时间、视角、门灯或驾驶状态。

### 6.3 输入与无障碍

- 第一人称增加 `T` 展开/收起时间菜单，解决指针锁定时无法直接点击角落按钮的问题；提示中写“按 T 调整时间”。仅在非输入控件、无组合键且非重复按键时响应。
- 打开前先登记时间菜单状态，再暂停移动/驾驶并释放指针锁定，避免锁定退出事件把玩家切回上一视角。清空 WASD/跳跃/车油门等输入，保留人物坐标、朝向和骑乘关系。
- 关闭后回到原视角和姿态；通过按钮、T、Esc 收起均先保留鼠标可用，再由“点击场景继续”这一明确手势恢复指针锁定。无需自动下车，不因浏览器拒绝锁定而丢失选定时间。[Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)要求用户手势的情形已纳入设计。
- 时间菜单中的空格、方向键和滚轮只操作界面，不触发跳跃、骑行、相机缩放或场景拾取；Esc 只关闭当前面板，不能同时退出第一人称。设置、地图、详情和 Inspector 的暂停应由共享原因集合管理，关闭一处不能错误恢复另一处仍占用的控制。
- 入口使用 `aria-expanded/aria-controls`，节点采用单选组语义，支持 Tab、方向键、Enter/空格；焦点进入当前选项，关闭回到入口。选定结果用简短状态播报，自动模式不每分钟播报。触控只需点按，无悬停依赖。

## 8. 预算、风险与交付边界

- 沿用目标 GLB 合计 ≤4.25 MiB、运行素材 ≤16 MiB、静态及实际首屏 JS 各 ≤3 MiB、完整发布 ≤41 MiB。实际首屏包含所有必需异步 JS；完整发布包含全部调试分包、清单和说明。中性 HDR、解析天空与时间菜单的净增字节在实施时实测，本轮不抬阈值。
- 继续使用 pure/精确导入、显式注册、资源白名单和独立托管。计划不增加相机、方向光数量或室外持久阴影图数量；替换 HDR 不等于零内存成本，必须核对销毁、材质共享和实际纹理数。
- 主要成本为自然光阴影动态刷新；先保留人工灯缓存和局部覆盖，记录更新频率与绘制变化。旧方案中暂停的 FPS、GPU/加载耗时实验继续暂停；不能凭字节、截图或 10 Hz 设计声称帧率/加载变快。
- 主要画质风险为低角度长影、室内 HDR 固定亮斑、不同来源材质环境强度、海面自定义着色器残留白昼底色，以及夜间没有新增道路照明时的可见度。按上述视角与失败路径处理，未通过项目保持待办。
- 本方案针对现代海岸住宅，不改变唐宅 `SET-008` 的季节/时段或油灯设定；未来复用时间控制能力时，应另按唐宅影响矩阵复查，不能直接套用此处月相、人工灯与时段参数。
