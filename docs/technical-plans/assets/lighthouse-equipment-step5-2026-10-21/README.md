## 方法和边界

- 仅独立托管最终`dist`（本机8245端口），Playwright临时独立上下文，无用户配置/账户；Chrome155.0.8059.85/.86（各记录保留实际版本）、匹配的WebKit27.2 revision2370、Playwright Core1.64.1、Node24.21.0、Babylon9.30.0、TypeScript5.9.3、webpack5.111.1。
- 原0.1秒凭据连续调用真实生产调度，八个1440秒参考周期检查日程/能量/维护/存档；实际UI通过原生指针锁定/鼠标/键盘。局部设备测试可设合法落脚机位；连续journey只有住宅初始机位，之后不修正位置或高度。
- 参考循环加速执行，不是现实运行192分钟或物理手机实验；GPU显隐/静态截图和字节不构成FPS、加载速度或真实射程结论。未重验Firefox/Safari/物理设备与主观听感。
- 保留历史脚本，不覆盖旧证据。`suite-adapter.cjs`适配当前49交互标识、8车辆网格、自动初态和拥有的保存监听；早期已执行的兼容适配器原件冻结在`adapters/initial-suites.cjs`，汇总逐项记录实际执行摘要。旧脚本的baseline字段是来源标签，实际输入包由本次汇总及清单绑定。

## 复跑

先按日志命令完成工程构建，仅托管dist，然后设置`PLAYWRIGHT_PACKAGE`到可用客户端；WebKit需与该客户端的`browsers.json`匹配。可用`PLAYWRIGHT_BROWSERS_PATH`指定临时浏览器目录。本轮匹配运行时下载至`/private/tmp/lighthouse-step5-browsers`，没有加入项目依赖或发布。运行`node run-checks.cjs`（可跟套件名），最后运行`node verify-evidence.cjs`。

完整复跑从模型生成合法低电档开始，再做现场恢复；`run-checks.cjs`逐套串行、包摘要变化即拒绝拼接，矩阵用新匹配WebKit默认launcher。[Playwright官方启动脚本](https://github.com/microsoft/playwright/blob/main/browser_patches/webkit/pw_run.sh)规定macOS使用其同目录框架；本次先前2336旧浏览器与1.64.1不匹配的诊断独立保留，最终96项使用2370。
