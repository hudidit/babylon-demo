# 开门重复发声修复验收（2026-10-25）

代码基线`d8b334b`；方案与取舍见[声音方案第18节](../../2026-10-24-game-soundscape-expansion.md#18-开门音效重复修复2026-10-25)。本轮仅改变门运动片段的循环策略，木门/金属门/推拉门各两个变化单次播放，保留原交互状态机、素材字节与其他持续声音。

## 失败复现与修复结果

[基线浏览器记录](before-browser.json)是修改运行目录、生成器和资源校验前，使用相同专项脚本在原生产包取得的预期失败结果。六个变化各只调用一次`AudioVoice.play()`，但底层`AudioBufferSourceNode.loop=true`，片段在动作端点前未结束，脚本因此失败。木门0.4/0.58秒、金属0.28秒、轨道0.44秒，均短于0.7秒动画；单查播放调用次数会漏掉内部重播。新增单元回归也先在旧配置下失败。

[修复后浏览器记录](browser.json)：Chrome 155，三类门各两个变化共六次原生打开及六次关闭。每段运动只发一个播放调用、启动一个原生音源，`loop=false`，在动画端点前自然结束，余下运动帧无补播。打开无门扣，关闭每次各一次门扣；主输出非零且峰值<1，动作结束后0活动声部、输出归零。正常页面/控制台错误0、浏览器告警0；未打开Inspector，其既有CSS提醒不在此次范围。生产构建仍有既有3条体积建议。

[专项脚本](../../../../tools/check-door-audio.cjs)只托管未修改的生产`dist`；debugger捕获既有Room，原生点击配附近轨道相机站位夹具，原交互每50ms推进0.05秒。包装`AudioVoice.play()`及原生音源`start/ended`仅作观察，没有修改音高、加速音频时钟或定时器。主输出旁路在总增益后采样。没有人工耳机/扬声器试听，不将原生输出检查写成音色、接缝或整体混音验收，也未采样FPS/加载时长。

## 工程检查与复现

[463测试](tests.log)、[类型检查](typecheck.log)、[开发构建](development.log)、[生产及发布校验](production.log)通过。新增六变化非循环/自然结束回归与错误循环清单拒绝检查；既有防夹、反向、自动关闭、暂停、擦拭/持续声音去重测试保持通过。[重建记录](reproduction.json)确认14个动作WAV摘要与基线完全一致、再次重建一致；交叉淡化处理与播放循环策略分开维护。

```sh
python3 tools/prepare-action-audio.py
npm test
npm run typecheck
npm run build
npm run build:production
node tools/check-door-audio.cjs
```

生成器使用本地归档原料和macOS AudioToolbox；浏览器脚本使用本机Chrome及Playwright Core，可由`PLAYWRIGHT_PACKAGE`指定包位置，结束后关闭浏览器和服务器。`AUDIO_GAME_DIST`与`AUDIO_CHECK_OUTPUT`可分别指定生产包和证据目录。历史基线必须配当时的资源校验运行，当前校验已会拒绝旧循环清单。

## 容量与交付

[前后容量](capacity.json)与[最终完整发布清单](release-manifest.json)：570个文件在`/`和`/audio-lab/`逐项HTTP 200、字节/SHA256一致，含全部动态分包、来源、许可及清单自身。实际首屏含必需异步JS，3,171,826 B保持；静态JS2,952,730 B、运行素材17,960,471 B、模型4,332,840 B、全部音频2,070,809 B与PCM16,698,240 B保持。四个循环字段从`true`改为`false`使来源清单增加4 B，完整发布44,905,425→44,905,429 B，所有原预算通过。
