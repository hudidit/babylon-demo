## 交付范围

[LighthouseStory.ts](../../../../src/examples/LighthouseStory.ts)只接收已提交的场景时间、当前设备上下文及带来源/原事件编号的工作事实，实现11任务、章节、报告与可回读消息、接送取消/留站、旧呼号来源核对及主动结束。不会写设备、Wh、天气或维护期限。

[LighthouseStorySave.ts](../../../../src/examples/LighthouseStorySave.ts)提供新故事工厂、只读上下文映射、严格完整封套及`babylon-lighthouse-story-v1`独立槽。封套内设备继续使用原版本2格式；正常探索的`babylon-lighthouse-duty-v1`及演练的`babylon-lighthouse-exercise-v2`不读取、不复制、不迁移、不覆盖。故事只能从独立第1日12:00开始，恢复核对连续接受小时、设备日序/钟面、当前问题/修订和导航。

本步模块尚未从运行入口导入。接班信/玩家模式菜单/场景订阅留步骤二；故事天气、专用问题安排、等待/生活留步骤三；尾声交互/结尾展示留步骤四；完整实际游玩留步骤五。全篇事件夹具通过不能写成当前玩家已能玩完整剧情。

## 接入与复现

纯模型输入必须来自已提交设备事件，同一来源按原编号递增转发；`inspection`、`maintenance`、`discovery`、`comparison`分别保留游标，重复/已过期编号不重新生效。`comparison`编号留给后续现场读数对照适配器；它不是独立能量模型。事实缓存有界，任务/报告完成快照另存；当前工作不能使用旧修订快照。`synchronize`只接受共享时钟已接受的累计小时，不负责结算等待或手动跳时。

`submitReport`只记录有证据支持的报告；`deliverReply`是独立的已收到回复事件，不隐含读信。`readMessage`单独推进阅读；`requestSourceCheck`与正式核对回复也分开。结尾选择与已看过分别保存。`fromState`及完整封套解码只验证和重建，不推进时钟、发信或重新抽数；未完成设备动作只在保存副本中取消，下一实际场景更新再处理已满足条件的后续消息。

复现：运行`npm test`、`npm run typecheck`、`npm run build`、`npm run build:production`，随后设置`PLAYWRIGHT_PACKAGE`为已安装的Playwright Core路径，执行`node docs/technical-plans/assets/lighthouse-story-step1-2026-10-22/check-release.cjs`。本次Core路径`/private/tmp/dsh-playwright/node_modules/playwright-core`，未加入项目依赖。脚本临时监听本机端口，仅托管dist，结束自动关闭；首次沙箱禁止本机监听的诊断见[记录](diagnostics/server-sandbox.log)，批准本机验收后成功，与页面运行错误无关。
