## 1. 背景与现状

用户希望房屋坐落在海边悬崖上方的平地，阳台正对大海，外景具有更真实的空间、材质和光照。

当前实现已核对：

- [RoomExterior](../../src/examples/RoomExterior.ts)为全屋提供共享森林，真实近中景树木配合有限半径摄影远景；室外材质关闭实时光照，主要依靠照片和顶点明暗。窗洞和玻璃已通透，应继续复用。
- [HouseLayout](../../src/examples/HouseLayout.ts)规定1米=5世界单位，室内地面`floorY=-5`；阳台位于平面南侧`y=10.8～12.3m`，向海方向可直接使用世界`+Z`，无需旋转房屋或改变地图。
- [Room](../../src/examples/Room.ts)的阳台预设位于屋外向北看屋内；要体现面海，本次实施需同步调整预设。环绕视图目前裁掉近侧外景，全屋鸟瞰隐藏外景；第一人称保留完整室外。
- 室内使用`study-interior.hdr`、分房窗光、缓存阴影、SSAO和ACES。海面若直接沿用室内环境贴图，会产生错误的房间倒影；全局更换HDR又会改变现有室内外观。
- [最近生产验收](assets/scene-reuse-2026-10-17/README.md)记录运行素材15.70MiB、实际首屏JS2.62MiB、完整发布40.78MiB。预算余量很小，外景应作为森林的替换。

## 2. 目标与范围

推荐组合：**连续三维崖顶/崖壁 + 实拍岩石PBR材质 + 轻量动态海面 + 一致的海岸天空与日光**。照片材质负责表面细节，几何轮廓、遮挡、移动视差及反光共同建立真实感。

以阳台面海为主构图，同时保证侧窗、后窗看到同一世界中的不同方向。房屋背面是内陆草坡，侧面可见海岸转折；无需让每扇窗都看到海。

初次交付为技术方案，阶段A完成空间灰盒，B完成PBR/草石/独立天空日光，C完成动态波浪、天空反射/高光、海雾及泡沫。阶段D已完成工程、完整生产交付、Chrome/WebKit画面与功能回归及海岸独立稳定基线；Firefox启动、Safari自动化与物理移动设备尚受环境限制，未将其填为通过。八房及后续南向次卧窗、半透明全景、跳跃和窗框修复保留。户外自由行走、昼夜天气、海浪物理和新增海浪声音留待单独需求；原暂停的FPS/加载耗时实验继续暂停。

## 3. 场地布局与视觉目标

以下尺寸是美术灰盒的起点，不是建筑或地质安全结论。以真实相机画面调整后记录最终参数。

| 要素 | 推荐初值与目的 |
| --- | --- |
| 房屋与坐标 | 房屋和室内地面保持原位置；外部平台包住整栋房屋，地面略低于室内，补齐可见基座，避免房屋悬空或地面穿入地板 |
| 崖顶平台 | 约50～70m宽，向房后延伸；房旁保持平整，外围渐变为低缓起伏和裸岩，避免一整块水平矩形草坪 |
| 阳台至崖缘 | 初值5m，候选4～6m；保留低矮草地和少量裸岩，栏杆外仍有陆地承托，主视线保持开阔 |
| 崖顶至海面 | 初值28m，候选24～30m；降低海面和崖脚，使用`floorY-高度×5`，保持房内坐标、眼高和碰撞基线 |
| 岸线形状 | 不对称曲线：一侧有稍向海伸出的岩岬，另一侧退后；从阳台能看到侧方岩壁和崖脚，避免整条垂直崖壁完全藏在脚下 |
| 主视角 | 阳台内侧以约1.6m眼高朝南看海，近处栏杆/草地、侧方岩岬、中远海面和天空同时形成层次；配合客厅望向阳台的第二构图 |
| 时段与配色 | 晴朗午后，太阳从海侧斜向照入；低饱和灰褐岩、黄绿草、蓝灰海面和轻微暖光，海天交界有薄雾，避免夸张橙色滤镜 |

海面应占阳台主要视野，侧方岩岬负责表达悬崖高度。先用无贴图灰盒检查站姿、低头、左右转头和横竖屏；空间关系达标后再投入精细材质。

## 4. 方案及取舍

### 4.1 三维地形承担轮廓和尺度

- 用固定种子的可复现地形生成器，连续生成崖顶、土层断面、分层崖壁、崖脚和向海延伸的海床/岸线数据。崖壁使用有厚度的多层截面网格，可形成台阶、裂缝和局部凹凸；单一高度场只承担崖顶/缓坡，不能直接代表垂直或悬挑岩壁。
- 大尺度岩体与层理决定自然形状，小尺度坑洼交给材质；按层理方向布置少量不同形态的岩块，避免平均撒石、规则尖角和均匀随机噪声。
- 崖缘、主要岩岬和近景石块是真实几何，移动相机时有真实视差。远方仅布置少量简化岬角，靠距离和海雾降低细节。
- 草地使用坡度/高度/手工控制区混合，配少量有体积的草簇、低灌木。基础地表承担覆盖，大量透明草片的叠绘不作为首选。
- 平台到崖壁使用共同边界和连续法线/材质过渡；地形封闭可见侧面，海面伸入崖脚下方，消除裂隙、穿帮和漏背景。房屋基座、地面接触和崖脚湿润带均需近景验收。

### 4.2 实拍材质兼顾近景与重复控制

- 优先试用[Poly Haven Seaside Rock](https://polyhaven.com/a/seaside_rock)的海岸岩石PBR；[Rock Face 01](https://polyhaven.com/a/rock_face_01)可作为岩体层理/几何参考。候选不等于已采用，实施时按实际镜头和预算定稿；这些资产按[上游许可](https://polyhaven.com/license)为CC0，仍需保存作者、原件摘要与加工记录。
- 主岩石采用约2K颜色、1K法线/ARM起步，真实米制纹理尺度；较大裂缝和岩层起伏由几何提供。禁止将整幅含固定视角的悬崖照片铺到一面墙上作为可近看的崖壁。
- 优先为崖壁生成沿层理展开的UV，统一色调与纹理密度；用低频宏观颜色、少量固定变体和粗糙度变化打散重复。若陡峭转折仍明显拉伸，再评估局部三向投射插件，并核对法线重定向、接缝、采样成本和分包影响，不直接引入整套节点编辑器。
- 岩面干湿、土层与植被按高度/坡向/岸线分布。颜色按sRGB，法线/ARM按线性数据处理，核对OpenGL法线方向和R=AO/G=粗糙度/B=金属度；石头、土和水使用非金属参数。

### 4.3 海面随视角和时间变化

- 使用固定世界坐标的分区海面网格，近海较密、远海逐步稀疏；少量解析波（Gerstner波或同等实现）提供缓慢起伏，叠加不同尺度/方向的移动法线，产生连续的波面与反光。
- 水面着色包含视角相关菲涅耳、与天空方向一致的反射、太阳高光、粗糙度、近岸至远海颜色变化及距离雾化。远处逐步过滤细浪法线和高光，检查闪烁与摩尔纹。所有颜色在线性空间合成，沿用现有ACES处理，避免重复色调映射。
- 天空可用轻量渐变与稀疏云层，离线由同一套天空参数生成小尺寸预过滤环境贴图，供海水/室外PBR共享。固定下午时段下无需每帧重建天空反射。
- 使用共享岸线距离/海床高度数据控制窄带泡沫和颜色过渡，配合缓慢变化的破碎遮罩。第一版可用静态岸线近似，记录其不跟随每个浪峰的限制；泡沫不能是固定白边，海面不能像镜子或匀速平移的照片。
- 根据28m高处看海的主要用途，首选自定义轻量海面着色器。天空环境反射不包含准确的本地崖壁/房屋实时倒影，灰盒阶段先检查这些倒影是否在构图中重要。确有明显缺失时，才评估一个仅渲染必要外景、可见时刷新的低分辨率平面反射目标，并重新验收预算及GPU成本。
- Babylon的[Water Material](https://doc.babylonjs.com/toolsAndResources/assetLibraries/materialsLibrary/waterMat)支持通过渲染列表实现反射/折射，本地9.30.0实现包含两个RTT；作为局部倒影需求的备选。首版不引入FFT海洋或全场景每帧反射/折射，投入优先用于主视角可见的轮廓、水面高光和岸线。
- 有限海面在最大镜头范围前逐渐并入海天雾带，海面网格边缘不得露出；检查相机`maxZ`、深度精度及现有SSAO的距离范围，不以无限放大模型解决远景。

### 4.4 室外日光与室内衔接

- 为室外PBR配置限定网格作用范围的日光和海岸环境贴图；以材质级`reflectionTexture`覆盖环境，保留室内HDR和既有镜面。相关能力见[Babylon PBR文档](https://doc.babylonjs.com/features/featuresDeepDive/materials/using/masterPBR/)，并已核对本地9.30.0的`PBRMaterial`类型定义。
- 天空太阳、海面高光、岩壁亮暗和阳台投影读取同一太阳参数。只校准阳台及必要临海窗补光，使其与室外方向/色温衔接；背海窗以天空散射补光理解和调校。避免无评估地重做全屋灯光。
- 外景先评估一个局部1024²缓存阴影，覆盖房屋基座/平台、近景岩体和植被接触；远海不纳入阴影图。房屋/栏杆是否参与外部投影使用独立名单，不能把全屋加入新的每帧阴影。
- 海雾只影响室外材质，室内保持清晰。玻璃继续弱反射、高通透，反射中不能出现错误的室内HDR房间。

### 4.5 现有视图、裁切与生命周期

- 保留`RoomExterior`外部接口，内部按地形、海面、天空、植被分模块，配置集中管理米制尺寸、太阳/海色和固定随机种子；无需先完成公共SDK提炼。
- 阳台预设改为从阳台内侧向南看海，验证环绕限制、目标点和手机退远；第一人称自由朝向仍由用户控制。原全屋鸟瞰继续用于室内剖面；验收另存屋外侧视截图，核对整屋确实坐落在平台上。
- 近侧剖面只作用于可能遮挡房屋的近景地形/植被；天空、海面和远方海岸保持完整。阶段A将该裁切限定在距房屋中心50m以内，远处工程侧视保留完整地形/崖体。现有`clipPlane2`与镜面的`clipPlane`独立，新着色器必须遵守相应裁切，不能沿用“所有室外材质统一裁掉”的规则造成半片海消失。
- 外景继续标记`exterior`并排除室内拾取和漫游碰撞，保留窗户、阳台栏杆、入户的现有安全边界；日光不受室内灯开关影响。全屋共享纹理/海岸状态，释放房间不能提前销毁共享资源。
- 海面动画在外景不可见、页面后台或场景销毁时停更；恢复保持时间连续且避免巨大delta。移除所有observer、纹理、网格、材质、灯和可选目标，失败导入保留房屋及低成本海岸占位。
- 必需外景JS/着色器和素材进入正常首屏就绪流程及请求统计；不靠进入阳台后突然加载或遗漏动态分包规避预算。

## 5. 资源预算与实施闸口

基于`f86c659`成品的历史验收值，以及本轮读取的实际森林图片字节；这些不是新方案的实测结果。1MiB=1,048,576字节。

| 项目 | 字节 / 预算或设计上限 |
| --- | ---: |
| 当前运行素材 | 16,457,409；余319,807字节 |
| 当前完整发布 | 42,756,315；余235,301字节 |
| 当前实际首屏JS | 2,751,444；余394,284字节 |
| 退出运行白名单的森林全景及树皮 | 1,858,746 + 52,093 = 1,910,839字节 |
| 退出森林后可用的素材空间 | 2,230,646字节，约2.13MiB |
| 退出森林后可用的完整发布空间 | 2,146,140字节，约2.05MiB，需共同容纳素材、代码、全部分包及说明增量 |
| 新海岸素材合计设计上限 | 1.55MiB：岩石PBR约0.97、草地/植被约0.20、水面法线约0.10、室外环境约0.28；均需实际编码验证 |
| 新代码及全部分包净增设计上限 | 0.30MiB，其中实际首屏JS净增≤0.18MiB |
| 说明/清单等净增预留 | 0.05MiB；新素材和全部交付增量合计≤1.90MiB |

按上述设计上限估算，素材约15.42MiB、实际首屏JS约2.80MiB、完整发布约40.85MiB；这只是账面估算，不承诺编码、构建或渲染结果。实际首屏须包含必需异步JS，完整发布包含Inspector等全部动态分包、来源、许可和清单自身。两个目标GLB≤4.25MiB、素材≤16MiB、首屏JS≤3MiB、完整发布≤41MiB均不调整。

几何初始目标为室外总顶点≤原森林160,000的检查上限，按空间分区合批；记录可见绘制、材质/纹理、生成纹理像素和新增阴影显存，不用下载字节替代GPU成本。程序生成数据和自定义着色器代码也必须计入对应JS/运行成本。是否更快或更流畅需要独立实测，本需求不恢复暂停实验。

若1.55MiB素材上限下的近景不能达标，先比较同镜头编码、共享材质、纹理分辨率与几何细节配置；若仍确需扩大预算，应先保存候选体积/画质/依赖证据，再更新本方案、资源原则、阈值/白名单和相关测试，不能只上调阈值或降低现有室内画质。

新素材保存原件/交付SHA256、工具版本、参数、来源及许可；移除森林的当前发布入口，历史原件与历史文档保留。后续更新当前资产说明时另建海岸版本记录；已冻结v1的清单、标签和摘要不覆盖，新增海岸版本另建基线。

1. 工程：`npm test`、`npm run typecheck`、临时目录开发构建、`npm run build:production`及发布校验。启动注册测试使用无总入口预热的独立进程；自定义材质/环境加载器按实际依赖在`RoomRuntime`/`RoomShaders`精确登记。
2. 视觉：阳台面海、客厅望海、左右沿栏杆移动、低头看崖缘、侧窗/后窗、屋外侧视，检查轮廓/尺度/海平线、地形接缝、岩层UV、重复、高光、泡沫与远处闪烁；按1280×800、390×844、844×390及DPR1/2检查。保存同姿态前后截图和短时连续画面，动态效果不能只验收静态截图。
