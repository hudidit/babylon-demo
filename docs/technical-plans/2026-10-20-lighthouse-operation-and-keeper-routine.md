## 背景与当前实现

当前灯塔已有首层维护室、二至四层观景室、顶层灯室和外廊，沿垂直梯连续可达。首层已有工具、配电面板、工作灯开关和可查看记录，顶层已有程序生成的透镜环与保护框。

核对 [LighthouseDetails.ts](../../src/examples/LighthouseDetails.ts)、[LighthouseRecords.ts](../../src/examples/LighthouseRecords.ts) 和 [LighthouseLayout.ts](../../src/examples/LighthouseLayout.ts)：工作灯控制的是塔内照明；维护记录是写有 `DAYLIGHT STANDBY` 的固定原创图面；灯头仍是美术陈设，尚无导航灯运行、旋转驱动、故障、供电和任务状态。

[RoomTimeOfDay.ts](../../src/examples/RoomTimeOfDay.ts) 提供八个时间节点和连续时钟，默认正午、自动流转默认关闭，开启后一个昼夜为现实24分钟。太阳轨迹为美术示意，没有经纬度、日期和季节；当前天气保持晴到轻霭。住宅和灯塔之间已有连续陆路，“孤岛”可以作为整个居住地的剧情背景，补给码头和完整岛屿地形仍属后续范围。以上均与唐宅档案无关。

## 现实灯塔如何工作

### 导航信号由光学系统和固定灯质共同形成

灯塔向海上提供位置或危险水域的视觉标志。传统菲涅尔透镜通过成组棱镜收集光线，向海平线方向形成集中的光束；旋转光学系统扫过观察者时，观察者看到周期性亮闪。[Trinity House 光学说明](https://www.trinityhouse.co.uk/about-us/a-to-z-of-trinity-house/optics)介绍了这一机制。

邻近灯塔通过灯光颜色、闪光节奏等特征帮助船员识别；白天的塔身颜色和外观也参与识别。塔高、海面以上灯高与能见距离有关，不能把一个灯泡的亮度直接换算成任意海况下的可见距离。[Trinity House 常见问题](https://trinityhouse.co.uk/about-us/trinity-house-faq)说明了日标、灯高和闪光特征。

“旋转”并非所有灯塔的必要条件。NLB的[太阳能改造资料](https://www.nlb.org.uk/history/solarisation/)记录了用电子闪光器控制LED启闭的技术；保留旋转视觉也有现实设备基础，例如厂商[Sabik VRB-25-LED](https://sabik.com/product/vrb-25-led/)采用LED、直驱无刷电机和昼夜自动检测。该产品说明用于证明技术组合可行，本方案不照搬其射程或具体额定功率。

### 点灯依灯站运行要求和能见条件决定

美国国家公园管理局对[Cape Lookout守塔工作的记录](https://www.nps.gov/calo/learn/historyculture/lh-keeper.htm)明确提到日落至日出点灯，白天风暴导致视线受阻时也要点灯。现代[Start Point灯站](https://www.nlb.org.uk/lighthouses/start-point/)用光敏设备控制启闭，并把设备状态传回管理中心；[Trinity House](https://trinityhouse.co.uk/about-us/trinity-house-faq)也介绍了用能见度探测器触发灯光或雾号。

具体站点可能有全天运行安排。[Longstone在2015年的改造记录](https://www.trinityhouse.co.uk/articles/re-engineering-the-longstone-lighthouse)就记录了由全天灯改为夜间灯的航海评估。因此，固定18点到6点只能是项目的示意作息，不能称为各地灯塔的统一制度。浓雾中的开灯也不保证远处仍能看见灯光。

### 守塔人的工作随技术年代改变

传统油灯塔需要运油、修灯芯、清除烟灰、清洁透镜、给重锤钟机上弦，并在夜间观察光源和转动。[Cape Hatteras的记录](https://www.nps.gov/caha/learn/historyculture/thekeepersfaqs.htm)显示曾由主守塔人和两名助手轮流承担四小时夜班，兼管建筑维修、物资和日志。

现代自动灯塔把人的工作转为巡检、保洁、报告与维修。[Stoer Head](https://www.nlb.org.uk/lighthouses/stoer-head/)有远程监测、定期现场巡视和年度技术维护；该站的频率不直接作为本项目的统一标准。Trinity House最后一座有人值守灯塔于1998年完成自动化，见[官方回顾](https://trinityhouse.co.uk/articles/a-fine-farewell)。

因此，本项目采用“自动设备加驻岛维护员”的剧情安排。主角能在正常夜间休息，收到异常报警后处理；若以后改用19世纪油灯，则需要连同人员轮班、油库、烟道、重锤井和补给制度重新设计。

## 推荐灯站配置与取舍

### 设备组成

| 设备 | 运行职责 | 主角可做的工作 |
| --- | --- | --- |
| 白色LED导航主灯与旋转光学头 | 电机按固定速度转动，形成规定的白闪 | 观察发光、转速、异常声音及温度指示；按故障更换模块 |
| 独立备用LED灯 | 主灯或转动机构失效时维持预设导航信号 | 检查备用电源，做受控切换测试，确认主灯恢复后再切回 |
| 控制器与光敏检测 | 自动判断昼夜，管理模式、反馈和报警 | 检查传感器是否被盐垢遮挡，核对自动模式和告警 |
| 24V直流电池组与保护配电 | 夜间供电，保护导航支路 | 查看电量、充放电及故障指示；检查外部接头、线缆和渗漏痕迹 |
| 太阳能与充电控制器 | 白天回充电池 | 检查遮挡、盐污、充电趋势和固定件，按污损清洁 |
| 备用柴油发电机与充电器 | 连续阴天或充电系统故障时补能 | 核对燃油、机油和泄漏，按维护安排试机或补给 |
| 灯室玻璃、密封与通风 | 保护光学设备，保持出光通畅 | 检查盐膜、结露、鸟污、漏水和风雨损伤 |
| 通信和日志终端 | 上传状态，接收天气、补给与故障信息 | 登记观察、设备读数、处置及尚未修复的问题 |

主灯与备用灯采用互锁，避免同时发出不同节奏。备用灯有独立的小电源支路和相应储能，不能只在同一故障回路上再接一只灯。备用灯的覆盖能力须另设记录；信号恢复不等于主灯性能完全恢复。

太阳能、电池和备用灯都有真实灯站案例：[Start Point](https://www.nlb.org.uk/lighthouses/start-point/)使用太阳能给电池充电，外廊设应急备用灯。发电机作为本虚构灯站的补能配置，位于塔外独立通风设备间；燃油储存另设，不占用首层楼梯或灯室。住宅、电动车和导航供电分支管理，剧情上保留导航用电优先级。

选择LED与无刷直驱后，日常任务以观察和清洁为主，不安排每天剪灯芯、加灯油、上重锤或给密封电机加油。是否更换润滑件、滤芯或电池，应由所选设备手册和运行状态决定。

### 灯质与旋转速度

首版建议固定为 `Fl W 10s`：从同一海上观察方向，每10秒出现一次短白闪。它是本项目候选灯质，不对应某个已指定的真实灯站。

- 采用一个有效主光束，每圈10秒，即6转每分钟；这一速度处于所引Sabik设备的可调转速范围内。
- 闪光来自光束扫过观察方向；不能把整个灯头变成每10秒整体熄灭一次，同时声称这是同一旋转光学机制。
- 备用灯用电子闪光器重复相同候选灯质，切换时记录一次过渡；不要把它表现成持续常亮的家用应急灯。
- 若以后增加第二束相反方向的光，在相同转速下同一观察方向会每5秒遇到一次光束，须重新核对灯质，不能只增加视觉光束。
- 亮闪时长与光束宽度一并调试，白闪时间应短于暗间隔；射程需结合选定光学设备、灯高和能见条件另算，本次不承诺海里数。

晴夜以可见灯头和克制的扫光表现导航功能。雾中明显光路、海面照明和扫过陆地的效果分开验收；不能用无边界的亮锥穿过塔壁、山体或住宅来表示灯光有效。

### 供电量级示例

以下仅用于后续玩法平衡，数值为假设，尚非设备选型：主灯及电机夜间平均50W、控制通信全天平均5W，按12小时夜间计算，日耗电约为 `50×12＋5×24＝720Wh`。若设计保留3天自主运行，按允许使用80%储能计算，名义储能至少约为 `720×3÷0.8＝2700Wh`；24V、120Ah约为2880Wh。

这只是基本算术示例，未计温度、老化、线路及充电损耗，也不包含备用独立储能、住宅和雾号。实际选型须另计裕量，并以所在地最差季节日照校核太阳能，不把2880Wh写成已验证容量。游戏第一阶段只实现正常供电和主备状态；精细能量模型放在后续阶段。

## 每天何时点亮

### 常规日程

现实规则采用“覆盖当地夜间，低能见度按本站要求延长”。未选择地理位置、日期和季节前，游戏首版以场景时间 **18:00开启，次日06:00关闭** 作为便于理解的默认值，配置可调整。

当前示意日轨在18点和6点太阳均高于地平线5°。这两个时刻在本方案中代表黄昏提前亮、清晨稍后关的缓冲，不能标注为真实日落日出。若后来接入真实经纬度和日期，再用当地日出日落或经调试的光敏门限替换日程数据。

| 条件或时段 | 导航主灯状态 | 人的职责 |
| --- | --- | --- |
| 06:00至18:00，晴朗 | 白天待机，保持控制与通信 | 巡检、清洁、补给；受控测试除外 |
| 17:00起 | 仍按白天规则待机，允许短时功能测试 | 完成傍晚确认，离开后仍保持自动模式 |
| 18:00至次日06:00 | 自动运行，保持固定灯质 | 启动后确认一轮；之后正常休息并接收报警 |
| 白天低能见度 | 配置为需要点灯的状态，优先于白天待机 | 核对能见度、设备及补能能力，记录延长运行 |
| 主灯故障或主灯检修 | 切换备用灯；仍按是否需要导航决定发光 | 确认备用信号，再隔离和检修主灯 |
| 主备均不可用 | 灯灭并保持故障报警 | 记录中断，向岸上值班中心报告，安排修复 |

当前尚无天气系统，低能见度输入只列为后续接口；不能把当前固定的远景轻霭直接当作浓雾。未来接入传感器模拟时，开关阈值和恢复延迟应按本站方案配置，避免临界值来回启停。

### 控制顺序

是否需要点灯先由夜间或低能见度需求决定，再检查主灯可用性；主灯不可用则转备用，两者都不可用才记为服务中断。独立覆盖此顺序的情况只有受控测试和明确隔离：检修主灯不会同时停掉可用备用灯。

面板建议提供“自动、测试、检修”三种模式。日常只需确认自动状态；测试可提前结束或超时返回自动；检修必须保持隔离标识，并说明由备用灯承担导航。原有工作灯开关继续只控制塔内照明，不能兼作导航主开关。

灯在预定时间自动启亮，不能把清洁任务或日志打勾设成通电前置条件。错过巡检应留下未完成记录，真实污损或电量异常才影响设备。

## 主角每天需要完成的工作

下表是针对虚构灯站设计的工作安排。真实维护频次以本站规程和设备手册为准；现代设备每天检查，不等于每天拆开或更换部件。

| 场景时间 | 工作与位置 | 检查内容及完成依据 |
| --- | --- | --- |
| 06:00至06:30 | 晨间交接，首层面板或住宅终端 | 核对整夜是否有停灯、备用切换和电量告警；确认晴天已自动待机，保留故障记录 |
| 08:30左右 | 登塔巡检，沿五层至灯室 | 看玻璃、光学保护面是否有盐膜、鸟污、结露；观察电缆、漏水和固定件；发现污损后才清洁 |
| 同次登塔 | 短时灯具与驱动检查 | 在测试模式看发光、转动和反馈，核对10秒周期及异常声音；完成后回自动，避免用裸眼贴近主光束检查 |
| 10:00左右 | 供电巡视，首层及塔外设备区 | 核对电池、充电趋势、传感器遮挡和太阳能固定件；外部有污损再清洁，无需每天拆接线端子 |
| 午后按需 | 保养、库存和生活工作 | 处理小范围防腐、密封、清扫、工具归位、备件和燃油库存；安排下一次补给和安全联络 |
| 17:00至17:30 | 傍晚准备，面板及必要的灯室复查 | 确认剩余电量能支撑预计夜间、备用灯可用、无遗留隔离，按维护计划做短时测试 |
| 18:00后 | 起灯确认，住宅或岸上终端 | 看主灯已运行、旋转反馈及灯质正常；首版保留可观察灯头的确认位置 |
| 21:00左右 | 睡前状态查看 | 看告警、天气和电量趋势，登记后休息；正常情况不要求再次爬塔或每小时起床 |
| 夜间异常时 | 报警处置 | 判断主灯、备用和供电状态，先保导航；风浪或电气条件不适合时保留隔离并请求支援 |

日常交互可归纳为：读仪表、观察设备、按需擦拭、受控试灯、核对备用、记录与补给。现代LED通常无需每天更换，健康电机也无需为制造任务而每天拆修。

### 每周及更长周期的工作

每周从几个维护项中轮换：备用灯与报警切换、发电机试运转、备件和燃油盘点、可达紧固件与门窗密封检查。试机时长和负载按选定设备手册制定，本次不把某个分钟数称为通用规程。

按月份、累计机时或专门检查安排电池健康、充电系统、腐蚀、防雷和通信设备检查。整塔油漆、精密光学调整、起吊和专业电气作业属于专门维护，不塞进每天的必做清单。风暴后追加漏水、玻璃、支架、线路与道路检查；风暴正在影响外廊时，不安排单人出廊擦玻璃。

### 日志内容

日志记录场景日序与时刻、天气和能见状态、主灯或备用灯、灯质检查结果、电量和充电趋势、告警、清洁或维修、耗材及未解决问题。自动事件保留客观记录，主角补充观察和处置；缺少签字不会抹掉已经发生的点灯或中断。

“已检查”“发现问题”“已处置”“复验通过”应区分。不能一次点击“完成巡检”就同时清掉电量低、灯头卡滞和未修复的漏水。

## 故障及对应玩法

| 可观察现象 | 原因候选 | 主角的处理循环 | 对导航的影响 |
| --- | --- | --- | --- |
| 转动正常但出光减弱，玻璃可见污迹 | 盐膜、鸟污或结露 | 观察定位，清洁或处理密封后复查 | 渐进减弱；不立刻触发沉船事件 |
| 灯头有光却不转，或周期异常 | 驱动、电源或转速反馈故障 | 切备用，隔离主灯，再检查或更换对应模块，复验后恢复 | 固定方向常亮不能算按灯质正常服务 |
| 阴天后电量持续下降 | 充电不足、面板遮挡或充电系统故障 | 核对充电趋势，按需清洁或启备用充电，记录剩余支撑时间 | 先告警，随后影响可用供电 |
| 无理由白天亮灯或天黑未起灯 | 传感器污损或控制模式错误 | 查传感器与模式，受控覆盖后排查，修好回自动 | 留下异常和人工覆盖记录 |
| 机房燃油低、机组不启动 | 补给不足或机组故障 | 检查外部状态，按需补给或报修；导航先由电池支撑 | 影响持续补能能力，不能瞬间等同主灯熄灭 |
| 漏水或保护动作反复发生 | 密封损伤或电气故障 | 保持故障支路隔离，启用独立备用，申请专业维修 | 记录降级；不鼓励反复合闸消警 |
| 状态终端失联 | 通信链路故障 | 就地确认实际灯光、记录、恢复通信或用备用联络 | 通信故障本身不等于主灯已经停灯 |

故障依据天气、累计运行和已有隐患生成，正常日允许只有巡检。灯头、电池、充电、通信和污损分别表达，避免用一条综合“耐久度”让任何故障都靠扳手修好。反馈先给可观察症状和趋势，保留处理窗口；结果优先体现停灯时长、降级时长、补给延误或维修记录，船舶事故若进入剧情需另建条件。

## 接入现有项目的实施步骤

### 第一阶段让导航灯按规则运行

1. 新建不依赖渲染的灯站状态模块，维护运行模式、点灯需求、主备可用性、告警及运行事件。沿用已有时钟和暂停原因，不建第二套日历。
2. 接入首版18点至6点日程，补上主灯、旋转反馈和独立备用显示；支持白天短测试、故障切备用及手动时间选点。
3. 将首层面板扩为有明确状态的控制与查看入口，复用既有工作台、查看和声音流程；原工作灯继续独立。
4. 检查固定观察方向下的10秒灯质、真实输入到塔顶的路线、昼夜与主备切换，以及生产独立发布。

第一阶段即能形成每天自行运行的灯塔，不必等待任务、天气或经济系统。

## 时钟和交互边界

- **昼夜时钟**决定作息和能量消耗；开启自动流转后仍沿用24分钟一天。关闭自动时，日程停在所选时间。
- **设备运动计时**使用场景活跃时的现实秒数，10秒闪光周期不乘昼夜60倍加速。它只管理设备相位，不另建日历。手动停在21点仍可观察旋转，打开暂停界面或后台则冻结设备相位和耗电，恢复不补算后台时间。
- 手动选点属于现有游览功能：可以看起灯与待机，不因从白天跳到夜里就批量生成漏检、消耗整夜燃料或判定任务失败。模式和故障状态保持，过渡结束后按目标时刻求值，不把1.2秒视觉过渡当作经过了多个工作日。
- 维护玩法的每日任务和库存按连续自动经过的日界线推进；时间按钮不补发奖励、不重复消耗库存，也不隐式开启自动。主灯相位连续，不随每次刷新仪表重新开始。
- 能量平衡使用平均功率、运行时长和充电状态；不能把10秒旋转周期再当作一天中的10秒来重复放大耗电。
- 灯站在海岸整体显示且未暂停时运行，即使玩家在住宅内也保持导航状态；不能照搬“摄像机靠近才启用”的原局部工作灯门控。隐藏整个海岸或销毁场景时清理设备更新与资源。
