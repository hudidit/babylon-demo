- 创建日期：2026-10-18
- 更新时间：2026-10-18
- 代码与初始设计基线：`750a5e3`。
- 关联：[唐宅场景方案](2026-10-18-tang-residence-scene.md)、[项目协作约定](../../AGENTS.md)、[资源与首屏优化原则](../resource-optimization-principles.md)。

## 1. 背景与目标

用户要求在开发中系统维护时代、宅主背景、房屋用途等信息，使后续调整能追踪到物品与表现细节。初始方案已包含史料、布局和素材方向，但设定、房间、物品和素材尚无稳定关联；单篇方案不断增补会产生重复、状态混淆和漏改。

本轮建立可持续维护的场景档案，登记初始设计并明确权威来源、稳定编号、状态及变更检查流程。不新增历史结论，不把暂定设定升级为用户确认，也不开始 3D 开发。

## 2. 方案与取舍

在 `docs/tang-residence/` 建立：

| 文件 | 维护职责 |
| --- | --- |
| `README.md` | 总入口、权威顺序、必读路径及完成条件 |
| `scene-profile.md` | 年代、地域、宅主/家庭、生活与视觉设定，以及这些设定的影响范围 |
| `spaces.md` | 宅地、房间和廊院的稳定编号、用途、尺寸与联系 |
| `objects.md` | 建筑构件、物品类型和布置记录，关联设定、空间、史料与素材 |
| `evidence.md` | 史料、采用边界、待查资料；沿用已有 H01—H11 编号 |
| `assets.md` | 候选来源与实际交付分别登记，许可、处理、路径、摘要及使用范围 |
| `change-control.md` | 变更影响矩阵、决策/待办、检查清单与记录模板 |

初始方案保留技术取舍、预算、阶段和历史快照，但将详细主数据移入档案并链接，避免同一设定在两处独立维护。根目录 AGENTS 增加唐宅开发必读与同步维护约定；索引和 CHANGELOG 记录本次文档规则变化。

采用 Markdown 表格与稳定 ID 即可满足当前规模，不新增数据库、运行配置或校验依赖。类型不等于实例，候选不等于已选用，史料等级不等于适用性验收，许可核实不等于素材已接入。尚无文件或测量时如实记“未建立/待定”，不伪造路径与摘要。

## 3. 实施步骤

1. 建立本方案；从 `750a5e3` 的初始设计提取已有设定、空间、陈设、证据和素材候选。
2. 建立七份档案，明确字段、关联和当前状态；新增决策、待核问题与变更模板。
3. 重整原方案为设计与技术入口，指向主数据；补充 AGENTS、方案索引和 CHANGELOG。
4. 核对本地链接/锚点、ID 唯一与引用、房间/物品/素材关联、数量与状态及 Git 差异；只提交本轮文档并推送当前分支。

## 4. 验收方法

- 读者能从一个物品反查所在空间、用途、哪些背景设定约束它、史料采用边界、素材候选及当前实现状态。
- 读者能从年代、身份、季节、房屋用途变化查到需要复查的领域，含文字、交互、音效、灯光和资源交付。
- 核实已迁移的 H01—H11、原空间尺寸和初始陈设不被无意改写；未确定的家庭人数、官阶、信仰等保持待定。
- 本地文档链接与锚点有效；登记 ID 唯一，交叉引用存在；原平面图和档案的布局/尺寸一致。
- 仅文档变化，按项目约定不运行场景测试或构建；不修改代码、运行资源、预算或第三方许可结论，不纳入并行进行的载具工作。

迁移前后逐行比较 H01—H11 内容及全部 19 个来源 URL，结果保持一致；预算节内容、原始平面 PNG/SVG 字节保持不变，档案中的文档资产大小与 SHA256 核对通过。原方案已改为引用各主数据，AGENTS、方案索引与 CHANGELOG 同步更新；按纯文档范围检查 Git 差异，不重跑场景测试/构建，也不纳入并行载具代码。
