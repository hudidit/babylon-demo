## 编写与维护

1. 新增或更新较大需求前，先阅读已有方案，避免重复规划或偏离既定目标。
2. 文件名采用 `YYYY-MM-DD-主题英文短名.md`，在文档开头记录状态、创建日期、更新时间和适用的代码基线。
3. 写清背景与现状、目标与范围、方案及取舍、实施步骤和验收方法。按实际需要补充风险、资源来源和 ROI，不要求每篇使用相同篇幅。
4. 实施时更新方案状态和实际选择；方案变化时记录原因；完成后补充验证结果、相关提交与遗留事项。
5. 同步维护本索引与根目录变更日志。被替代的方案保留，并链接到后续方案。

状态使用待实施、实施中、已完成或已替代。方案文件创建日期保持不变，后续修改更新文档中的更新时间。
