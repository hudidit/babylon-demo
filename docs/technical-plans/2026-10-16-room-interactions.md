## 背景与现状

家具大多按材质静态合并并冻结矩阵。书桌有两个装饰抽屉面，窗边桌有三个；古董柜 GLB 已有三个独立抽屉节点。两盏灯一直开启，第一人称依赖拖动环顾，没有中心拾取和鼠标锁定。阴影采用静态缓存，碰撞合并分区只适用于静态家具。

## 目标与范围

- 八个抽屉可独立、连续反向地平滑开合，移动把手和抽屉内部，保留关闭时的家具外观。
- 点击台灯、落地灯同步切换直接照明和各自发光材质，初始仍开启。
- 第一人称锁定并隐藏指针，中央固定小圆点；瞄准近处物品显示简短动作提示，左键交互。ESC 或浏览器释放锁定时退出并恢复上次环绕视角。
- 环绕视角仍可点击物品，拖动旋转不误触；设置、调试、切换视角及页面生命周期能正确释放鼠标。
- 沿用 pure 导入、现有素材和全部预算，不新增运行依赖，不做 FPS 或加载速度收益声明。

## 方案及取舍

1. 将交互物件从全室静态合并中分离；同一物件内部仍按材质合并。动态抽屉不冻结矩阵，不沿用静态碰撞分区，碰撞跟随实际几何移动。书桌/窗边桌补底板、侧板、后板和真实开口；古董柜直接利用原节点与纹理，确认 glTF 坐标转换后的向外方向。
2. 统一维护物件注册、射线拾取和无依赖插值动画；射线同时检查遮挡，第一人称限制操作距离，点击即时复核，焦点定时更新。动画期间刷新缓存阴影，静止后继续缓存。
3. 两盏灯使用独立发光材质，保留蜡烛及其他材质；灯光关闭不改变窗光/环境光。
4. 使用标准 Pointer Lock API 和 Babylon 现有鼠标输入；同时处理成功、失败、ESC、失焦与销毁。锁定失败时提示点击画面重试，未锁定时不启动移动，不将失败伪装成锁定成功。

## 实施步骤

1. 建立方案，核对模型节点、相机输入、冻结/合并及阴影行为。
2. 实现动态家具、独立灯光状态与射线交互。
3. 接入第一人称指针锁定、圆点、动作提示及退出流程。
4. 增加覆盖反向动画、实际模型方向、遮挡/距离、灯光独立性、动态碰撞和锁定状态的必要回归检查。
5. 测试、类型检查、开发构建、生产构建与发布校验；独立托管验证全部八个抽屉、两灯、第一人称及原交互，测量实际首屏 JS，保留截图与请求摘要。
6. 同步方案、索引及变更日志，提交并推送当前分支。

## 验收方法

- 真实几何测试覆盖关闭/打开边界、反向不中断跳变、移动后碰撞、遮挡与范围、两灯独立且发光状态一致。
- 真实浏览器点击进入第一人称后检查 `pointerLockElement`、鼠标自由环顾、WASD、中心拾取及 ESC 恢复；模拟失败/失焦并检查释放与控件恢复。拖动和右键不触发物品。
- 独立托管最终 `dist`，检查六视角及抽屉近景、灯具开关画面、设置和 Inspector，无新增运行/着色器错误或 404。
- 运行素材 ≤16 MiB、目标 GLB ≤4.25 MiB、实际首屏 JS（含必要异步）≤3 MiB、完整发布 ≤41 MiB；检查来源/说明及全部动态分包仍交付。

## 实际结果

- 八个抽屉已独立开合：书桌 2 个、窗边桌 3 个、古董柜 3 个。自建抽屉补齐底/侧/后板及真实开口，同一物件内部仍按材质合并；古董柜直接移动既有完整抽屉节点，沿源坐标 +Z 移动 0.38，对应房间向外 1.786，未改 GLB 几何、UV 或素材。
- 动态抽屉取消冻结矩阵并沿用实际三角形碰撞，不登记静态碰撞分区；开合时刷新三处阴影，静止后保持缓存。中途重复点击平滑反向，静态家具及固定灯具继续冻结矩阵。
- 两盏灯使用独立发光材质，点击同步切换直接光强与发光色；窗光、环境和蜡烛保持原状态。两种视角共用真实表面射线，非交互家具也能遮挡，第一人称有效距离为 7.5 房间单位，焦点每 100 ms 更新并在点击时即时复核。
- 第一人称使用原生 Pointer Lock 与 Babylon 既有输入，中央为 6 px 小圆点，瞄准可操作物件时略放大并显示动作。ESC、浏览器释放、失焦恢复进入前的环绕预设；设置/调试释放鼠标，设置关闭后可点击画面恢复。失败时显示重试提示，移动保持暂停，避免把失败当作锁定成功。
- 浏览器脚本最初只等待 `pointerLockElement`，该属性可能先于 `pointerlockchange` 回调更新，导致第一笔测试移动早于相机输入附加。已改为同时等待相机输入就绪；最终没有新增输入映射或自定义旋转代码。
