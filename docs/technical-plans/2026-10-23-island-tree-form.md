# 海岛树形与枝叶密度修正

状态：已完成（工程及Chrome画面/交互验收）。日期：2026-10-23，基线：`f5172ba`。承接[素材接入方案](2026-10-23-island-tree-assets.md)，遵循[资源原则](../resource-optimization-principles.md)。

## 问题与目标

用户指出上版树冠枝层太稀疏、不像真实松树。上版把小枝贴图直接放大到主枝尺寸，再按三四层、每层四方向排列；贴图虽来自真实素材，整体缺少主枝、细分枝和团簇，不能以工程测试通过代替美术验收。本轮明确替代此树形。

沿用现有岩岸/灯塔氛围，暂以温带海岸作为美术工作假设，不写成已确认的真实地域或树种。黑松可用于海岛造林，成熟冠形可向外开展；参考[舟山案例](https://www.forestry.gov.cn/c/www/dfdt/671950.jhtml)与[RHS黑松资料](https://www.rhs.org.uk/plants/13148/pinus-thunbergii/details)。本轮使用松针表现泛化的沿海针叶树，不把原Poly Haven素材宣称为黑松。海风影响通过偏冠、倾斜分枝和高低差表现，不能把所有树做成稀疏尖塔。

## 方案与取舍

1. 保留88棵根位、尺度参数、现有林团、丘体及非树景观。重新建树：略弯且渐细的树干、2～3条真实连接的主枝，形成宽阔、不对称的枝冠，而非整齐的轴向枝层。
2. 从已校验CC0松针原件重建多种紧凑叶簇图集：针叶保持细小尺度，单张表现密集的小枝团；多个有体积的交叉簇在空间中交叠，中心饱满、边缘有缺口。至少三种图案与不同尺寸/旋转组合，避免从任何一个主机位只看到少数扁枝。
3. 使用同一图集内树皮区域与叶簇，保留原19景观批次、共享材质、昼夜响应、资源失败降级。若新增树皮原件，记录独立URL/作者许可/SHA256及加工步骤。树木不新增阴影、碰撞、灯光、逐帧回调、依赖或动态LOD。
4. 基线首屏3,139,835 B、运行15,931,426 B、完整发布42,721,776 B；原四项硬预算保持。用减少重复低效叶片和合理分配近/远几何控制成本，既有166,000总顶点与15,000景观三角形上限保持。增加透明覆盖是成本，不宣称FPS无损，性能采样继续暂停。

## 实现结果与成本

原88棵树已重建为弯曲渐细树干、2～3条连接的分叉枝和不规则开展的树冠。三种叶簇分别由360根细小松针枝烘焙形成，与同一CC0素材的树皮颜色图拼成1024×1024图集；使用12/9张近/远叶片，减少旧的大枝片，把几何分配给真实枝干。树根位置与高度参数、丘体和非树景观摘要与基线相同。温带岩岸仍只是工作假设，不宣称原素材为黑松，也未新增生态或地域设定。

PNG由64,049 B增至265,227 B，约增加196.5 KiB；纹理、材质和批次数量保持，但纹理分辨率与透明覆盖增加都有成本。按RGBA8及完整mipmap估算，图集存储约由1.33 MiB升至5.33 MiB，这是估算，不是驱动显存测量。景观顶点10,129→10,153，三角形9,216→10,416；原海岸加景观165,829≤166,000，仍使用19个静态景观网格。没有新增阴影、灯、碰撞、依赖或每帧更新。

419项测试、类型、开发/生产构建及发布校验通过，固定原件重建摘要一致。Chrome生产包九机位×三尺寸27组前后姿态一致，另保存五天气×全景/屋后近景10张画面；根与`/home/`各498完整文件GET/字节/SHA256通过。原生键盘/参考步进、护栏、地图、设置、Inspector及贴图请求失败降级通过，正常路径无运行/着色器错误或404，保留旧CSS弃用和Webpack三条体积建议。
