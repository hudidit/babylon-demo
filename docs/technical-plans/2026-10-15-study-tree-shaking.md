## 背景与现状

现有完整发布目录 41,320,768 字节（39.41 MiB），初始请求正文 24,460,929 字节（23.33 MiB）；18 个素材 15,871,062 字节（15.14 MiB），首次 JS 8,585,185 字节（8.19 MiB），主 JS 8,571,260 字节。完整构建保留调试及编辑器，不能把完整目录与首屏下载混为一谈。

Webpack 已使用 production 模式、ESM 输出和默认压缩，下一步收益来自缩小依赖图。当前 Babylon.js 9.30.0 已提供 pure 模块与显式注册。书房运行路径使用 `@babylonjs/core` 总入口，入口中的火箭示例虽未实例化仍存在副作用依赖；`@babylonjs/loaders/glTF` 同时注册 glTF 1/2 及扩展。不能通过把所有模块强行标为无副作用、关闭功能或只拆分文件来冒充 tree-shaking。

## 目标与范围

- 对相同代码基线重新构建并保存初始/动态模块、文件字节及 gzip/Brotli 离线指标；区分首屏收益与完整发布目录变化。
- 将运行代码改为 pure 或必要的精确路径，显式登记渲染和输入依赖；移开未运行的历史示例，保留其他示例源码。
- 使用仅 glTF 2.0 的加载路径；先保留其现有扩展能力，按实际模块证据决定是否需要进一步细化，避免在未知模型能力上盲目删除注册。
- 保留 Inspector 按需加载及功能，保留全部实际构建分包。重点降低首屏 JS，验收目标为原始字节减少至少 30%；已实现 69.87%，并增加 3 MiB 上限。
- 不改变 18 个素材、几何、灯光、相机与后期参数。不引入 Brotli 部署、KTX2、资源分级加载、限帧或 FPS 测试；离线压缩只用于同口径比较。

## 方案与取舍

1. 记录 Webpack 模块及 chunk 归属，定位初始包保留的无关能力；用实际模块图及首次请求验收，不能只统计主文件。
2. 书房运行路径采用 Babylon pure 导入，专门的注册模块统一维护必需功能。MeshBuilder 改用实际需要的独立建模函数，避免对象形式保留所有 builder；类型采用 `import type`。
3. 渲染注册覆盖 WebGL 纹理/立方体/原始/动态纹理、HDR 预过滤、MRT、PBR/标准材质、阴影、SSAO/前置通道、后期、射线、碰撞及相机输入。以本地 9.30.0 源码和实际运行校验为准。无需在初始包注册物理、XR、节点编辑器等未使用功能。
4. Inspector 按需入口可在打开时补齐其必要注册。保留能力并检查打开后不会重新创建引擎或改变画面；不通过关闭 Inspector 取得体积收益。
5. 增加有意义的回归保护：实际初始模块图不得重新纳入总入口或无关大系统，首屏/完整目录预算可复验，独立进程验证 pure 注册下的场景关键能力，避免现有测试提前引入 core 总入口掩盖缺注册问题。

官方依据：[pure imports](https://doc.babylonjs.com/setup/frameworkPackages/es6Support/treeShaking/)、[显式副作用注册](https://doc.babylonjs.com/setup/frameworkPackages/es6Support/treeShaking/registeringSideEffects/)。当前安装版本不升级，不覆盖上游 `sideEffects` 元数据，不对整个第三方包设置 `sideEffects: false`。

## 实施步骤

1. 实施前建立本方案，重新生成基线构建、模块图和十视角/交互记录。
2. 收窄入口、运行代码与加载器，依据缺失注册诊断和模块图迭代。
3. 执行现有测试、独立注册回归、类型检查、开发/生产构建和发布校验。
4. 对最终目录独立托管，检查十视角、PBR/HDR/阴影/SSAO/后期、移动碰撞、设置和 Inspector；保存无错误/404 的实际请求与静态对比。
5. 汇总首屏 JS、完整生产目录、压缩后理论字节及遗留事项，同步索引、变更日志，提交推送。

## 验收方法

- 同一设备/Chrome、1280 × 720、DPR 1、禁用缓存、无 HTTP 压缩；不采样 FPS、CPU/GPU 或加载时间。
- 保持 18 个素材 SHA256 一致；相机、几何、模型属性、材质及后期配置一致，十视角检查没有可见退化。
- 运行前后均独立托管，统计 HTML、所有实际初始 JS、后续 Inspector 请求；对完整发布目录逐文件核验。
- 原始首屏 JS 减少至少 30%，发布预算继续满足原方案；记录 gzip/Brotli 参数，不把离线压缩估算当作实际网络传输。
- 测试、类型检查、开发/生产构建通过；浏览器无新增错误、缺失注册、着色器编译失败或 404。保留已有建议告警并如实记录。

## 风险与回滚

缺失副作用可能让类型检查通过但运行时失败，或导致没有阴影、SSAO、错误法线/环境光。必须在没有 core 总入口预热的浏览器和独立测试进程中验证，并检查 Inspector 开启前的初始画面。必要的依赖宁可显式保留，不用画质换体积。历史示例保留到独立文件。失败时按普通提交回退，不改写历史。

## 实施结果与最终取舍

- 已将书房运行模块改为 pure 导入，区分类型导入；入口只启动书房，历史火箭示例移至独立的 `Rocket.ts`。未修改其他示例、素材、照明或后期参数，也没有升级依赖或覆盖上游副作用元数据。
- `RoomRuntime.ts` 显式登记标准 WebGL、立方体/原始/动态纹理、MRT、动态缓冲、材质克隆/解析、射线、碰撞和原有手柄输入；阴影及后期构造器按 9.30.0 实现自动登记自身组件。独立进程测试避免几何测试的 core 总入口提前登记功能而掩盖缺失。
- 核对四个 GLB 均未声明扩展后，采用 glTF 2.0 核心加载器，移除初始路径上的 glTF 1.0 和整组扩展注册。未来增加带扩展模型时须同步评估加载器和发布校验，不能直接假定支持所有扩展。
- Webpack 跨初始/异步 chunk 共享模块，对重复着色器 include 按 GLSL/WGSL 分组；补齐适用于多初始 chunk 的文件命名。`RoomShaders.ts` 显式纳入启动时实际请求的 26 个 WebGL 着色器，避免纯模块的逐个小文件加载。这里也包含既有 DefaultRenderingPipeline.prepare 初始化的关闭状态效果着色器，未开启对应效果。
- 中间候选的主 JS 曾降到 2.48 MiB，但完整目录超预算；继续收窄加载器、共享 shader include 后满足原 41 MiB 预算。未将超预算候选交付，也没有调高原发布预算。候选一度产生 49 个初始请求，显式着色器后收口为 23 个，全部 JS 请求均计入下表。
- 初始模块图保留 501 个源模块；不含 core 普通总入口、XR、物理、FlowGraph 执行系统、FrameGraph、节点编辑器、高斯点云渲染器、Inspector 或 glTF 1.0。两个必需小工具单独允许：glTF 核心 objectModelMapping 使用的 `FlowGraphInteger` 值类型，以及 SSAO/深度渲染器使用的 GaussianSplatting 类型判定函数；没有因此引入对应大系统。
- 生产构建自动生成 `bundle-analysis.json`，检查实际初始模块及静态入口 JS ≤ 3 MiB；发布校验复核该报告。浏览器测量脚本另外把必需异步 JS 计入 ≤ 3 MiB 检查，防止仅改请求时机造成虚假缩减。
