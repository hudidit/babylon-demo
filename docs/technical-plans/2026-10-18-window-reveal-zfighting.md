## 1. 背景与现状

第一人称靠近窗户并转动镜头时，窗洞四周的墙面与窗框交接处会出现高频闪烁；表现为同一条窗洞侧壁在墙面漆色和深色木框之间来回跳变，部分角度还伴随明显的红/绿斑点。问题在正视、斜视和仰视时均可出现，海景次卧窗最明显。

六处外墙窗共用 [RoomFurnishings.window()](../../src/examples/RoomFurnishings.ts) 组件，[HouseArchitecture](../../src/examples/HouseArchitecture.ts) 按窗洞尺寸缩放后放入墙洞中心。问题不是材质、光照或相机精度单独造成，而是两组几何表面在墙洞切割面上完全共面，形成深度冲突（z-fighting）。

### 1.1 根因

以次卧南窗为例（`unitsPerMeter=5`、墙厚 `0.1m=0.5` 世界单位）：

- 墙体按窗洞边缘切分为独立盒段，窗洞侧壁切割面位于墙中线两侧各 `0.25` 单位处；顶部和底部切割面正好在窗洞净高边缘。
- 旧窗框的`window-casing`四周压条使用倒角盒：侧压条内缘在缩放后正好落在窗洞侧壁平面上，上下压条内缘同理落在窗洞顶/底平面上；压条深度 `0.35`，完全埋在 `0.5` 厚的墙体内部。
- 因此墙面切割面和压条内侧面在同一平面上重叠，渲染时深度值交替胜出，肉眼看到窗框木色与墙面漆色闪烁。压条本身在墙体内部，正常视角看不到完整的木框，只以这种闪烁形式暴露出来。
- 倒角盒的圆角会把角部顶点向盒内收；只把压条整体向外移动很小距离时，圆角仍会回到切割面附近，问题容易残留。单纯给材质加`zOffset`还会影响共享的墙面/木材材质，不能局部解决。

## 2. 目标与范围

- 消除六处外墙窗在第一人称下的窗框/墙面交接闪烁，保持窗框、玻璃、窗台、窗帘、日光、碰撞和窗外景观不变。
- 不新增贴图、模型、材质、灯光、相机或渲染目标；不改变房间布局和开洞数据。
- 保持原有首屏 JS 与发布体积预算，不把几何微调描述为 FPS 或加载速度收益。

## 3. 方案及取舍

### 3.1 埋入墙体的压条改为平直盒并整体退让

- 压条位于墙体内部，没有可见的倒角需求。将其从`beveledBox`改为普通`CreateBox`，避免圆角把角部顶点拉回切割面。
- 四周压条沿远离洞口的两个方向各退让`casingClearance = 0.04`本地单位；上下压条长度增加`0.08`，与退让后的侧压条对齐。按各窗缩放后，压条内缘与墙洞切割面之间约`3.9mm`（1m宽主卫窗）到`10.9mm`（2.8m宽主卧窗），上下方向约`4～8mm`。
- 退让后的压条仍完全位于墙体体积内，不会穿出室内墙面，也不影响玻璃、外侧窗台、窗帘或可见的室内贴脸线脚。

### 3.2 未采用的方案

- **材质`zOffset`/多边形偏移**：墙面和木材材质被大量共享，偏移会波及其他墙面、家具和贴脸，且随视角仍可能不稳定。
- **直接删除压条**：可消除冲突，但会丢失墙体内的窗框背衬，也会改变全景半透明墙下的轮廓，超出最小修复范围。
- **继续用倒角盒只挪很小的距离**：倒角圆角仍接近切割面，测试余量不足。
- **加厚/减薄墙体或改窗洞尺寸**：会改变墙体、碰撞和已有取景，代价远大于问题。

## 4. 实施步骤

1. 用调试材质把墙面染绿、窗框木材染红，在第一人称近窗/斜视/仰视位置复现红绿交替，确认问题来自压条与墙洞切割面共面。
2. 修改[window()](../../src/examples/RoomFurnishings.ts)：压条改普通盒，增加本地退让量，并同步上下压条跨度。
3. 新增几何回归测试：检查六处窗的`darkWood`窗框顶点中，位于墙体厚度内的所有顶点到四个窗洞切割面的距离都大于`1mm`。
4. 运行完整测试、类型检查、开发/生产构建和发布校验。
5. 在独立托管的最终生产目录上，用同机 Chrome 检查六窗第一人称正视/斜视/仰视、横竖屏和运行错误；进行21个相机位置×11个侧壁采样点的红绿像素探针，比较修复前后。
6. 保存前后截图、像素/场景/JS指标，更新本文、方案索引、变更日志和验收记录后提交推送。

## 5. 验收方法

- **几何**：六窗`darkWood`压条在墙体厚度内的所有顶点距窗洞四个切割面均大于`1mm`；窗框、玻璃、窗台、窗帘和碰撞均保留。
- **画面**：第一人称近窗正视、左右斜视、仰视/俯视时，窗洞四周不再出现窗框与墙面的交替色或红绿斑点；正常材质下与修复前相比只应看到交接面稳定，不改房间布置。
- **像素探针**：次卧左窗洞侧壁在21个相机位置、11个深度采样点上，修复后不得读到窗框色（红）；修复前应能读到。
- **工程**：`npm test`、`npm run typecheck`、`npm run build:production`及自动发布校验通过；实际首屏 JS（含必需异步）≤3 MiB，完整发布≤41 MiB，运行素材/GLB预算不变。
- **浏览器**：正常流程无运行/着色器错误、警告或404；六窗近景截图完整保存。固定相机/截图只作画面证据，不用于推断 FPS 或加载速度。

## 7. 风险与遗留

- 像素探针以次卧左窗洞为最不利代表，六窗几何由单元测试统一约束；其他窗的完整视觉验收以六窗截图为准。
- 修复前/后的室外海面是动画共享资源，普通截图在窗外像素上会有帧间差异；交接面判断以调试材质和固定相机探针为准。
- 压条现在为平直盒，埋入墙内不可见；全景半透明墙下其轮廓与旧倒角盒有极小差异，未观察到画面回退。
- 本轮只处理窗框/墙洞交接的深度冲突，不改变窗框造型、窗帘遮挡或室外景观；未恢复已暂停的FPS/加载耗时实验。
