# 入口自动关门、灯塔两层改造与子项目二步骤四

状态：已完成（工程与Chrome生产浏览器验收）。创建/更新2026-10-21，基线`384d919`。依据[资源原则](../resource-optimization-principles.md)、[灯塔垂直梯](2026-10-19-lighthouse-vertical-ladder.md)、[原内部方案](2026-10-18-lighthouse-interior.md)、[减量方案](2026-10-20-lighthouse-focused-experience.md)和[子项目二](2026-10-20-lighthouse-project-02-equipment-and-maintenance.md)。本次用户明确授权步骤四，从待选转为实施；四组复杂操作不随存档恢复为玩家入口。

## 背景和目标

住宅/灯塔入口常被遗忘关闭；灯塔进门易卡住，五站爬梯过于繁琐。用户要求开门10秒后自动关闭，稍增塔径、保持总高并减少为两层，然后完成子项目二步骤四。

## 方案与取舍

1. 住宅入户门和灯塔入口门完全打开后累计10个活跃现实秒再关闭；计时复用交互更新，不设setTimeout。暂停/后台不累计。保留现有门扇全步扫掠防夹，堵住时等待让开后继续，手动反向/再打开重置计时；室内房门和阳台门保持原交互。
2. 塔身基部半径2.8→3.4米（直径5.6→6.8米），总高20米及顶部灯室地坪高度保持；移除三个中间楼面，仅首层和顶部灯室，垂直梯只设两站。原三扇外窗作为采光窗保留，不再标为独立楼层。
3. 同步实体壳/内衬/台阶/门槛/门扇和实际碰撞。入口可行宽度0.96→1.20米。NullEngine实测外侧一米开门会在42.9%处触发旧外扫防夹，故灯塔门改向宽敞内侧开启，住宅开门方向保持；移动梯井避开入门直行区域，维护柜/工作台和电池柜向外布置。顶部灯室、外廊、屋顶等水平尺寸协调加宽，灯具本体和总高度不缩放；地图、标牌、提示及素材来源说明与两层布局同源。
4. 步骤四保留六组日常玩法：保护面每三值守日、太阳能面板每五值守日到期清洁，按真正自动日界线触发，手动选时/读档不补算。到期会改变真实表面/功率并更新修订，旧证据不冒充当前检查；完成清洁后仍需复查，历史记录保留最近七日。周期为游戏参数，不是现实维护标准。
5. 单一本地存档槽，明确“保存值守/继续值守”，置于首层面板和记录夹。保存版本、连续小时/日序、主备/能量/燃料/备件、证据、维护期限及日志，不保存网格、相机和进行中动作；不在动作开始扣料，恢复只能看到已提交事务。新会话仍默认正午自动；明确继续后按原步骤四约定暂停时间，界面提示T菜单恢复。
6. 各纯模型提供显式导出/校验恢复，统一存档模块完成版本/大小/字段范围/枚举/交叉一致性校验，全部通过后一次替换会话；不写私有字段、不把连续时刻取整到三小时。设备、太阳能/日程和天空同步，不重放跨日、不补扣离线消耗。损坏/未知版本不静默覆盖，明确提示并提供清除异常存档；新会话可继续游玩，写入失败也保留当前会话。
7. 当前模块维修/补给事务已有中断不扣和一次提交保护，步骤四将其库存/修订/燃料及证据一起持久化并验证读档不会重扣、补给或伪造复验；不恢复四组备选玩家按钮。天气/随机机制和子项目二步骤五仍为后续范围。

4. 独立生产托管检查住宅/塔门延时关闭与防夹、真实多次进出、两站上下/外廊、三项巡检、到期、存读档和故障存储路径；核对根/子路径全部文件、首屏JS、来源和预算。
5. 更新原方案、索引、CHANGELOG及证据，提交推送。

## 验收与约束

- 门：9.9秒不关、10秒开始关闭；手动反向和重开、暂停冻结、上下层高度隔离、玩家位于扫掠区不被推挤或穿过。
- 空间：实体高度保持，只有两个可站楼面/梯站和对应地图/标牌；正面及偏心直行进出无需反复修正，闭门/侧墙/梯井/护栏仍阻挡，车辆不能入塔。
- 维护：仅自动跨日到期一次；清洁不重复、修订后旧证据失效、清洁后独立复查和七日历史。
- 保存：连续时刻/日序/能量/库存/期限/证据/日志一致，读取暂停、取消中间动作不扣料；空档/损坏/未知版本/非法值/跨模型矛盾/存储拒绝不覆盖原数据或破坏当前会话。
- 工程：npm test、typecheck、开发/生产构建、自动发布检查，四项字节预算不变，不引入总入口、新依赖/外部素材或独立计时器。新增源码/发布字节实际记录，不推断FPS或加载收益。
