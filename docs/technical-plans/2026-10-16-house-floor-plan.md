## 背景与现状

已有书房 X/Z=-20～20、客厅 X=20～54 / Z=-20～20，以及 X=20 / Z=-5 的连通门。书房北侧原装饰门尚不可通行。用户需要完整户型作为后续房间生成的依据，并在画布右下角提供小地图，点击在浮层中查看大地图。本轮仅制作二维布局与交互。

## 目标与范围

- 最终采用无独立过廊的客厅中心布局：入户门位于东侧，开门直接进入完整客厅，内部不再保留原横向过廊及其分隔墙。西北为主卧、西南为次卧，北侧为小书房和厨房，南侧客厅连接阳台。
- 主卧 5.4×4.8 m（25.9 m²），较初稿 20.2 m² 扩大约28%；书房 3.0×3.4 m（10.2 m²），取代初稿不合理的64 m²书房。次卧5.4×3.6 m、厨房2.4×3.4 m、客厅5.4×7.4 m、阳台5.4×1.5 m。
- 主卧南侧并排布置主卫2.4×2.4 m和公卫3.0×2.4 m。主卫仅从主卧进入，公卫位于主卧外并直接面向客厅。主卧、次卧、书房和厨房均直接连接客厅，不通过其他私人房间。
- 房间尺寸为本轮最终规划，尚未改造已有三维房间。地图仅按已有场景所在的书房/客厅高亮定位，不显示会产生误导的精确位置/朝向点。现有场景内容与未来尺寸明确区分。
- 大图展示八个房间的房名、长宽、面积、门洞/开门方向、朝向、比例尺及已有内容/规划内容图例；小图突出位置关系。小屏提供可滚动的尺寸清单。
- 查看大图暂停场景输入、运动交互并释放鼠标。按钮/ESC 返回保持相机位置与朝向，沿用物品查看的锁定恢复和失败重试路径。桌面和横竖屏均可使用。

## 方案及取舍

1. TypeScript 维护唯一的米制矩形和门连接数据，SVG 按统一比例生成大小两图，不引入图片、依赖或 Babylon 运行注册。后续建房以这些规划数据为准，实际几何尚不在本轮范围。
2. 浅苔绿表示书房/客厅已有内容，不表示其三维尺寸已调整；米白斜线表示待生成内容。全部门洞为规划开口，三维壳体、家具、原门和碰撞保持原状。标注未扣墙厚，阳台按完整地面面积计入。
3. 原生 dialog 实现大图、焦点隔离与返回；地图不新增相机/引擎，不改变场景视角或传送。复用现有输入协调并将两种查看状态都纳入暂停判断。
4. 右下角地图独占空间，原视角条移至底部左侧并限制宽度；小屏缩小地图、视角条水平滚动，避免覆盖与无法点击。
5. 不改素材、白名单或预算。检查实际首屏 JS（包含必需异步及音频预热）、完整发布与独立托管；不进行 FPS/加载耗时实验。

## 方案调整记录

初稿为保留原三维两房尺寸，采用14.8米横向过廊、64平方米书房和20.2平方米主卧。用户指出不符合常见户型，要求入户直接进客厅、缩小书房、扩大主卧，并明确双卫的私用/公用归属。实施中据此替换初稿：取消过廊而非只隐藏其名称，采用10.8米宽、10.8米室内进深的紧凑布局，阳台另向南延伸1.5米；将书房移到北侧，使卧室和书房都有外围采光面。已有三维房间尺寸不再强行限制新的户型规划，定位改为房间高亮以保持语义准确。

## 实施步骤

1. 建立方案和索引，确认现有布局与输入、物品详情实现。
2. 定义户型数据、比例 SVG、房名/尺寸/开口/图例，制作小图与大图界面。
3. 接入环绕区域/第一人称房间高亮，模态暂停、Pointer Lock 和恢复/清理。
4. 检查几何不重叠、所有房间连通、入户直达客厅、缩小书房/扩大主卧及双卫访问归属；浏览器检查地图、键鼠隔离、原姿态恢复、移动和横竖屏以及信件/设置回归。
5. 执行测试、类型检查、开发/生产构建及发布校验；保存截图、请求字节与交付记录，更新结果、索引和日志，提交推送。

## 验收方法

- 户型按比例、尺寸一致，八房不重叠；无独立过廊，入户门直接连接客厅；主卫只从主卧进入，公卫从客厅进入。所有房间可从入户到达，新增/调整仅存在于地图。
- 大小图共用数据，当前三维场景所在书房/客厅高亮正确，不将旧几何位置误标进未来主卧或其他规划房间。尺寸和面积采用新规划，已有内容标记不冒充已改造。
- 点击小图/键盘打开大图，返回按钮/ESC 关闭；Tab 留在 dialog，地图输入不移动场景，第一人称关闭恢复位置且锁定失败可重试。查看信件时隐藏小图，避免模态嵌套。
- 全部工程检查通过，独立托管无新增错误/404，实际首屏 JS ≤3 MiB、完整发布 ≤41 MiB，运行素材摘要保持一致。

## 实际结果

- 按用户反馈完成第二版布局：八个房间均为按比例的独立矩形，无过廊房间或横向隔断；东侧入户门直接通客厅。主卫只连接主卧，主卧外公卫只连接客厅，其余房间直接通客厅。图示规划地面面积为124.7 m²（含阳台8.1 m²），未扣墙厚。
- 右下角小地图、点击/M快捷键打开的大图、返回按钮/ESC、焦点限制及横竖屏尺寸清单完成。书房/客厅按实际所在房间高亮，不把新规划坐标冒充旧场景的精确位置；原三维几何、门、家具和碰撞保持原样，后续按此图调整尺寸和生成内容。
- 63项测试、类型检查、开发/生产构建与自动发布校验通过。几何/连接测试覆盖不重叠、门洞边界、入户直达客厅、主卧扩大/书房缩小、主卫独享和公卫外部访问；Chrome检查桌面、390×844、844×390和320×568布局、键鼠隔离、Tab焦点、第一人称原姿态返回、锁定拒绝/点击重试以及重复开关无资源增长。
- 原有八抽屉、三灯、连通门/碰撞、视角/缩放、第一人称、设置和Inspector回归通过；信件查看的模态隔离、返回/横竖屏也通过。未新增素材、依赖、Babylon注册、相机或三维房间；网格145、材质64，与基线一致。
- 独立托管最终dist，488个发布文件逐个GET/SHA256核验通过；30个运行素材的字节与摘要不变。静态与实际首屏JS（含必需异步及音频预热）满足3 MiB预算，完整发布约40.01 MiB满足41 MiB预算。浏览器无运行/着色器错误或404，构建保留三类既有建议告警。
