# ESC 往返自由探索与远景

状态：已完成（用户复测后补修，真实 Chrome 系统按键验收）。创建及更新：2026-10-23。输入基线：`3dc759d`，本轮复查基线：`908ee13`。相关方案：[岛屿远景与视角入口](2026-10-22-island-overview-and-beacon-timing.md)、[现场界面](2026-10-20-lighthouse-focused-experience.md)。遵循[资源与首屏优化原则](../resource-optimization-principles.md)及[游戏文案规范](../game-writing-guide.md)。

## 背景与现状

玩家在灯塔附近按 ESC 后退出第一人称到岛屿远景，必须点击“自由探索”才可返回。键盘处理仅调用 `leaveFirstPerson`，反向入口缺失。现有 `setView("first-person")` 已能恢复步行位置、朝向或骑行/爬梯状态，并请求鼠标锁定。

## 目标与范围

- 没有弹窗且场景控制可用时，ESC 在远景和第一人称之间往返；复用现有视角切换及位置恢复。
- 地图、物品查看、设备、故事、设置和时间菜单继续优先处理 ESC；失焦、调试暂停和输入控件不触发视角切换。
- 忽略长按重复事件、输入法组合及已有修饰键拦截，避免一次长按反复切换。
- 在远景操作提示和画布辅助说明中补充“ESC 自由探索”。不改存档、剧情文字、素材、引擎注册或依赖。

## 方案与取舍

在 `RoomScene.keyDown` 的既有界面/暂停/输入过滤之后增加双向分支。保留浏览器 `pointerlockchange` 退出回调的单向职责，避免退出鼠标锁定时自动重新进入第一人称。原按钮和 `setView` 是统一入口。

鼠标锁定仍由浏览器授权；默认 ESC 解锁可能由浏览器消费，不一定产生页面 keydown。复验原生按键及失败后点击画面恢复的既有路径，不通过伪造鼠标锁定状态绕过限制。参考 [Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)。

## 实施步骤

1. 修改双向 ESC 分支与远景操作提示，保留所有弹窗优先级。
2. 用最终生产包在浏览器检查新会话、灯塔附近原位往返、长按、菜单/地图/故事及输入焦点；覆盖鼠标已锁定和未锁定路径。
3. 全量测试、类型检查、开发及生产构建/发布校验；仅托管 dist，测量含必需异步 JS 的首屏并核对预算。
4. 记录实际结果和边界，同步索引/变更日志，提交并推送当前分支。

## 验收方法

- 连续独立按 ESC 可进出第一人称，按钮选中、相机、地图和提示一致；灯塔附近往返后位置/朝向保留。
- 重复 keydown 不再次切换；输入法组合、修饰键、输入框及暂停不进入探索。
- ESC 优先关闭当前界面，该次按键不额外切换底层视角；原按钮与点击画面锁定仍可用。
- 四项预算、完整发布分包和来源说明保持；记录浏览器运行错误、404 和已有告警，不宣称加载/FPS 收益。

## 实际结果

ESC 已双向复用 `setView`，保留位置、朝向、按钮状态和原鼠标锁定逻辑；浏览器退出锁定的回调仍只退出第一人称。长按重复、输入法组合、修饰键、输入控件和暂停过滤保持。

Chrome 155 最终生产包检查新会话 ESC 进入、浏览器 ESC 退出、灯塔附近三次往返原位/朝向恢复、长按，以及设置/时间/地图/故事优先级；原生 ESC 均成功恢复鼠标锁定。第一人称地图关闭不额外切换视角；根路径与 `/home/` 入口均通过。1280×800 与 390×844 无页面溢出，手机沿用隐藏底部操作说明的既有样式。未复验其他浏览器或实机。

## 用户复测与补修（已完成）

用户反馈按ESC仍未返回第一人称，必须点击“自由探索”。已只读核对本地8080开发服务，确认包含双向分支，不能归结为代码未更新。真实Chrome系统按键已发现与先前无头自动化不同的鼠标锁定表现：视角切回后仍提示点击画面开始环顾；具体是否还会再次退回远景，继续跟踪原生按键、锁定变化及焦点路径，不先认定原因。

本轮先做最小诊断，再修正复现路径。验收增加有窗口Chrome系统ESC、快速连续往返、按住/松开、锁定失败及失焦/恢复；不以CDP按键的单独成功代替原生路径。维持弹窗优先级、位置/朝向和既有四项预算。

### 实际修改与原生验收

补修将场景快捷键移到文档捕获阶段，避免在画布/相机冒泡处理之后才收到；有弹窗、暂停或输入控件时仍先让出处理。进出视角均主动把焦点放回画布。另一个已确认的问题是：原代码只有锁鼠成功才给第一人称挂接普通输入，真实Chrome的ESC重锁失败后不能走动，玩家因此需要再次点击“自由探索”。现在普通相机输入可在未锁鼠时使用，WASD立即可移动，暂停/弹窗依旧禁用；车辆和爬梯的既有保护保持。

**纠正上一轮验收边界**：上文的Chrome155结果来自无头Playwright/CDP按键，它不能证明系统ESC会恢复鼠标锁定。真实Chrome确实可能拒绝ESC作为重锁手势，此时仍提示“点击画面开始环顾”，点画面可恢复锁鼠；本次不宣称绕过浏览器授权或保证无需点击就重锁。诊断阶段曾观察到一次按键后维持远景，但未把它伪写为已证实的单一浏览器原因；本轮增加捕获路由与焦点保护，以最终原生多轮结果验收。
