# 灯塔天气步骤四 完整保存恢复与演练隔离

状态：已完成（工程、Chrome现场及Chrome/WebKit天气回归）。创建及更新：2026-10-22。输入基线：`1533c6e`，包含天气步骤三与新夜间光束；[天气总方案](2026-10-20-lighthouse-project-03-weather-and-uncertainty.md)步骤四是[三天代班剧情](2026-10-21-lighthouse-three-day-story.md)正式存档的前置。本次只完成此步骤，不实施故事章节或步骤五平衡。

## 背景与现状

版本1只保存设备、Wh、库存、时刻和纸质文字。天气序列、过渡、风险余量、问题实例、随机流、薄膜潜伏阶段和访问缓存重建，读档会丢失当前隐患和先前检查的随机结果。现有固定天气直接改当前会话，尚无独立种子复现与存档隔离。

## 目标与范围

- 版本2完整保存天气序列/过渡、精确接受小时及补偿、五分钟风险余量、部件状态/问题/冷却/有界历史、四随机流、当前薄膜、线索与访问缓存、实际设备及时间。
- 全量验证后原子替换会话，继续先暂停，不结算离线时间、不重抽问题、不追加自动事件。保存不包含未完成现场动作，已提交事实及缓存保持。
- 正常值守沿用原本地键以兼容版本1。首次明确继续旧槽时，保留设备与历史，一次性初始化天气/线索并先写入版本2，再应用；失败时保留原槽和当前会话。只查看状态不消耗随机或迁移。
- 正常值守和独立演练分别保存；从正常选择固定天气时保留正常会话并进入独立副本。可输入uint32种子重开演练，自动天气也可在演练中复现。返回正常会话恢复原进度并先暂停，演练不覆盖正常存档。
- 无效、未来版本、跨模型矛盾和写入失败不静默重置。保留旧低层版本1编码能力供历史夹具/兼容测试，所有玩家保存写版本2。

## 方案与取舍

为天气序列、能见度和风险模型添加严格检查点接口；恢复时直接重建保存字段，不通过构造器重新抽取天气。随机流算法保持。天气/风险原始计数使用精确值，显示用的舍入快照不作为恢复源。

设备模块保留原版本1字段解析，版本2增加扩展数据恢复薄膜、天气请求及已记录线索编号集合。共用事实映射恢复检查认识，当前缓存校验绑定真实实例/修订；历史证据继续标记过期。加载时不把新的相机位置立即视为一次离开，首次恢复有效活跃帧后再按实际区域更新访问；离开时长仍只计自动小时，避免“加载到首层即重抽”，同时允许关闭自动时间后正常走近检查。

旧槽迁移按原版本1语义恢复已存污损，使用新种子建立一次天气会话。迁移只在成功写入后生效，旧档没有的过去天气与隐患不追算。跨日、手动选时与天气接受时钟分别验证，不假定自动小时和当前钟面总是线性对应。

演练入口沿用时间菜单。切换前结束未提交动作，当前已提交状态存入内存检查点；玩家明确保存才写对应本地槽。固定天气首次进入副本保持当时设备，按种子重开则新建完整独立初始会话。刷新后的默认新值守及“继续”行为保持明确，原槽不因进入演练自动覆盖。

## 验收方法

同一有效命令序列，连续运行与中途保存/恢复的天气、问题、随机抽取计数、缓存及Wh相同（能量按既有浮点容差比较）；不因检查窗口、刷新或读档多抽一次。覆盖进入雾的过渡和恢复迟滞、非整步长、两次漏检、修订失效、薄膜至显性、维护与严重问题冷却、重复加载和进行中动作不提交。

验证版本1仅在成功写入版本2后替换、重复继续不再换种子、未知/损坏/超限/非法随机计数/时间和跨对象证据拒绝、失败不破坏原槽；正常/演练切换和刷新均不串槽，种子边界0及4294967295有效。

保留[资源原则](../resource-optimization-principles.md)预算：目标GLB4.25 MiB、运行素材16 MiB、含必需异步首屏JS3 MiB、完整发布41 MiB。输入包实际首屏3,062,443 B、完整发布42,510,439 B；不新增素材/依赖/灯/几何/相机。浏览器按实际初始及必需异步请求测量，完整目录含全部动态分包及说明；不做FPS或加载耗时结论。
