## 1. 背景与现状

当前八个时段已统一控制日月主光、天空渐变与光盘、海面、窗光及环境照明，默认正午，支持1.2秒手动过渡、0.2秒减少动态效果过渡和24分钟自动循环。天空尚无云层和星点，因此白天空旷、夜空缺少细节。

代码中可直接利用的基础：

- [CoastalSky.ts](../../src/examples/CoastalSky.ts)通过现有 `ShaderMaterial` 输出线性天空颜色，`applySkyTime` 统一传入时间参数，支持裁切和镜面反射眼位。
- [CoastalOcean.ts](../../src/examples/CoastalOcean.ts)引用相同 GLSL，但当前海面反射与海雾均调用 `coastalSkyGradient`，没有直接调用包含光盘的 `coastalSkyRadiance`。扩展时须区分天空细节、反射与海雾，不能把星点直接加进所有渐变采样。
- [RoomExterior.ts](../../src/examples/RoomExterior.ts)已有一个天空球；[RoomMirrors.ts](../../src/examples/RoomMirrors.ts)已有两张512²局部镜面目标及可见刷新门控。
- [RoomTimeOfDay.ts](../../src/examples/RoomTimeOfDay.ts)的手动切换保存并混合已显示快照；混合过程的 `hour` 不是按时间顺序播放的真实中间时刻。新参数需要随快照混合，避免正午切午夜时误播黄昏、星点瞬间开关。

本方案扩展原昼夜功能的天空表现，保留原四阶段记录，不将原方案未包含的云、星记为已交付。唐宅尚未实施，本次不涉及其设定档案。

## 2. 目标与范围

采用“疏朗白云、克制星点”的晴朗海岸风格，让天空有层次，同时保留现有海天色彩和道路可见度。

1. 白天为不规则、边缘柔和的薄积云，大小疏密有变化，保留大面积蓝天。可见上半球云覆盖率初定15%～25%，这是调图目标，不代表气象测量。
2. 清晨与黄昏让朝向太阳的云缘少量染成淡金、粉橙，背光处偏灰蓝；正午以暖白和浅灰为主，避免纯白剪影和整片乳白色天空。
3. 夜晚出现固定分布、亮度有层次的细小星点；月亮附近及地平线附近更少、更淡。夜云保持低对比蓝灰，云后星点受遮挡，晴空区域仍占主体。
4. 八节点、任意连续小时、快速改选、跨午夜、暂停和恢复均连续；同一片天空在住宅、窗边、步道、塔区及镜面中方向一致。
5. 首版固定云形和星位，通过时间改变颜色、亮度与可见度。云层漂移、星点闪烁、银河、流星、星座标注、天气切换和云影不在首版范围；无需新增菜单。

## 3. 八节点视觉目标

星点权重是美术初值，须结合现有曝光与天空亮度在浏览器中校准；不修改日月角度、主光强度或环境照明来放大天空细节。

| 时间 | 云层表现 | 星点目标权重 | 视觉重点 |
| --- | --- | ---: | --- |
| 00:00 午夜 | 很淡的蓝灰云形，晴空为主 | 1.00 | 星空最明确，月亮周围自然减弱 |
| 03:00 后夜 | 暗蓝灰，东方低空随既有晨光变淡 | 0.90 | 星点保持，后续随晨光连续退去 |
| 06:00 清晨 | 白灰云体、东侧淡金粉云缘 | 0 | 不残留白昼星点，保留东方晨色 |
| 09:00 上午 | 清爽白云、轻微灰蓝底部 | 0 | 蓝天和白云清楚分离 |
| 12:00 正午 | 全天最清晰的白云层次 | 0 | 约15%～25%覆盖，保留太阳与海面细节 |
| 15:00 午后 | 略偏暖白，西南侧云缘受光 | 0 | 与上午保持相同云形、不同受光 |
| 18:00 黄昏 | 西侧淡橙粉云缘，背面偏冷灰 | 0 | 日落后星点再逐步显现 |
| 21:00 入夜 | 低对比蓝灰云形 | 0.70 | 星星清晰但不盖过月亮和住宅暖灯 |

## 4. 技术方案与取舍

### 4.1 推荐：扩展现有天空着色器

在现有天空球的片元着色器内计算云层和星点，复用共享天空函数向海面提供反射。固定种子和参数写入源码，无新增下载素材、网格、材质、纹理、灯、相机或RTT，也不增加粒子系统。

| 备选 | 优点 | 代价与选择 |
| --- | --- | --- |
| 现有天空材质内程序化云与星点 | 与时段、镜面、海面共享方向和参数；无新素材请求 | 增加片元计算；作为本方案首选，需实际画面与兼容性验收 |
| 云图 / 星空图叠加 | 美术形状容易直接控制 | 增加素材、来源记录、解码/显存成本，需处理接缝和过滤；首版不选 |
| 体积云 / 独立粒子或星点网格 | 可增加更强的空间和运动效果 | 引入额外几何、通道或采样复杂度，超出“一些白云和星星”的首版需求 |

`ShaderMaterial` 可直接使用源码字符串、显式声明 uniform，并通过 `setFloat/setVector3` 更新参数，见 [Babylon 官方说明](https://doc.babylonjs.com/features/featuresDeepDive/materials/shaders/shaderMaterial/)。实际导入与注册以项目锁定的 Babylon 9.30.0 和已有 pure 路径为准，不引入 Babylon Lite 或新的材质包。

### 4.2 白云：连续方向上的固定密度场

- 以世界朝向的归一化观察方向 `d` 为输入，在三维方向域取固定种子的低频噪声，初定3层尺度叠加。采用连续方向域避免经纬贴图的左右接缝和天顶拉伸；噪声函数统一使用 `coastal` 前缀，避免与海面已有 `hash/noise` 重名。
- 通过密度阈值和软边形成若干大小不同的云团，少量细尺度只用于轮廓，控制覆盖率；不将一层均匀噪声铺满天空。地平线附近逐步减弱细节并融合雾色，天空下半球云层为零。
- 云体采用暖白亮部、浅灰蓝暗部和柔和过渡，结合太阳方向给临近日出/日落方向的云缘局部暖色。云色以线性空间混合，由既有后期统一处理，曝光仍为1.12。
- 云形在八个时段保持不变，夜间只降低云体亮度与色彩反差；云密度同时用于遮挡星点和局部削弱日月光盘。主光、地面照明与投影继续沿用原晴天近似，不新增随云变化的阴影或全局明暗起伏。
- 这是天空背景中的薄云表现，不能写成有真实厚度、体积散射或真实云影的模拟。白云即使经过太阳方向，也不应长期遮住全部光盘或形成满天阴云。

### 4.3 星点：固定分布与像素过滤

- 在上半球使用连续的等面积方向映射，例如 `q = d.xz / sqrt(1 + d.y)`；仅在 `d.y > 0` 区域采样。它把上半球映射为单位圆盘，不使用经度接缝或天顶奇点。
- 将圆盘划成稀疏网格，用固定种子确定候选星点的单元内偏移、亮度和轻微冷暖；检查相邻单元，避免星点在网格边界被截断。上半球候选数量初定250～400颗，实际视角中的可见数量取决于视场、遮挡与亮度，不要求每张截图出现固定数量。
- 大多数为细小、偏弱的暖白或冷白点，少量更亮；1280×800、DPR1下以约1～2像素的软点为初始目标，放大视角也保持角尺度。避免十字光芒、大光斑、均匀点阵和满屏白噪声。
- 根据方向映射的屏幕导数确定采样足迹，在连续坐标上求导后再做单元运算，用软核和能量补偿处理亚像素星点；DPR变化、转头与缩放不能导致成片跳闪或星点不断增亮。导数计算不要放入非一致片元分支。
- 太阳高度初定−4°至−12°之间平滑显星/退星；这是与现有美术日轨匹配的可调阈值，不是当地天文结论。再叠加地平线淡出、月亮附近抑制和云密度遮挡；日间权重严格为零，下半球严格为零。
- 不随相机旋转重新随机，不使用墙上时间或每帧随机数。转头看到的是同一片星空；21→00→03保持星位，刷新/重建时固定种子重现。首版不模拟恒星周日运动。

屏幕导数能力遵循 [Khronos WebGL 标准](https://registry.khronos.org/webgl/extensions/OES_standard_derivatives/)：WebGL1需相应扩展，WebGL2中为核心能力。当前海面与饰面已使用导数；天空新使用时仍须核对声明、引擎能力和实际编译，不能以已有材质通过代替新路径验收。

### 4.4 时间模型：新增视觉值随快照混合

在时间快照的天空视觉数据中补充云色/明暗、星点权重及必要的月亮抑制方向等结果；固定密度、种子和候选分布作为配置，不随时间重建。字段名称在实施时统一，避免天空和海面各自再求一遍时段。

- 连续求值时，根据太阳高度、节点权重和线性颜色得到视觉值；节点之间连续，23.999→0无断点。
- 手动切换时，直接混合“已显示快照”和目标快照中的视觉值，不能在混合结果的 `hour` 上重新调用显星门控。否则1.2秒正午→午夜可能突然显星，快速改选也会回跳。
- 月亮附近的抑制使用明确的月亮方向和可见强度，不能借当前 `primary` 误把太阳当成月亮；日月换源时遮挡/抑制也要淡化，不能制造黑洞扫过天空。
- 新参数走既有 `applySkyTime` / `skyTimeUniforms`，同批传给天空和海面；沿用自动最高10Hz、手动逐帧的视觉更新、暂停原因和停止后精确补齐。若连续画面暴露步进，先记录证据并在方案内说明调整，不独立增加一只时钟。
- 减少动态效果时仍使用0.2秒淡化，首版没有额外云漂或星闪动画。菜单、地图、详情、失焦/隐藏及释放语义沿用现状。

### 4.5 海面、海雾、镜面与环境反射

把共享计算职责明确分开，保留现有渐变接口的纯净用途：

| 路径 | 目标 |
| --- | --- |
| `coastalSkyGradient(d)` | 保留低频天空和朝向暖色，供海雾使用；不含星点、云团边缘或光盘 |
| 天空背景计算 | 渐变之上添加星点与日月光盘，再按云密度合成云色；只执行一次既有色调映射 |
| 海面反射计算 | 使用相同方向域、云形和时间参数；根据反射方向足迹与现有水面粗糙度低通过滤，不照搬清晰星点/光盘 |

海面现有GGX已负责日/月高光，因此新的反射函数不再额外加入光盘，避免重复亮斑。白云可以形成柔和、随波破碎的浅色反射；星点默认在粗糙水面上过滤为极弱贡献，不要求每颗星都有倒影，不产生闪烁亮粒或白色光带。海雾仍使用纯渐变，不能把星点和白云投到海天雾带上。

室内双卫镜面继续反射实际场景，保留镜像眼位和裁切 include，不为新天空增加RTT或关闭既有门控。无真实窗洞、墙后及不应见天空的位置不能穿出云星。中性室外HDR与原室内IBL保留为低频近似，家具/车体不新增精确云星反射，也不因此改变房屋照明。

## 8. 风险与处理顺序

- **云变成雾墙或遮天**：先降低覆盖阈值、细噪声和不透明面积，保留明确蓝天；不通过提高曝光补救。
- **星点转头闪烁 / 接缝**：先检查连续映射、邻域与屏幕足迹过滤，再调整亮度/半径；不以关闭星空或放大成亮斑作为完成。
- **海面闪粒 / 雾带污染**：区分低频渐变和细节反射，增大粗糙度对应过滤足迹；保留原GGX主光高光。
- **新着色器兼容失败**：核对导数声明、GLSL变量命名、pure注册和裁切/镜像路径；旧NullEngine测试不编译实际GPU程序，必须有浏览器编译证据。
- **增量超出目标或画面仍不稳定**：先减少冗余噪声层、共享函数和无用分支；仍不足时在本方案记录证据与替代选择，不能直接提升预算或跳过检查。
