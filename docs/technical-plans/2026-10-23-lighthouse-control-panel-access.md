# 首层运行面板位置与点击可达性

状态：已完成（工程与 Chrome 生产浏览器验收）。创建及更新：2026-10-23。输入基线：`3dc759d`（工作区已含 ESC 往返修复）。相关方案：[两层布局](2026-10-21-lighthouse-two-levels-and-save.md)、[现场界面](2026-10-20-lighthouse-focused-experience.md)、[设备工作台](2026-10-22-device-ui-workbench.md)。遵循[资源原则](../resource-optimization-principles.md)。

## 背景与现状

运行面板位于西侧维护柜上方，向塔心的操作方向与垂直梯重叠，正面视线受梯子遮挡。鼠标主键在梯口接近范围内优先上梯，进一步压缩面板可操作的站位；用户只能从侧面反复找目标。

## 目标与范围

- 将面板及其旋钮作为整体移到入口右侧空墙，朝向塔心，让玩家可正面靠近；与梯口、电池柜、充电控制器和门扇扫掠区错开。
- 适当增大实体可点击面，整块面板和原旋钮继续对应同一稳定交互 ID。不添加穿墙或超距点击，不改六组命令权限、存档和梯子操作。
- 采用共享布局数据，继续复用原材质/批次，不增加下载素材、灯光、依赖或相机。

## 方案及取舍

在 `LIGHTHOUSE` 登记面板的径向安装位置、朝向及尺寸，程序几何直接读取。候选中心为塔内局部 `(2.4, -1.8)` 米，面板厚0.14米、宽0.84米、高0.74米，中心离首层地面1.5米；正面朝塔心。背面接入弧墙，正面站位距板约1米，避开西侧梯口。

保留主键近梯上梯的既有行为，通过移出梯口操作区解决本次冲突，不扩大到全场景输入改造。工作灯开关仍留在维护柜，原 ID/位置保持。

## 实施与验收

1. 更新布局、面板/旋钮程序几何及来源说明，保留稳定 ID。
2. NullEngine 核对正面及两侧站位可走、不会上梯，面板3×3取样均可拾取；墙体与距离限制保持。
3. 仅托管最终生产包，在实际第一人称用原生主键单击验证正面与偏侧位置、完整面板和旋钮；核对进门/梯口通行及手机/桌面近景。
4. 全量测试、类型/开发/生产构建和发布校验，核对含异步 JS 的首屏预算及完整发布根/子路径文件，更新方案/索引/CHANGELOG 后提交推送。

## 实际结果

已采用候选径向位置与尺寸，背面接入弧墙、面向塔心；面板和三个控制块继续属于 `lighthouse-control-panel`，维护柜照明开关留在原位。未扩大射线授权或添加不可见点击盒，面板实体正面面积由0.48×0.64米增为0.84×0.74米，约2倍。

- 几何检查：三处正面/偏侧站位和3×3面板网格共27条射线均可触发同一动作；所有站位可走且不在上梯触发区，入口至操作区采样畅通。墙体遮挡和原1.5米命令距离保持，更新旧面板测试夹具。
- Chrome155最终生产检查：三处站位分别点击中心、左上、右下和控制块，共12次原生主键单击均打开运行面板，未进入梯子；ESC正确关闭并保留第一人称。1280×800与390×844近景已检查，无需侧身挤在梯旁。测试在关闭面板后等待180ms让浏览器锁定事件结清，再点击画面恢复环顾；不将刚关闭界面后的首次锁定点击计为设备点击。
- 全量395测试、类型/开发/生产构建及发布校验通过，36项运行素材不变，四项预算保持；详见[联合验收证据](assets/player-controls-2026-10-23/README.md)。没有进行FPS/加载耗时实验，未重跑全程住宅步行至灯塔或实机测试。
