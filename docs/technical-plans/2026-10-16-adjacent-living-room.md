## 背景与现状

书房范围为 X/Z ±20、地面 Y=-5。右侧墙与天花、前墙只在第一人称启用，步行位置被限制在原房间内。用户要求在隔壁增加客厅，由开发确定布局，装修风格与书房一致。保留书房家具、抽屉、灯具与信件查看。

## 目标与范围

- 在书房右侧 X=20～54 增加 34×40 客厅，地面与层高保持一致；共享墙 Z=-9～-1 留出宽门洞，通道连接两房且不与原家具冲突。
- 延续暖砖、胡桃木护墙、黄铜线脚、苔绿/米色织物及暖色灯光。客厅以三人沙发、双扶手椅、茶几地毯组成会客区，背墙布置装饰壁炉、画作和陈列柜，增加窗帘、绿植和边几灯。
- 增加双房全景、书房和客厅预设；第一人称从当前房间进入，能通过门洞往返；封闭壳体、移动边界和碰撞覆盖客厅。
- 复用已有贴图、画作和程序家具，不新增下载素材或依赖，不改变已有 4.25/16/3/41 MiB 预算。

## 方案及取舍

1. 客厅采用独立组合模块，复用家具几何与材质工具，按区域/材质合并静态网格并保留碰撞分区。柔软座垫、实木框架与细小黄铜脚形成和书房一致的家具语言。
2. 共享墙在环绕视角剖开、第一人称完整启用；门洞的墙体、护墙、线脚同步断开，避免仅画出门洞但仍存在隐形碰撞。
3. 两房直接光按区域限定网格，保留书房原三处直接光和环境补光；客厅独立窗光与可切换台灯，缓存静态阴影。继续沿用 SSAO、FXAA、锐化和既有曝光。
4. 壁炉为装饰性炉膛和木柴，不引入粒子火焰/新动画系统。现有森林窗景与画作沿用原来源记录，不扩展其许可声明。
5. 不做 FPS、CPU/GPU 或加载耗时实验；截图及请求字节只作为视觉、功能和预算证据，既有亮屏性能验收继续待完成。

## 实施步骤

1. 建立方案、索引与日志，检查现有几何、合并、灯光和第一人称路径。
2. 完成客厅、共享门洞及封闭壳体，接入分区灯光和预设/步行。
3. 验证门洞往返、实体墙阻挡、家具接触、灯开关及书房回归。
4. 运行测试、类型检查、开发构建、生产构建与发布校验；独立托管检查双房全景、客厅/近景、第一人称、设置和 Inspector，保存实际首屏请求及完整交付摘要。
5. 更新实际结果和文档状态，提交并推送当前分支。

## 验收方法

- 客厅能在全景辨认，近景检查软包、木纹、地毯、窗帘、壁炉及摆件落地/贴合。
- 第一人称通过真实门洞往返；门洞以外的共享墙、外围墙和家具能阻挡，环绕切换不会遗留输入或阴影状态。
- 原书房各视角、八抽屉、两灯和信件详情，以及设置、拖动缩放与 Inspector 继续正常。
- 工程检查及独立托管通过，无新增运行/着色器错误和 404；实际首屏含必需异步 JS ≤3 MiB，完整发布 ≤41 MiB，素材摘要不变。

## 实际结果

- 已在 X=20～54 增加客厅，地面/层高与书房一致；Z=-9～-1 为真实宽门洞，共享砖墙、两侧护墙、踢脚线和线脚同步断开。全屋全景展示两房，保留原书房镜头，新增客厅镜头；从客厅进入第一人称直接落在客厅，ESC 恢复进入前预设。
- 客厅完成苔绿三人沙发、米色双扶手椅、胡桃木双层茶几/边几、波斯纹地毯、黄铜灯具、装饰壁炉/木柴、陈列柜/书本/陶器、挂画、森林窗景/亚麻帘和绿植。全部复用既有纹理与程序几何，无新增下载资源或依赖。
- 家具按客厅区域和材质独立合并，与封闭壳体分开；保留原静态碰撞分区。窗光和台灯使用独立缓存阴影，排除其他房间网格，书房原有三处直接光参数保持不变。客厅台灯可在环绕和第一人称点击开关。
- 视觉检查发现单独批次的窗景/画作仍保留建模父节点，直接重新指定父节点会移动到局部坐标。已改为保持世界变换的 `setParent` 并重新冻结，新增单网格批次与壳体切换回归。客厅天花保留受光、排除不必要的自身投影，消除自阴影条纹。
- 44 项测试、类型检查、开发构建、生产构建与自动发布校验通过。浏览器通过七环绕视角、客厅/壁炉/陈列柜/窗帘近景、原生 WASD 门洞双向往返、共享墙阻挡、家具碰撞、三灯/八抽屉、ESC、锁定失败与重试、设置、拖动缩放和 Inspector 回归；独立信件脚本通过横竖屏、输入隔离及返回/资源清理。
- 独立托管最终 `dist`，462 个文件逐个 GET 与 SHA256 一致，无运行/着色器错误或404；保留三类既有 Webpack 建议告警。18 个运行素材的路径、字节和 SHA256 与基线完全一致，全部动态分包和来源/许可文件仍在交付目录内。
