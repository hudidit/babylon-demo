## 1. 推荐方向

采用**安静、写实、有距离层次的海岛值守声景**。近处能听出木材、金属、玻璃和布料的接触，电驴与灯塔能听出是否在运转，海浪与风雨交代室外环境。声音密度随地点和动作变化，保留安静的阅读与停留空间。

沿用 Babylon Audio V2 和已有音频生命周期，借鉴 FMOD/Wwise 的事件、参数、分组混音和并发管理方法。先把常用动作、持续状态、环境过渡做准确，再补细节；本轮不建议迁移中间件，也不以背景音乐覆盖交互声音的缺口。

推荐开发顺序：**容量与试听小样 → 门和擦拭 → 电驴、海风海浪和雨声 → 脚步、梯子、窗帘及设备细节 → 完整混音验收**。每期可独立交付，但只有电驴与天气阶段完成后，才算覆盖用户本次提出的主要声音场景。

本文的声部、参数范围、素材数量和专项预算是项目设计建议，不是行业统一标准，也不是已实现或已验听效果。

## 4. 玩家听到的层次与路线

| 声音层 | 内容 | 设计重点 |
| --- | --- | --- |
| 手上动作 | 门、抽屉、开关、纸张、窗帘、擦拭 | 起止准确、材质可辨，优先于背景；无效点击不响 |
| 身体与移动 | 脚步、落地、梯子踏步、电驴座垫接触 | 随实际移动而响，不按键盘按住时长制造脚步 |
| 运行设备 | 电驴电机/轮胎、灯塔转台、已有机组 | 运行才响，停机变安静；不凭音效暗示尚不存在的故障或操作 |
| 环境底声 | 海浪、海风、雨幕、屋顶/窗面受雨 | 室外开阔，入屋收敛，进塔略封闭；不同地点有清晰变化 |
| 稀疏细节 | 局部阵风、枝叶、远处海鸟 | P2可选，低密度、有间隔；不成为循环里每隔几秒必响的标记 |

一段推荐试听路线：在家翻纸、开门，室外风浪逐渐清晰；上车后低速电机显现，提速时轮胎与迎风声增加；停车、下车后恢复步行节奏；进塔门关闭，室外高频减弱，近处可听到转台；停机擦拭时布料声位于眼前，中断立即收声；回到屋内遇雨，听到屋外雨幕及轻屋顶声，阅读时整体后退。

首期不加连续配乐、人物配音、虚构无线电人声、船舶或雾号。当前没有雷电事件，风雨不自动配雷鸣；雾本身也不需要专属“魔法音效”。这些若以后需要，应有独立场景/叙事依据。

## 6. 四组关键声音的详细设计

### 6.1 开门与关门

保留现有运动事件，补充门类型、方向及运动程度。把手声可并入起动素材，但不得点击被拒绝时播放。短促开合先用运动片段；运动时间长于片段时使用可平滑结束的短循环，不让素材自带撞门尾音。

门被玩家挡住时，摩擦在20～60 ms内淡出；继续运动时从当前状态恢复，反向不叠两份。关门扣只认关闭端点；没有独立开门撞限位的结构则不加夸张撞击。自动关门与手动关门共用状态规则。推拉门使用轨道与框体声，避免全屋同一个“吱呀”。

门对环境声的影响另由室内外混音计算，不能收到门扣事件就把海风直接静音。窗帘开合也不代表玻璃开闭；当前固定窗不增加不存在的开窗状态。

### 6.2 电驴行驶

电动车的声音主体是轻电机、轮胎和迎风感，避免汽油发动机怠速、换挡轰鸣与强烈赛车声。当前未建立电源开关、喇叭和支架动作，不为这些不存在的动作强加声音。

| 输入 | 拟议听感映射 |
| --- | --- |
| `abs(speed)` / 当前前进上限 | 平滑控制电机音高与轮胎强度；前进0～40 km/h，倒车使用真实低速范围 |
| 有效前进/倒车驱动，结合真实加速度 | 让加速时电机稍突出、松开后减弱；受阻停车时归零，不能按住W就持续高速轰鸣 |
| 实际速度与刹车状态 | 起刹一次轻摩擦，持续制动逐渐变弱；静止时按空格不叫，反向前的减速也按真实状态处理 |
| `riding`、成功上/下车 | 座垫/衣料短声一次，运动层随状态启停；下车失败时不播放成功下车声 |
| 速度与室外风环境 | 迎风层逐渐增加；与海风共享混音控制，避免两层宽带噪声相互叠满 |

参数更新拟按20～30 Hz采样、50～150 ms平滑，数字仅为初始调音值；底层增益/音高平滑，不逐帧创建声源。可先用一个高质量电机循环，试听跨度不自然才增第二个速度层；不把整段录好的“起步—巡航—停车”强行套在任意驾驶上。

第一人称跟车声源放在车辆实际位置，适度限制近距离左右摆幅，避免转头后电机突然只剩一耳。自车先不做Doppler，后续只有外部移动声源确有需求才单独验证。

### 6.3 风、雨、海浪与室内外过渡

使用`海浪底层 + 风底层 + 雨幕 + 一个邻近受雨表面`的组合，不为每种天气录制一整条同时包含所有声音的长轨。雨量直接取现有插值后的`rain`；海浪按距海及遮蔽变化，雨不直接代表海浪大小。

当前无独立风速，拟从`from/kind/transition`派生仅供听感的风强度，例如晴0.20、阴0.35、雾0.15、风雨0.85，再叠小幅缓慢起伏。此数值只属于声音美术，不改变天气、风险、清洁权限或存档，不代表m/s。随机阵风、变体使用独立随机源，不消耗`LighthouseRandom`的天气/发现序列。

| 所在区域 | 混音目标 |
| --- | --- |
| 海岸步道、露天停车处 | 风浪较完整；雨落地面，避免长时间刺耳高频 |
| 住宅内部 | 户外底声降低并削弱高频，窗边/门口适当恢复；雨天可加屋顶或窗面声 |
| 灯塔首层 | 门外风雨退后，脚步/门和本地设备突出 |
| 灯塔顶层内部 | 外风可略多于首层，转台为近场中心；不全塔铺同等强度机械声 |
| 外廊/太阳能作业点 | 恢复暴露的风雨；动作声仍能辨认，清洁权限沿用真实天气规则 |

区域来自已有房间/楼层/位置判定，加门口过渡带及迟滞；先用少量区域音量与滤波，不为每个声源每帧射线。拟用0.5～1.5秒区域渐变，天气跟随自身过渡；强制换天气、读档等跳变另做短淡变。塔内少量房间质感作为P2试验，不首期加入全场卷积混响或声学传播模拟。

循环要试听接缝、编码延迟与重复特征。8～20秒缓冲底声先做无缝循环，变化来自独立声部的慢变化；素材中不要带固定鸟叫/响雷当作每圈提示。长环境素材若需流式，先验证首播与循环间隙；Babylon官方说明流式不具备静态声的`loopStart/loopEnd`，因此不能默认替换后仍无缝。

### 6.4 擦拭盐膜

最重要的是“玩家正在做事”的触感与事务一致。使用少量贴布声、2～3次往返摩擦和收布声组合；不添加刮刀、碎玻璃或强烈尖叫摩擦。当前没有手臂动画，就与实际清洁进度同步，不虚构逐帧手势。

| 真实状态 | 应听到的声音 |
| --- | --- |
| 请求被接受，清洁开始 | 轻贴布声，建立本次动作句柄 |
| 持续看向目标，进度增长 | 摩擦层随有效动作时间运行；盐膜1.5秒、太阳能2秒分别跟随各自事务，不能硬编码同一段全长录音 |
| 走开、被挡、打开界面、失焦，或灯启动/天气等条件取消 | 立即淡出摩擦，不补播收尾和成功提示；原业务按自己的规则取消 |
| 真实清洁提交 | 收布声一次，表达手上动作结束；不发“设备已健康”的成功音 |
| 后续独立复查完成 | 若需要提示，只在有效记录提交后给轻确认，且保留结果文字；与擦拭完成不是同一事件 |

只从可观察行为取声：不能根据尚未发现的隐患偷偷加异响、提前暴露随机结果；清洁也不改变其他部件音色来暗示“全站修好”。

## 7. 混音、空间与玩家控制

拟议内部组为`Master → Actions / Vehicle / Devices / Ambience / UI`。玩家初期只需总音量、动作音效、环境声、界面声四项；Vehicle/Devices归动作控制，避免暴露过多技术分类。保留总静音、快捷入口、偏好容错和试听；以后确有音乐/语音时再增加对应设置。

- 优先级：当前动作的关键终点/有效提示 > 当前擦拭与驾驶 > 邻近设备 > 环境底层 > 稀疏装饰。优先级决定抢占，不表示每个高优先级声音都更响。
- 环境声应低于近处操作；试听先以普通关门/擦拭作参考。阅读时环境拟再降6～10 dB；必要提示时环境拟短降3～5 dB、约0.3～0.8秒恢复，避免每个脚步都造成抽吸。所有增益均待场景试听确定。
- 不把每个文件归一到同一个峰值或统一`-14 LUFS`；短开关、长风雨的测量与主观响度不同。最密场景需检测实际输出削波、峰值与持续响度，并在耳机、小音箱、笔记本扬声器比较；设备音量百分比不是声压级。
- 第一人称实物声用真实位置；环绕/岛屿远景保留轻2D操作反馈和低环境底声，避免使用远处相机造成所有声音消失，远景不播放角色脚步。详情/UI始终2D，展示相机不成为世界listener。
- 单声道选项属于后续设置验收范围，方向信息仍有视觉提示。雨声可以单独降低，不要求玩家为了听清门与擦拭同时承受更大环境噪声。
- 所有操作成功/失败、任务和风险信息继续可视化；不靠声音替代已有记录、日期、检查时长与“待复查”。本轮不新增玩家文案，实施涉及设置/提示时再按[游戏文案规范](../game-writing-guide.md)核对。

### 状态与时间规则

| 情境 | 音频行为 |
| --- | --- |
| 首次未解锁、加载未完成 | 玩法照常；旧短声丢弃。准备完成后，循环重新读取当前状态，不能播放已经停车的电机 |
| 普通前台探索 | 动作随有效活动秒数；循环播放使用音频时钟，业务参数由统一快照更新，不把音频当游戏时钟 |
| 关闭自动昼夜走时 | 天气不再自行演变，但当前风雨循环可持续；仍实际运行的转台可有声，不能把自动走时关闭误当全游戏暂停 |
| 地图、设备面板、阅读 | 停止运动/擦拭声；环境可低音量保留静态底声。设备若在当前暂停规则下冻结，其运行声也淡出，不能制造还在工作的假象 |
| 设置、Inspector或外部暂停 | 世界声淡出，按现有暂停语义冻结；设置试听作为独立短声允许播放 |
| 静音、失焦、隐藏 | 停止声源，清除旧短声与待播动作；隐藏/失焦不保留环境底声，不靠计时器后台续播 |
| 返回前台或取消静音 | 满足浏览器解锁条件后，从当前状态重建需要的循环；无历史门扣、完成声、消息连播 |
| 读档、切模式、回家、销毁/重建 | 先结束旧会话声源与异步请求；重建区域、位置和参数，禁止旧动作回调污染新会话；音频不写进玩法存档 |

一次性短声预热后即时播放；环境/载具按使用区域与接近程度准备，限制并发下载/解码。没有准备好的雨声允许短暂无声，不阻止天气与清洁权限变化。失败重试有界，来源缺失或无法解码的片段不无限重试。

## 9. 素材与制作计划

推荐**实物录音优先，少量离线合成辅助**。布擦玻璃、门轨、座垫接触很适合自录，能直接按1.5秒/2秒动作裁切；海浪/风雨与电机可从许可明确的录音库筛选。合成只用于轻UI提示或实录不足时的电机层实验，不用在线生成服务成为运行依赖。

| 声音 | 候选获取方向 / 搜索词 | 筛选重点 |
| --- | --- | --- |
| 擦拭 | 自录布擦玻璃；`cloth wipe glass`、`window cleaning cloth` | 无喷雾/碎玻璃混入、起止可分离、无过重房间混响 |
| 门、轨道与接触 | 复核已有原录音；`wood door latch`、`sliding door track` | 区分起动、摩擦、端点，音色符合实际门材质 |
| 电驴 | `electric scooter motor steady speed`、`ebike tire rolling` | 优先稳定速度、干净循环段；排除汽油引擎与录音人员说话 |
| 天气海岸 | `coastal wind ambience`、`sea waves distant`、`rain roof window` | 风、海、雨尽量可拆分；避开固定鸟叫/雷声与音乐 |
| 脚步/梯子 | 自录或材质系列录音；`footsteps wood concrete metal ladder` | 同系列鞋型与空间一致，多个自然变体 |

[Freesound FAQ](https://freesound.org/help/faq/)说明素材许可逐项不同，实施时优先筛选并核实CC0；[Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds)页面列为CC0，可作为接触/撞击候选，不能代替具体试听。[Sonniss GameAudioGDC](https://sonniss.com/gameaudiogdc/)可作录音候选目录，但平台的可用于游戏说明不自动证明允许原音频公开入库，选用前核对具体许可证与交付方式。本次未挑选、下载、授权核实或试听任何新增具体文件。

每条最终音频保存原页面、作者、许可及证据、获取日期、原件摘要、处理步骤/工具版本、声道/采样率/时长/循环点、交付摘要。多来源混音保留所有来源。原件及工程不放运行目录；从无损原件制作，不反复转码有损交付。AI候选若以后采用，另记生成工具/模型、条款、提示词与固定输出，不视为天然可再分发。

点声源优先单声道，环境底层可立体声；默认48 kHz与已有素材一致。瞬态短声先保留PCM WAV；循环比较MP3/AAC/Opus的实际目标浏览器解码、接缝与音质，**暂不指定一种压缩格式为已通过方案**。不默认交付多份回退副本，也不引入运行解码库；确有需要时所有副本都进入预算。

初步制作工作量为新增24～36个短片段、6～10个循环，约30～46个新文件；允许复用、合并和删减，不按数量验收。先做一扇门、一段布擦、一条电机和一组风雨小样，贴合场景后再批量制作。

### 建议的专项设计上限（尚未生效）

> 下表保留初始设计的候选约束；阶段A的容量结论见13.4，阶段B实际执行18/3.125/44 MiB与音效专项限制见第14节。16声部/24 MiB未启用。

| 项目 | 候选上限与约束 |
| --- | --- |
| 门与擦拭小阶段新增交付音频 | ≤0.35 MiB；仍须先腾出完整发布空间 |
| 本方案P0/P1全部新增音频 | 累计≤1.80 MiB，包含前项；连同现有0.274 MiB，交付音频合计约≤2.08 MiB；不是现有16 MiB预算之外的额度 |
| 新增音频运行JS | 完整产物增量先以≤0.10 MiB为小样目标；实际首屏≤3 MiB仍为硬约束 |
| 解码PCM | 短声常驻≤8 MiB；全部同时驻留候选≤24 MiB，含正在交叉淡变、预热及淘汰未完成的缓冲；不等于浏览器进程总内存 |
| 播放声部 | 候选总上限16：短声最多8、持续声最多6、过渡临时最多2；前台擦拭与关键端点保留额度，远设备/装饰先停 |

48 kHz、float32、立体声20秒的一个缓冲约7.32 MiB；三个就约21.97 MiB，因此不能把所有风雨素材一次解码。先加载当前区域的必要层，循环共享数据，接近新区域才准备，离开后淘汰；超内存时延后可选层，不靠静音仍占满缓冲。首次小样须据实际同时驻留表调整长度、声道或流式选型。

初始设计时`AUDIO_LIMITS.fileBytes=0.50 MiB`、6声部与8 MiB限制不会自动变更。阶段B已同步将音效总文件/核心上限改为1 MiB/384 KiB，并保留6声部/8 MiB，见第14节。后续增加分组/并发仍须同步校验器和测试；16声部/24 MiB只是待测设计上限，不声称低端设备已能稳定运行。

容量处理有两条路：

1. **优先保持现有硬预算**：小样前评估等画质/功能的资源与依赖优化。完整P0/P1若按上限交付，需为新增素材、JS、来源、清单及分析开销预留约2.2 MiB完整目录空间、至少约1.23 MiB运行素材回收空间，并为实际首屏新增代码腾出余量。2.2 MiB是预留目标，最终以完整产物差值验收；不删除Inspector、说明文件或动态分包凑预算。
2. **证据表明无法合理回收时**：先完成受控小样、试听和字节测量，在本方案记录替代方案、画质/功能取舍及具体新阈值，再同步资源原则、构建配置/白名单和测试。当前没有足够证据选择新硬预算，本次不调整。

容量验证是实施的前置工作，不是本次调研的阻塞项。文件变小、循环复用与减少声源都不能直接写成加载速度或FPS收益；继续遵守已暂停的性能采样边界。

### 13.2 引擎、状态与浏览器验证
